# 超参数：该选什么、为什么

超参数是你**真正开始训练模型时**才会撞上的东西。当你对语言模型的理解还停留在抽象层面时，根本不用关心这些；可一旦要实例化一个模型，问题就扑面而来：前馈层该多大？注意力头该有几个？head 维度是不是必须整除隐藏维度？词表该多大？要不要 weight decay 和 dropout？模型该做深还是做宽？

如果从零开始搜索这个高维空间，会非常吓人。但好消息是：**大家实际尝试的超参数空间其实很小**。Tatsu 的发现是：**真正会随着成功模型变化的超参数很少**——人们遵循着相当清晰的**经验法则（rules of thumb）**。这一节逐一展开这些法则，以及背后的证据。

## 前馈层维度与模型维度之比：第一个共识超参数

先看一个前馈层。它涉及两个维度：

- $d_{model}$:$x$ 的维度，也就是 MLP 的输入（以及输出）维度；
- $d_{ff}$：前馈层维度，MLP 内部**上投影的隐藏维度**（即 $W_1$ 的输出维度、$W_2$ 的输入维度）。

$d_{ff}$ 与 $d_{model}$ 的比值控制着 MLP 的"丰富程度"。那么它应该是多少？

**共识答案是：$d_{ff} = 4\,d_{model}$。** 这个 4 倍法则"好得出奇"地有效，几乎所有用非门控 MLP 的模型都这么选。不过有几个例外。

### 例外一：GLU 变体把比例降到 $\frac{8}{3}$

还记得门控线性单元多了一个门控矩阵 $V$ 吗？它带来了**三**个矩阵（$W_1$、$V$、$W_2$），而不是两个。如果保持相同的维度，参数量就会变多。**为了保持总参数量与非门控版本一致**，门控模型会把 $d_{ff}$ **缩小到原来的 $2/3$**。做一点算术：若非门控模型取 $d_{ff} = 4\,d_{model}$，则门控模型应取

$$d_{ff} = \frac{2}{3} \times 4\,d_{model} = \frac{8}{3}\,d_{model} \approx 2.67\,d_{model}$$

看一下各模型的实际取值:

| 模型 | $d_{ff}/d_{model}$ |
|------|--------------------|
| PaLM | 4 |
| Mistral 7B | 3.5 |
| LLaMA-2 70B | 3.5 |
| LLaMA 70B | 2.68 |
| Qwen 14B | 2.67 |
| DeepSeek 67B | 2.68 |
| Yi 34B | 2.85 |
| T5 v1.1 | 2.5 |

![](/lectures/03/slide-38.png)

大量模型都落在这个 **2.6 左右**的范围,这正是 GLU 单元的标准参数化。两个有趣的偏离:

- **LLaMA-2** 用了 **3.5**。原因很实际:LLaMA-2 的注意力用了 **MQA**(后面会讲),省下了注意力参数,于是他们"任意地"乘了个 1.33,把 MLP 做得更大一点;
- 所以真正出现在 GLU 模型里的比值,**要么 2.6 左右,要么 3.5**;非门控模型则是 4。

### 例外二:T5 的"大胆"选择

大语言模型训练在很多时候是一场**互相抄超参数**的游戏,但 **T5** 很不一样——Google 系总是出奇地大胆。11B 参数的 T5 用了:

$$d_{ff} = 65{,}536, \qquad d_{model} = 1024 \quad \Longrightarrow \quad d_{ff} = 64\,d_{model}$$

一个 **64 倍**的乘数！为什么？这又是一个**系统层面**的论证：T5 论文认为，**矩阵乘法越大越胖，硬件利用率越高**——把 $d_{ff}$ 做极大，矩阵乘法就更容易把 GPU 喂饱。近期也有一些追随者：**Gemma 2** 用 8 倍，SmolLM/Gemma 3/Gemma 4 用 4 倍（GLU）。但 **64 倍至今没有第二个模型敢用**。

### Kaplan 等人的量化证据：为什么 1~10 都是安全的

光看惯例不够。Kaplan 等人 2020 年的经典**缩放定律**（scaling laws）论文里（通常被人记住的是缩放定律部分，但其实**超参数部分也很有用**）恰好做了这个实验：固定其他一切，改变 $d_{ff}/d_{model}$ 比例，画 loss 上升了多少。结果显示存在一个**很宽的盆地**：比例从 **1 到 10** 左右，效果都大致最优；一旦超过 10 往 100 走，loss 会**接近二次方地**飙升。

换句话说，2.6、3.5、4 这些取值**全都落在安全盆地内**——选哪个都差不多，你根本不用纠结。

### 结论

- 默认选 **$d_{ff} = 4\,d_{model}$**（非 GLU）或 **$d_{ff} \approx 2.66\,d_{model}$**（GLU），对几乎所有现代 LLM 都工作得很好；
- 但 T5 证明**激进的选择也能训练出好模型**（T5 本身是个完全正常的模型），只是很可能**计算上不划算**;
- 有趣的尾声：T5 的改进版 **T5 v1.1** 用的是 GeGLU 和更标准的 **2.5 倍**乘数——论文没有明说，但字里行间能读出：**Google 自己在更新 T5 时也决定回到更标准的取值**。

## 注意力头：head 维度 × 头数 ≈ 模型维度

第二个共识超参数是**模型维度与"head 维度 × 头数"之比**。规范的选择是：给定隐藏维度 $d_{model}$，有了多头之后，把维度**均分**给每个头——即**保持总维度固定**:

$$d_{head} \times n_{heads} = d_{model}$$

但这**不是必须的**:你也可以固定每个 head 的维度、随着头数增加让注意力部分吃掉越来越多的参数。大多数模型遵循前一种(1:1 比例):

| 模型 | 头数 | head 维度 | 模型维度 | 比例 |
|------|------|-----------|----------|------|
| GPT-3 | 96 | 128 | 12288 | 1 |
| T5 | 128 | 128 | 1024 | 16 |
| T5 v1.1 | 64 | 64 | 4096 | 1 |
| LaMDA | 128 | 128 | 8192 | 2 |
| PaLM | 48 | 258 | 18432 | 1.48 |
| LLaMA-2 | 64 | 128 | 8192 | 1 |
| Qwen 3.5(27B) | 24 | 256 | 5120 | 1.2 |

绝大多数模型的比例都在 1 附近;少数例外主要是 Google 系模型(T5 的 16 倍是个明显的破例者)。Tatsu 对这个超参数的评语是:**又一个"宽容"的超参数**——已有的消融显示,比例 1 附近存在一个相当宽的盆地,怎么选都不会太差。不过它的重要性不如下一个。

## 纵横比(aspect ratio):模型该深还是宽?

第三个、也是概念上最重要的超参数是**纵横比**。当你把模型放大或缩小时,通常的做法是**固定一个纵横比**(多宽 vs 多深),然后把整个模型按比例放大。所以纵横比在某种意义上**控制着整个"深度对宽度"的权衡**。

你可能会以为这个选择非常自由(想要推理效率就做宽,想要推理能力就做深),但数据显示,**大多数现代模型都落在同一个甜点区(sweet spot)附近**:

| 模型 | $d_{model} / n_{layer}$ |
|------|--------------------------|
| BLOOM | 205 |
| T5 v1.1 | 171 |
| PaLM(540B) | 156 |
| GPT-3 / OPT / Mistral / Qwen / OLMo 3 | 128 |
| LLaMA / LLaMA-2 | 102 |
| Gemma 3 | 87 |
| Gemma 4 | 61 |
| T5(11B) | 33 |

![](/lectures/03/slide-44.png)

也就是说,**每层大约 100 个隐藏维度**——GPT-3、LLaMA、Qwen 全守在这个甜点附近,比值约 **100**(宽容范围约 100~200)。既没有人做"特别深"的模型,也没有人做"特别宽"的模型。

### 纵横比的系统考量

为什么停在 100?部分是**表达力与硬件的权衡**:

- **太深**的模型系统上很难伺候:层数一多,要并行化就得**切层**——这就是**流水线并行(pipeline parallel)**,而流水线并行是**绝大多数人极其不想碰**的东西;
- **太宽**的模型反而好办:把矩阵切开分布到 GPU 上就是**张量并行(tensor parallel)**,实现简单得多;
- 所以存在系统上"倾向做宽"的理由,也存在表达力上"倾向做深"的理由,最终大家停在比值约 100 的位置。

### 纵横比的经验证据

Kaplan 等人 2020 年的论文对多个规模(50M、274M、1.5B 参数)做了纵横比扫描,结果显示:**最优纵横比约在 100 附近**,而且**在不同规模的模型上几乎不移动**——如果你相信这一点在大规模上仍然成立,就可以放心地固定一个纵横比去训练。

Tay 等人 2021 年(Google)也做过一系列非常有趣的深度 vs 宽度实验,结论更进一步:**当你扫描深度-宽度权衡时,真正决定模型好坏的主要是 FLOPs**——FLOPs 上去了模型就变好,纵横比本身并不是那么关键。综合起来,大家的共识是:**存在一个宽容的超参数带,选一个让系统利用率最高的值即可**——表达力方面的顾虑反而很难理性地权衡。

## 词表大小

最后一个底层超参数是**词表大小(vocabulary size)**。它的分布呈现非常清晰的两极分化:

- **单语模型(只追求英语好)**:词表大多在 **3 万到 5 万** token 之间;
- **多语/生产系统(含闭源模型)**:词表普遍在 **10 万到 25 万**。

| 单语模型 | 词表大小 | 多语/生产模型 | 词表大小 |
|----------|----------|----------------|----------|
| 原始 transformer | 37000 | mT5 | 250000 |
| GPT | 40257 | PaLM | 256000 |
| GPT-2 / GPT-3 | 50257 | GPT-4 | 100276 |
| T5 / T5 v1.1 | 32128 | Gemma 4 | 262144 |
| LLaMA | 32000 | DeepSeek | 100000 |
| | | Qwen 15B | 152064 |
| | | Yi | 64000 |

趋势很清楚:**LLaMA 之后,大家纷纷转向多语或生产部署,词表大幅膨胀**(Google 系尤其大);同时**模型越来越大,能"消化"的词表元素也越来越多**(缩放定律研究显示:模型越大,能支持的有效词表越大),这两个因素叠加,让"大的单语模型"几乎绝迹。

### 问答:多模态模型的词表怎么办?

(有同学问:多模态模型的词表大小会不同吗?)

这取决于你的**分词方式**。如果你的图像等模态也走 token 化,就需要**多得多的 token** 来覆盖它们;很多开源多模态模型会给图像单独配一个**独立的大词表图像分词器**。

### 问答:用 bits-per-byte 比较不同分词器有效吗?

(有同学问:用 bits-per-byte(BPB)比较不同分词器的模型,这种比较有效吗?)

Tatsu 认为这问题问得很好。语言建模本质是**生成式建模**——建模"整个字符串空间上的概率分布"。**只要序列是完整的**,你给任何字符串一个概率,不同模型的比较就总是有效的。用 BPB 比较时要注意两件事:

1. **分词器是否"完整"**:早期的分词器会丢掉一些 token/词,那会让比较失效;但**现代分词器都是完整的**,能建模任何序列,所以这点不用担心;
2. **是否做了长度归一化**:BPB 总是用**同样的分母**(字节数)做归一化,所以**永远是公平的比较**。

(还有同学追问 perplexity 与 BPB 的关系:Tatsu 说两者本质上是**对偶的**,但他不太确定同学具体想表达什么,约定课后细聊。)

## 正则化:dropout 与 weight decay

最后一个话题是正则化。先看直觉:预训练(pre-training)是最**不该**想到正则化的地方——数据量远超参数量(除非你是 Google,否则**互联网数据比 FLOPs 还多**),你大概率**永远不会看到同一份数据两次**,而且只对语料做**一遍(single pass)SGD**。理论上,单遍 SGD 几乎不可能记住数据。所以**计算受限的语言建模里,过拟合几乎从来不是问题**——有人甚至只看训练 loss。

但看看人们**实际**在做什么:

| 模型 | Dropout | Weight decay |
|------|---------|--------------|
| 原始 transformer | 0.1 | 0 |
| GPT-2 | 0.1 | 0.1 |
| T5 | 0.1 | 0 |
| GPT-3 | 0.1 | 0.1 |
| T5 v1.1 | 0 | 0 |
| PaLM | 0 | (variable) |
| OPT | 0.1 | 0.1 |
| LLaMA | 0 | 0.1 |
| Qwen 14B | 0.1 | 0.1 |

(注:大多数论文根本不讨论 dropout;对开源模型来说,"不讨论"基本等于"没用 dropout",但闭源模型可能不是这样。)

规律是:**dropout 基本已经过时了,但 weight decay 仍然被大量使用**。这非常反直觉——为什么要给一个只看一遍数据、不存在过拟合的模型加 weight decay?

### 为什么预训练还在用 weight decay?

Tatsu 先让听众想了 10 秒钟,然后给出答案(这个观察来自 **Andriushchenko 等人 2023** 年的论文):

**weight decay 不是为了控制过拟合。** 证据是:在单遍 SGD 的语言模型训练中,不同强度的 weight decay 下,**训练 loss 与验证 loss 的差距(train-val gap)完全一样**——本来就不过拟合,模型点全都落在 $x=y$ 线上,weight decay 并没有让验证 loss 变得更好。

真正有趣的是,**weight decay 与优化器存在奇怪的交互**。看不同 weight decay 强度**与学习率衰减相结合**时的表现:

- **常数学习率**:weight decay 没什么帮助(你的直觉来自这里);
- **余弦(cosine)学习率调度**:强的 weight decay（图中蓝色虚线）**起步慢,但在训练尾段收敛到好得多的极小值**——因为学习率衰减时,weight decay 提供了某种**隐式加速(implicit acceleration)**。

所以答案是:**你用 weight decay 不是为了让模型"正则化",而是为了获得更好的训练 loss**。它通过"在学习率降到零的尾段改变学习动态"来实现这一点——这是一个典型的"看似正则化、实则是优化干预"的案例,也是深度学习很难从第一性原理推理的原因之一。这正是这门课让你动手实践的原因:**你可能会自己撞上这类反直觉现象**。

### 问答:为什么这些"正则化"手段会起作用?

(有同学问:Tatsu 有没有关于为什么某些正则化在某些情况下起作用的解释?)

Tatsu 说,**并不是所有正则化都影响优化**——比如 dropout 现在基本没人用了,因为它和优化器的交互不好。但 weight decay（把参数往零收缩）**可能允许你使用更高的学习率、或者衰减得更快**——这些效应有各种各样的实现途径,他并没有一个统一的解释。

### 问答:这些超参数是搜出来的还是抄的?训练中会动态调整吗?

(有同学问:这些经验法则这么多,你们训练时到底还在搜超参数吗?)

两者都有。每次训练都有"可以变什么"的论点,但**报告里大家很少动超参数,通常一次只改一个架构选择**,极少有人全盘推翻重来。Google 是唯一一个喜欢"大幅翻新"的组织——比如最新的 **Gemma 4 给每一层都配了独立的嵌入(per-layer embedding)**,用来在内存使用和 FLOPs 之间做权衡。

(另一同学问:训练过程中会动态调整这些参数吗?)架构类超参数不可能在训练中途改(会让训练不兼容),唯一的例外是 **weight decay**:大家确实会**让它与学习率调度联动**——这是已被验证非常有效的启发式。其他超参数训练期间基本固定。

### 问答:扩散模型(Diffusion)有不一样的架构吗?

(有同学问:扩散这类"未来模型"有没有显著不同的架构选择?)

Tatsu 坦言自己没深入调研过扩散语言模型——主要问题是**没多少人在大规模训练扩散语言模型**,而且很多现有模型其实是"**改造**"出来的:架构和 LLaMA 系模型基本一样。至于"如果从零训练,最优架构是什么",他说自己并不知道。

## 小结:哪些超参数是"不用动脑"的?

综合来看,有些超参数**基本不需要深思熟虑**——它们已被验证、人人都在用:

- **MLP 的隐藏大小**:$d_{ff} = 4\,d_{model}$(GLU 用 $\frac{8}{3}$ 左右);
- **多头注意力的 head 维度**:$d_{head} \times n_{heads} = d_{model}$;
- **纵横比**:约 100 维/层(受系统约束左右,100~200 都安全);
- **正则化**:通过 weight decay(尽管其效果主要在优化动态上)。
