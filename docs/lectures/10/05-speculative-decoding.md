# 投机解码：无损的捷径

到目前为止，我们看的都是有损（lossy）的方法：把 KV cache 压得很小、量化、剪枝——它们都可能伤精度。这一节介绍一个非常优雅的**无损**（lossless）方法：**投机采样 / 投机解码（speculative sampling / speculative decoding）**。它在数学上保证：**输出分布与目标模型完全一致**，同时大幅加速。

## 回顾：检查比生成快

先回顾推理的两个阶段：

- **prefill**：给定一个序列，可以**并行编码所有 token**（计算受限，而且顺带给出概率）；
- **generation**：逐 token 生成（访存受限）。

换句话说：**"检查（checking）一个序列好不好"比"逐 token 生成它"快得多**。给你一个序列，要判断"它作为下一个 token 有多好"，可以把所有 token 一起并行跑一遍，这比一个一个地生成快得多。投机解码利用的正是这个不对称性。

## 基本思想：草稿模型 + 目标模型

做法是这样的：用一个更便宜、更小的**草稿模型（draft model）** $P$ 来生成，猜测几个 token（比如 4 个）；然后用我们真正关心的**目标模型（target model）** $Q$ 来**审查**（review）这些 token，决定接受还是拒绝。

- 草稿模型小、便宜，所以即使它是访存受限的、得一个一个生成，代价也不大；
- 目标模型大、昂贵，但我们让它**并行处理一批 token**，也不算贵。

于是整体效果是：小模型吐出一串 token，大模型批量批评它们，得到一串"burst"的 token，然后再来一串……（课上有动画演示：大模型逐 token 生成很慢，投机解码则是一串一串地出。）

## 算法与接受准则

这是 2022 年底几篇论文几乎同时提出的（此处是其中一篇）。算法如下：

1. 从草稿模型 $P$ **采样 $K$ 个 token**（自回归地逐个采样）；
2. **并行**地用目标模型 $Q$ 计算这些草稿 token 的 logits；
3. 逐个决定接受还是拒绝：以概率

$$\min\left(1, \frac{q(x)}{p(x)}\right)$$

接受；其中 $q(x)$ 是目标模型给 token $x$ 的概率、$p(x)$ 是草稿模型给它的概率；
4. 一旦第一次拒绝，就从这个 token 的**残差分布（residual distribution）** $\max(q - p, 0)$ 里采样，然后**结束**。

![投机解码的算法示意图](/lectures/10/speculative-sampling-algorithm.png)

直觉：$q$ 比 $p$ 大得越多，说明草稿模型越"押对了"，越应该接受它；否则就退回残差分布重新采样。这本质上就是**拒绝采样（rejection sampling）**，只不过做了一个关键修改：**总是能产生至少一个候选**（普通拒绝采样在被拒绝时什么也不给、会一直循环），因此每一步都能前进一个 token，而不会卡住。

关键性质：

> **保证得到目标模型的精确样本（exact sample）。**

## 精确性的证明：两词表例子

为什么能保证精确？用讲义里的"按例证明"（proof by example）来说明。假设词表只有两个元素 $\{A, B\}$：

- 目标模型概率：$[q(A), q(B)]$；
- 草稿模型概率：$[p(A), p(B)]$；
- 假设草稿模型**过度采样**了 $A$，即 $p(A) > q(A)$；因此它必然**欠采样** $B$，即 $p(B) < q(B)$；
- 残差概率 $\max(q - p, 0) = [0, 1]$——$A$ 处残差为 0，$B$ 处残差为 1。

现在计算"投机采样最终采到某个 token"的概率。

**采样到 $A$** 有两条路径：要么草稿直接采到 $A$ 且被接受（概率 $p(A) \cdot \frac{q(A)}{p(A)} = q(A)$）；要么草稿采到 $B$ 被接受——但 $B$ 处残差是 0，且接受 $B$ 后流程就结束了，不会再采 $A$。所以第二条路径贡献为 0：

$$P[\text{采到 } A] = p(A) \cdot \frac{q(A)}{p(A)} + p(B) \cdot 1 \cdot 0 = q(A)$$

**采样到 $B$** 也有两条路径：要么草稿直接采到 $B$ 且被接受（概率 $p(B) \cdot 1 = p(B)$，因为 $p(B) < q(B)$ 时接受概率为 1）；要么草稿采到 $A$、被拒绝（概率 $p(A)\left(1 - \frac{q(A)}{p(A)}\right)$），然后从残差分布采样——而残差分布是 $[0, 1]$，即必然采到 $B$：

$$P[\text{采到 } B] = p(B) \cdot 1 + p(A)\left(1 - \frac{q(A)}{p(A)}\right) \cdot 1 = p(B) + p(A) - q(A) = 1 - q(A) = q(B)$$

两项合起来：

$$P[\text{采到 } A] = q(A), \qquad P[\text{采到 } B] = q(B)$$

**投机采样产出的分布与目标模型 $Q$ 完全一致。**（多 token 版本逐位置做同样的论证即可。）

论文展示，投机解码确实带来了大幅加速。

![投机解码在不同草稿长度下的统计](/lectures/10/speculative-sampling-stats.png)

注意草稿长度 $K$ 有一个**甜点区（sweet spot）**：

- 草稿 token 太少 → 没有充分利用目标模型侧的批处理并行；
- 草稿 token 太多 → 更容易被拒绝，浪费；
- 本例中大约 **$K = 3$～$4$** 最好。

### 补充推导：接受率与加速比

课上对"精确采样"给出了按例证明，但加速收益还可以从数学上更定量地理解。我们补充一个接受率与加速比的推导。

**每个位置的接受率**。对草稿模型采出的一个 token $x$（服从分布 $p$），接受概率为 $\min(1, q(x)/p(x))$。取期望（对 $p$ 采样）：

$$\alpha \;=\; \mathbb{E}_{x \sim p}\!\left[\min\left(1, \frac{q(x)}{p(x)}\right)\right] = \sum_x p(x) \min\left(1, \frac{q(x)}{p(x)}\right) = \sum_x \min\left(p(x), q(x)\right)$$

最后一个求和正是 $1 - \text{TV}(p, q)$，其中 $\text{TV}(p,q) = \frac{1}{2}\sum_x |p(x) - q(x)|$ 是 $p$ 与 $q$ 的全变差距离。于是：

$$\alpha = 1 - \text{TV}(p, q)$$

两个极端：当草稿与目标分布完全一致（$p = q$）时 $\alpha = 1$，每个 token 都被接受；两者差异越大，接受率越低。这定量说明了一个直觉——**草稿模型越接近目标，投机解码越快**，所以要用蒸馏把草稿往目标方向"炼"。

**每轮（round）产出的 token 数**。每一轮草稿采样 $K$ 个 token，逐个以概率 $\alpha$ 接受，直到第一个被拒绝的 token（从残差分布采样后）结束。每轮实际产出的 token 数期望为截断几何分布：

$$\mathbb{E}[m] = \frac{1 - (1 - \alpha)^K}{\alpha}$$

当 $\alpha \to 1$ 时 $\mathbb{E}[m] \to K$（全部接受）；当草稿很差（$\alpha$ 小）时 $\mathbb{E}[m] \to 1$（只前进一个 token，即退化为普通解码）。

**加速比**。设草稿模型生成一个 token 耗时 $\tau_p$，目标模型**并行验证 $K$ 个 token**耗时 $\tau_q$。一轮的成本是 $K\tau_p + \tau_q$，产出 $\mathbb{E}[m]$ 个 token；而不用投机解码时，串行生成同样多的 token 需要 $\mathbb{E}[m] \cdot \tau_q$。于是加速比为

$$\text{speedup} = \frac{\mathbb{E}[m] \cdot \tau_q}{K \tau_p + \tau_q}$$

当草稿足够小（$K\tau_p \ll \tau_q$）、且 $\alpha$ 接近 1 时，$\mathbb{E}[m] \approx K$，加速比趋近 $\frac{K \tau_q}{\tau_q} = K$ 量级——一轮的并行验证被 $K$ 个 token 摊薄。这也解释了甜点区的存在：$K$ 太小则 $\tau_q$ 摊不薄、收益有限；$K$ 太大则 $\alpha < 1$ 带来的拒绝损失超过摊薄收益（$\mathbb{E}[m]$ 不再增长、反而每轮浪费更多草稿成本）。

实践中，草稿模型通常比目标模型小很多，例如**目标 70B + 草稿 8B**，或者**目标 8B + 草稿 1B**。而且理想情况下，你希望草稿模型**尽可能接近目标模型**——这就要靠**蒸馏**（distillation）把它"炼"向目标。

## 与前面技巧的结合

很有意思的是：**这一讲前面讲的所有"减小 KV cache"的手段，都能直接用在草稿模型身上**。整体思路是：

- 想办法把 KV cache 变小（架构、量化、剪枝……）；
- 如果得到一个你满意的模型，直接服务它；
- 如果还不够满意，至少它可以当一个**草稿模型**，让目标模型来"修复"。

投机解码的文献现在非常多，有很多在原作之上的改进，这里就不展开了。

## 草稿模型的改进：Medusa 与 EAGLE

草稿模型本身也是创新空间很大的地方：

- **Medusa**：草稿模型用多个头**并行**生成多个 token（而不是自回归地逐个猜）；
- **EAGLE**：草稿模型**利用目标模型的高层特征**来预测，猜得更准。

![Medusa 与 EAGLE：两种改进草稿模型的方式](/lectures/10/medusa-eagle.png)

## 小结

- **精确性**：得益于数学（修改版拒绝采样），投机解码**保证**从目标模型精确采样——无损；
- **不对称性**：它利用"检查比生成快"的不对称性，让昂贵的模型只做并行检查；
- **创新空间**：草稿模型的设计（Medusa、EAGLE 等）有大量发挥空间，且**涉及训练**。

投机解码解决的是"让单个序列的生成更快"的问题。但在真实的线上服务里，还有另一个维度的难题：**动态的工作负载**——请求随时来、长短不一、前缀共享。这是最后一节的主题。
