# 量化、剪枝与蒸馏：有损捷径

上一节讲的是改模型架构（GQA、MLA、CLA、局部注意力）来减小 KV cache。这一节换一个更"系统"的视角：**量化（quantization）**与**剪枝（pruning）**——它们不是改架构，而是想办法让模型本身"变小"，从而在访存受限的推理里直接提速。它们的共同点是**有损（lossy）**：会牺牲一点精度，所以每一步都要检查精度有没有掉得太多。

## 量化：降低数值精度

量化核心思想就一句话：**降低数字的精度**。精度低 → 内存占用少 → 由于推理访存受限，延迟与吞吐就更高。当然，精度掉了，你肯定要担心准确率。

### 量化机制：scale 与 zero point

量化（以及反量化）的基本操作是：用 `scale` 和 `zero point` 把连续值映射到离散的整数网格。看讲义里的小例子，$x = 5.2342$、`scale = 0.1`、`zero_point = 4`：

```python
x = 5.2342
scale = 0.1
zero_point = 4

x_quant = round(x / scale) + zero_point    # 量化：round(52.342) + 4 = 56
x_approx = (x_quant - zero_point) * scale  # 反量化：(56 - 4) * 0.1 = 5.2
```

量化公式是 $q = \text{round}(x / s) + z$，反量化是 $\hat{x} = (q - z) \cdot s$。本例量化后得到 56，反量化回来是 5.2——损失了 0.0342。误差就这么来的。

可以稍微分析一下这个误差。四舍五入引入的误差至多半个刻度，所以绝对量化误差有一个上界：

$$|x - \hat{x}| \le \frac{1}{2} \cdot s = \frac{1}{2} \cdot \frac{\text{range}}{2^{b}}$$

其中 $b$ 是量化位数、`range` 是被量化数值的取值范围——位宽越低、范围越大，$s$ 就越大、误差越大。注意**相对误差**取决于被量化数值的大小：对接近 0 的小数值，$0.5s$ 可能是一个很大的相对误差，这正是低精度（尤其整数量化）容易破坏数值稳定性的原因。也正因如此，量化时选好 `scale`（以及 `zero_point`，用于对称性较差、带偏置的分布）很关键——`scale` 太大则噪声大，太小则容易溢出（超出整数表示范围）。

### 精度谱

不同精度的选择是一个谱系，从训练到推理各有用途：

| 精度 | 字节 | 说明 |
|------|------|------|
| fp32 | 4 字节 | 训练时参数与优化器状态需要它 |
| bf16 | 2 字节 | 推理的默认选择 |
| fp8 | 1 字节 | 在 H100 上 e4m3 格式范围约 $[-240, 240]$；"敢的话"连训练都可以做 |
| int8 | 1 字节 | 范围 $[-128, 127]$；比 fp8 精度低一点但更便宜，**只用于推理** |
| int4 | 0.5 字节 | 范围 $[-8, 7]$；更便宜，精度也更低 |

### 量化感知训练（QAT）与训练后量化（PTQ）

如果你担心量化会搞坏模型，有一个办法：**训练时就考虑量化**。这叫做**量化感知训练（quantization-aware training，QAT）**：训练的前向过程中就做"量化-反量化"，相当于在训练时模拟量化误差。这样权重会被"训练得适应量化"，量化后表现更好。缺点是：**需要昂贵的大规模训练**。

人们通常的做法是反过来的——**训练后量化（post-training quantization，PTQ）**：先训练好模型，再事后量化。便宜得多。朴素做法是对每一层或每个张量，单独确定 `scale` 与 `zero point`，然后量化。一般效果不怎么样。

几个更聪明的 PTQ 方法：

- **GPTQ**：利用一些 **Hessian 信息**逐层量化；量化时把误差记录并"传播"到尚未量化的权重上，从而**补偿（correct）**量化误差；
- **激活感知量化（activation-aware quantization，AWQ）**：更精密的方法。它基于一个观察——**某些激活通道的数值特别大**，而那些与这些激活通道相乘的权重就**更重要**。于是给这些权重分配更高的精度。

### AWQ 细节

看 AWQ 的原理图：一个 bf16 的权重矩阵，量化为 int3 后，你找出那些与"大激活通道"交互的权重——它们在整体上往往就是重要的少数。对少数重要的通道（约 0.1%～1% 的权重）保留 fp16 高精度，其余保持 int3。

![AWQ：对少数重要通道保留高精度，其余低精度](/lectures/10/awq-schema.png)

效果上，fp16 → int3 大约能带来 **4 倍的内存下降、3.2 倍的加速**。

## 模型剪枝：撕掉一部分再修好

另一个思路更"粗鲁"：直接从大模型上**撕掉一部分**，然后把它**修好（fix up）**。这是 NVIDIA 一篇论文的做法。

流程分三步：

![剪枝 + 蒸馏的循环：识别重要部件、剪掉、蒸馏修复](/lectures/10/pruning-kd-loop.png)

1. **识别重要性**：在一个小的校准数据集（calibration set，约 1024 个样本）上，估计模型中各个部件（**层、注意力头、隐藏维度**）的重要性，选出最重要的部分；
2. **移除不重要的部件**：删掉不重要的隐藏单元、甚至整个层，得到一个更小的模型；
3. **蒸馏修复**：剪出来的小模型一开始自然是不太好的（"Frankenstein"），所以用原模型对它做**蒸馏（distillation）**，在数据（或你关心的任务）上再训练一段时间，"治愈"它。

结果相当不错：他们能把一个 **15B 的模型剪成 8B**，精度损失不大，而重新训练所用的数据量比从头训练少得多。

![剪枝+蒸馏的结果：15B → 8B 精度损失很小](/lectures/10/pruning-kd.png)

> **课堂问答一：怎么区分重要层与不重要层？**
>
> （同学：你怎么区分重要的层和不重要的层？）
>
> **Percy**：一般你会准备一个校准集，把输入过一遍模型，观察**激活的幅度（magnitude）**。有些单元（尤其是"死单元"）的激活接近零，那些就是不太重要的；激活大的想保留。这是高层次的思路。
>
> **课堂问答二：为什么激活大就意味着重要？**
>
> （同学：为什么激活大就重要？如果它对所有 prompt 都一直输出 100，那它必然有意义吗？会不会只是训练出来的一个伪影（artifact）？）
>
> **Percy**：总的说，这是一个**经验观察**：模型里确实有些通道远比其他通道大。如果事实不是这样，这些技术就不一定管用——但事实恰好如此，因为这些模型就是这样训练出来的，你可以利用这一点。至于"某个神经元永远是 100"：如果是这样，你还得看方差之类的东西。如果均值高、方差低，你也不能直接删掉它（那样一切都会坏掉），但也许有别的方式——比如把它的贡献**并入 bias**。

## 小结：两条配方

把"有损捷径"总结一下：整个游戏的目的是——**在不伤精度的前提下，降低推理复杂度**。可以理解为主要做两件事：减少**参数量**或减少 **KV cache**。

具体执行有两条配方：

- **从零开始（from scratch）配方**：
  1. 定义一个更快的模型架构（比如 GQA、MLA、局部注意力）；
  2. 直接训练这个更快的模型。
- **蒸馏（distillation）配方**：
  1. 定义一个更快的模型架构；
  2. 用**原模型（架构可能不同）**的权重来初始化——这个"Frankenstein"模型当然不会太好；
  3. 用**蒸馏**修复它。

蒸馏配方的妙处在于：你不必从头训练，只需用远少得多的数据把剪出来的模型"治愈"。

> **一个伏笔**：如果你用各种手段（架构、量化、剪枝）折腾出一个满意的模型，那就直接服务它；如果还不满意，它至少还能派上另一个用场——当**投机解码（speculative decoding）**里的草稿模型。这是下一节的主题。
