# 什么是"好模型"：评估的本质与困惑度

## 开场：课程还剩什么

到今天为止，这门课已经把"训练一个语言模型"所需的全部环节都过了一遍：我们定义了架构、优化器、主训练循环（main training loop），用 kernel 让训练变快，然后看了缩放定律（scaling laws），还略微讲了怎么让推理（inference）变快。剩下的唯一一块拼图，就是**你拿什么数据来训练**——那是下一周的主题。

而数据会塑造模型的行为：如果你用代码训练，模型大概就会擅长写代码；如果你只拿 DNA 序列训练，它大概连英语都不会说。但在谈数据之前，我们需要先想清楚一个问题：**我们希望模型具备什么行为**？这正是本讲的主题——评估（evaluation）。

评估问一个非常简单的问题：给定一个训练好的模型，它有多"好"？而"好"又是什么意思？

评估看起来像是一个相当机械的过程：定义一些提示词（prompts），把提示词发给模型，拿回一些回答，然后算准确率。既然这么机械，为什么值得花整整一讲来讨论？因为评估实际上是一个**非常深的话题**，而且它极其重要——**评估塑造了 AI 的发展**。评估设定了"北极星"（north stars），无论是开源的还是闭源的模型开发者，都把评估当作衡量进步的标尺。因此，你如何仔细地设计评估，就在隐含地塑造你的模型未来能够做什么。

> 评估的核心挑战可以用一句话概括：**把抽象的构念（abstract construct）转化为具体的指标（concrete metric）**。你通常从一个抽象的想法出发——"我希望我的模型擅长对话"，或者"我希望它擅长……"。这些是抽象概念。而评估，就是把它们变成由具体提示词或具体环境驱动的、可计算的指标的过程。整讲会看到这个"抽象构念 → 具体指标"的过程反复出现。

## 四种"好"的视角

先回到"什么让一个模型好"这个问题。一种直觉是：**模型好，就是它在基准上表现好**。有一个网站叫 [Artificial Analysis]（https://artificialanalysis.ai/），它已经成为思考模型"智能"的一个标准去处：上面可以看到从 GPT-5.5 一路往下的各种模型的排名，包含了我们这一讲会讲到的好几个数据集。

![Artificial Analysis 的模型智能指数排名](/lectures/12/artificial-analysis.png)

另一种直觉是：**模型好，就是它在基准上表现好、同时还便宜**——因为成本应该被算进去。下面这张图把刚才的"智能指数"画成横轴，纵轴是运行某个模型要花多少钱（按推理成本算）：

![智能指数 vs 推理成本](/lectures/12/artificial-analysis-cost.png)

正如你所预料的，两者大致相关：付得越多，智能指数越高。但注意它们并不是完全对齐的——中间有很大的散布。

还有一种直觉是：**模型好，就是人们更喜欢它**。这正是 [Arena AI]（https://arena.ai/leaderboard）（原名 Chatbot Arena）的立场——它根据人们喜不喜欢模型来形成排名，这部分后面会深入展开。

![Arena AI 的人类偏好排名](/lectures/12/lmarena-leaderboard.png)

最后一种直觉是：**模型好，就是人们愿意选它、并为之付费**。[OpenRouter](https://openrouter.ai/rankings) 是一个聚合服务，你可以通过一个统一的端点使用很多不同的模型。因此它收集了大量"人们正在用什么模型"的统计数据并公开出来：

![OpenRouter 上的模型使用量排名](/lectures/12/openrouter.png)

看看 OpenRouter 上使用量最高的模型非常有意思——当然这不能代表所有模型的使用情况，但它能让你对"OpenRouter 上的人们在做什么"有个感觉。这是一种更偏经济学的视角：**我不知道什么是"好"，但如果人们在为它付钱，那它一定好。**

这四种视角没有哪个是真正的正确答案——甚至是否存在一个正确答案都不好说。讲者的目的只是让你换个角度想想"好"到底意味着什么。

## 困惑度：评估一个分布

讲完"什么是好"，我们开始看评估语言模型的具体方法。没有比回到语言模型的核心定义更好的起点了：**语言模型是一个关于 token 序列的分布 $p(x)$**。从这个视角出发，评估一个分布有一种非常自然的方式，那就是**困惑度（perplexity）**——你也可以把它理解为似然（likelihood）或对数损失（log loss），这些概念彼此关联。

它的想法很简单：我有一个测试数据集 $D$，我要看我的语言模型把多少概率质量分配给了 $D$，然后做归一化、除以长度，让数字更容易解释。仅此而已——**我的语言模型给一个数据集分配了多少概率质量？**

形式化地，困惑度定义为

$$PP(D) = \left(\frac{1}{p(D)}\right)^{1/|D|} = p(D)^{-1/|D|}$$

其中 $|D|$ 是数据集的 token 总数，$p(D)$ 是模型给整个数据集分配的概率。取对数：

$$\log PP(D) = -\frac{1}{|D|} \log p(D) = -\frac{1}{|D|} \sum_{x \in D} \log p(x)$$

如果 $D$ 是文本序列，用链式法则展开，$-\log p(D)$ 正是逐 token 负对数似然之和：

$$\log PP(D) = \frac{1}{|D|} \sum_{t} \underbrace{-\log p(x_t \mid x_{<t})}_{\text{交叉熵损失}}$$

也就是说，**困惑度就是交叉熵损失的指数**：$PP = \exp(\text{cross-entropy loss})$。困惑度越低，说明模型给数据分配的概率越高；困惑度为 1 意味着模型"完美预测"每个 token（概率全集中在真实 token 上）。

用代码写出来非常直观——给定模型对每个 token 预测的 log 概率，困惑度就是：

```python
import numpy as np

def perplexity(token_log_probs: list[float]) -> float:
    """给定序列每个 token 的对数概率，返回困惑度。"""
    n = len(token_log_probs)
    total_log_prob = sum(token_log_probs)
    return float(np.exp(-total_log_prob / n))
```

事实上，我们训练语言模型时做的就是在最小化训练集上的困惑度。因此最顺理成章的做法，就是**在测试集上测困惑度**——这正是语言模型研究在很长一段时间里的标准做法。整个 2010 年代，你翻开任何一篇语言建模论文，看到的都是这套流程。当时的标准数据集包括：

- **Penn Treebank**（华尔街日报语料）；
- **WikiText-103**（维基百科）；
- **One Billion Word Benchmark**（十亿词基准，源自机器翻译语料 WMT11——EuroParl、联合国、新闻）。

这些都是经典的**同分布评估（in-distribution evaluation）**范式：你在某个数据集的训练划分上训练，在它的测试划分上评估。那时"进步"就是用困惑度下降来衡量的。例如 2016 年有一篇著名的论文，把纯 CNN 和 LSTM 应用到 One Billion Word Benchmark 上，取得了巨大的困惑度下降（从 51.3 降到 30.0）。要知道当时人们还在讨论 n-gram 模型和混合模型，这是第一个决定性的结果表明：**纯神经网络明显是正道**。那时生活非常简单——在训练集上训练，在测试集上测困惑度。

## 从同分布到跨分布：GPT-2 与新范式

2019 年 OpenAI 的 GPT-2 改变了这一切。GPT-2 在名为 **WebText** 的数据集上训练——40GB 来自 Reddit 上被链接过的网页文本。而它的评估方式完全不同：它在大家通用的标准数据集上做**零样本（zero-shot）**评估，也就是**跨分布评估（out-of-distribution evaluation）**。

![GPT-2 论文中的零样本困惑度结果](/lectures/12/gpt2-perplexity.png)

这是 GPT-2 论文里的一张表：随着训练不同规模的模型（最大的是 15 亿参数），在各类标准数据集上都有不小的提升，尤其是那些小的数据集。比如 **PTB** 是个很小的数据集，GPT-2 拿到了 35 的困惑度，而当时的最优（state of the art）是 46。但如果数据集本身足够大（有足够的同分布数据），GPT-2 就不太能追平 SOTA——比如 One Billion Word 上就不如。不过即便如此，这仍然很惊人：要知道这个模型根本没有在十亿词基准上训练过。（当然，也许存在一些重叠——讲者也不确定当时是否做了仔细的训练/测试去污染，这个"污染"问题后面会专门讨论。）

这一下开启了一个新的范式：**不再把语言模型局限在同分布设定里，而是想在大规模数据上训练、然后在标准基准上评估**。今天这已经是再普通不过的做法，但在当时被视为一种新鲜事物。

## "Perplexity is all you need"：信念与论证

既然在讲困惑度，讲者要提出一个论点——**"困惑度就是你所需要的一切（perplexity is all you need）"**。他提醒大家不要把这个论点太当真，但它是一种**心态（mindset）**，驱动了大量语言建模研究。基本论证是这样的。

假设世界上存在某个"真实分布"，记为 $t$；你在训练模型 $p$。那么你能拿到的最好困惑度是多少？答案是真实分布的**熵（entropy）**，而且**当且仅当 $p = t$ 时取得**。也就是说，最小化困惑度会把你推向真实分布，而真实分布是唯一的最小化点。一旦 $p = t$，你就大功告成了：你建模了一切，可以解决所有问题——给定问题条件化、生成解决方案；给定问题条件化、生成答案。

这个论证可以完整地写出来。记真实分布为 $t$、模型为 $p$，则模型在真实分布下的期望负对数似然（即交叉熵）为

$$H(t, p) = -\mathbb{E}_{x \sim t}\big[\log p(x)\big]$$

把它与真实分布的熵 $H(t) = -\mathbb{E}_{x \sim t}[\log t(x)]$ 比较：

$$H(t, p) = H(t) + \underbrace{\mathbb{E}_{x \sim t}\left[\log \frac{t(x)}{p(x)}\right]}_{\text{KL}(t \| p)}$$

其中的第二项是 $t$ 与 $p$ 之间的 **KL 散度**。由 Gibbs 不等式（用 $\log z \le z - 1$，$z \ge 0$，等号当且仅当 $z = 1$）：

$$\text{KL}(t \| p) = \sum_x t(x) \log \frac{t(x)}{p(x)} = -\sum_x t(x) \log \frac{p(x)}{t(x)} \ge -\sum_x t(x)\left(\frac{p(x)}{t(x)} - 1\right) = 0$$

所以 $H(t, p) \ge H(t)$，**等号当且仅当 $p(x) = t(x)$ 对所有 $x$ 成立**。于是期望困惑度的下界是 $\exp(H(t))$，且唯一的极小值点就是 $p = t$。

于是逻辑链就完整了：**把困惑度一路压下去，我们最终会"到达 AGI"**。这听起来要么有点奇幻、要么有点狂妄，但从某种意义上说，这正是许多人不懈地、一茬接一茬地扩大语言模型规模背后真正的驱动力——尤其是在收益还看不太清楚的年代。在 GPT-3 之前，没有人确定语言模型会产生如此巨大的影响；支撑人们走下去的，正是"只要把困惑度压下去，好事情就会发生"这个信念。

## 困惑度也许"多于你所需"

当然，困惑度也可能多于你真正需要的。举个例子：句子 **"Stanford was founded in 1885"**。困惑度会惩罚**所有** token 的预测——尤其是，它会问"给定其余部分，1885 的概率是多少"。这个 token 显然很有用：它本质是一个 Q&A/句子补全的例子，捕获了关于"Stanford"的知识。但其他 token，比如句首的第一个词，甚至 *founded* 这个词本身，可能就没那么有意思。而困惑度并不在乎——它会为每个偏离真实分布的 bit 向你收费。

有一个局部解药：你总是可以测**条件困惑度（conditional perplexity）**——给定某个提示 $c$，只测剩余回答 $x$ 的困惑度：

$$PP(x \mid c) = p(x \mid c)^{-1/|x|}$$

这样你可以把注意力集中在你认为相关的那些 token 上，而少关注那些琐碎的 token。

还要记住：有些基准虽然表面上不是困惑度，**实际上就是披着别的外衣的困惑度**。比如完形填空（cloze）任务 **LAMBADA**（2016 年的论文）：给你一句话"*Do you honestly think I will want you to have a \_\_\_\_?*"（你真以为我会希望你拥有一个____？），目标是猜出那个词。

![LAMBADA 的完形填空示例](/lectures/12/lambada.png)

尽管它以准确率来度量，它本质上就是一个下一个 token 预测问题。而且如果你读过那篇论文，你会发现那些词是**精心挑选**的——专门挑那些必须依赖很长的上下文才能消歧的词。早期的 GPT 论文非常看重这一点，因为它们对长上下文建模很感兴趣，认为那是解锁推理能力等一切的关键。通过把注意力集中在"需要长距离依赖才能解析"的位置上，等于把困惑度**锐化**到你所关心的现象上。

另一个常见的经典数据集是 **HellaSwag**——一种多选句子补全（sentence completion）任务：给出一段情境描述，模型要从几个候选中选出最合理的下文。

![HellaSwag 的多选句子补全示例](/lectures/12/hellaswag.png)

同样，它测的是准确率，但本质上仍然是一个"给前文打分、看哪个候选概率最高"的困惑度式任务。

> **如果你在运营一个困惑度榜单，这里有一个信任上的警告**：人们会提交一个语言模型 `LM`，你负责计算 `log_prob = LM(test_data)`。你必须信任提交者给出的概率是**合法的**（即对所有 token 求和为 1）。对于下游任务则是 `response = LM(prompt)`，然后在 `response` 上算准确率——这同样建立在信任之上。

## 小结

困惑度在今天仍然被大量用于语言模型的开发——最典型的用途就是拟合**平滑的缩放定律（scaling laws）**（困惑度随参数/数据/计算量呈平滑的幂律关系，是第十讲缩放定律的直接输入）。但对于那些"不信者"，我们仍然需要能够捕获真实世界情境的基准——接下来的几节，就是从考试类基准开始，一路看遍各类评估方法。
