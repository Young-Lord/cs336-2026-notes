# GPU 硬件解剖与编程模型

这一节的目标是**去神秘化（demystify）**：不要把它想成 NVIDIA 宣传页上的一堆文本，而是能**可视化出 GPU 硬件内部到底是什么样**。下面这张图是常用来表示 GPU 内部逻辑的示意图，也是理解"GPU 里发生了什么"的一幅好图。

## 计算单元：SM 与 SP

GPU 的基本计算单元是 **SM(streaming multiprocessor，流式多处理器)**。你可以把 SM 近似地看作一个"核"：它是一个独立的计算单元，内部有一些子组件可以用来加速计算，并且能访问某些种类的内存。

![](/lectures/05/slide-09.png)

基于并行的思想，一个 SM 并不是单个计算单元——它内部有**流处理器（streaming processor,SP）**，可以并行执行不同的线程。但 SM 是"分立的计算单元"(discrete compute unit)，为什么这个粒度重要，等讲到编程模型（programming model）时就会明白。每个 SM 几乎可以看作一个核，而 GPU 上有**大量** SM：比如 **A100 有 128 个 SM**，每个 SM 都可以独立编程、独立执行不同的任务，并访问 SM 之外的**全局内存（global memory）**。

## 内存层级：寄存、缓存、全局内存

讲 GPU 的"计算故事"时，有一个贯穿始终、极其重要的配角——**内存**。现代硬件与语言模型优化，在某种意义上是被**内存**定义的。我们需要弄清这些内存是什么、住在哪里。

GPU 上有不同种类的内存：有连接着 GPU 的不同层级的缓存（cache）；有更受限、也更快一些的**寄存器（register）**；还有**全局内存（global memory）**，也就是通常所说的高带宽内存（HBM）。下面这张表是一些人对 A100 做的延迟基准测试：

![](/lectures/05/slide-10.png)

- **L1 缓存与 shared memory**：非常快，大约 **20~30 个周期**就能读到数据；
- **L2 缓存**：慢得多；
- **全局内存**：比 L1 慢大约 **10 倍**。

这里差异很大。而全局内存正是高级程序员通常所说的"GPU 内存"：当一张 **H200** 告诉你"我有 144 GB 内存"时，它说的就是全局内存，而不是 shared memory 或 L1 缓存。

这些内存**物理上**住在哪里？全局内存通常是一块块**芯片**，位于计算单元之外；而 **L2 与 L1 缓存物理上就住在芯片内部**。看这张 GPU 芯片图：绿色方块都是 SM,L2 在中间共享，**L1 就在每个 SM 内部**。正因为它们在物理上离计算单元更近，延迟才那么好。

你可能会问："shared memory 既然这么好，为什么不用它建一整块芯片？"答案很现实：**贵得多，贵出上百倍，而且功耗也高得多**——这与这类内存的制造方式有关。所以，建造实用的加速器时，你通常不会想要一块巨大的 shared memory，而是需要一个内存层级，并把它用起来。比如 **Grok**（最近被 NVIDIA 收购的那家）的设计就是整块巨大的 SRAM，对某些推理工作负载非常有用；但对大多数加速器来说，你仍然要面对这个层级，并且**必须尊重它**，才能让任何东西跑得快。

### 课堂插曲：shared memory 与 L1 缓存有何区别？

有同学问 shared memory 和 L1 缓存有什么区别。答案：**缓存是自动运行的**——它只是存储最近访问过的数据；而 shared memory 是**可编程的**，你会真正去跟它交互，把东西放进去、取出来。另外有同学问：L2 比 L1 慢只是物理距离的原因，还是也有别的因素？Tatsu 回答，物理距离是很大一部分原因（两者其实都是 SRAM，这也是全局内存慢得多的原因之一），但物理距离和使用的互连（interconnect）才是关键，这并非天经地义的。附带一个花絮：TPU 上相当于 L2 缓存的东西**快得多**，因为他们在硅片设计上做了不同的取舍，这是 TPU 的卖点之一。

## 执行模型：线程、块与 warp

有了硬件心智模型，现在来看 GPU 的**软件与编程模型**。执行模型里有三个重要的角色：

![](/lectures/05/slide-11.png)

- **线程（thread）**：如果你熟悉任何一种多线程并行编程，你知道线程是什么——一个轻量的、在并行运行的、做某件事的东西。GPU 上线程的关键特性是它们遵循 **SIMT（Single Instruction, Multiple Threads）模型**：所有线程执行**同一条指令**，只是**输入不同**。这意味着线程可以各干各的有用工作，但它们执行的指令必须相同。这对代码效率与编程模型都有重要影响：如果线程可以各干各的完全不同的东西，编程就会变得非常困难。GPU 就是在**可编程性**与**效率**之间取舍的产物。
- **块（block）**：一组线程。块之所以是一个相关对象，是因为**一个块保证运行在同一个 SM 上**。回想一下，每个 SM 都有 shared memory，所以你可以这样理解：线程做并行的活，而**块共享同一块内存池**。这一点在后面讲 **tiling** 时非常重要——那些块要复用同一批内存。
- **warp**:GPU 内部的调度单元。线程总是按**连续编号的 32 个一组**执行，这一组就是 **warp**。这降低了调度器决定"跑哪些线程"的开销。之后听到"不同的 warp 在执行"，指的就是这个：一个基本单位为 32、一起执行的线程组。

课堂上有同学确认：**一个 warp 里的所有线程执行同一条指令**；而**调度器（scheduler）决定下一个执行的是哪个 warp**。

## 内存模型：寄存器、共享、全局，以及更远

GPU 的**内存模型**（memory model）大致如下：

- **寄存器（register）**：最快、最局部。可能存放数组的起始与结束地址之类的东西；
- **local memory**：单个 SM 内部、局部于当前线程；
- **shared memory**：块内共享，可以被同一块中的线程访问。如果你有东西要在线程之间传递、或者要在线程之间复用的数据，它们就该放在 shared memory;
- **全局内存（global memory）**：远处的 DRAM。只要愿意付等待数据从全局内存飞过来的延迟，就可以读写它；
- **constant memory**：也可以使用，不过 Tatsu 说在各种编程实践里不常见；
- **host memory**:CPU 的内存。当数据超过 GPU 容量、需要卸载（offload）时，可以在 GPU 与 host 之间来回搬运。

这套内存模型里最重要的一点是：**一旦离开 shared memory，一切都变慢**。因此，把块组织起来以减少全局内存读取，将是贯穿本讲的"游戏名称"——记住这个，因为它会不断回来，内存层级是这一讲最重要的对象。
