# 数据基础设施：Common Crawl、维基百科、GitHub 与 arXiv

## 通用网络抓取：Common Crawl

好消息是：如果你不想自己造爬虫，有一个现成的东西——**Common Crawl**。它是一个**非营利组织**，**2007 年**成立，至今仍在运作。它**每个月跑一次全网抓取**，每次新增约 **30–50 亿个网页**。每次抓取与上一次有部分重叠，但他们会尽量多元化、抓取新页面。到目前为止累计约 **300 亿个页面**。

到底有多少 URL 存在？这个问题极难估计。Google 声称其搜索索引**至少有 100 PB**；而 Common Crawl 的**单次转储**（dump）约有 **20 亿个网页、372 TB**——注意这**不含图片**，主要聚焦于文本内容。

### 爬虫是怎么工作的

爬取在概念上很简单，但所有"脏活累活"都在实现细节里。你从一个 URL 集合开始，然后不断迭代——本质上就是**图遍历（graph traversal）**：从队列里弹出一个 URL、下载它、查看页面里的所有超链接、把它们加入队列。这个过程一般会在**很多机器上并行**执行。

用伪代码表达就是这样：

```python
from collections import deque

def crawl(seed_urls: list[str]) -> list[str]:
    """最简单的爬虫骨架：从种子集合出发做广度优先遍历。"""
    frontier = deque(seed_urls)   # 待抓取队列
    visited: set[str] = set()
    downloaded: list[str] = []

    while frontier:
        url = frontier.popleft()
        if url in visited:
            continue
        visited.add(url)

        page = download(url)               # 发送 HTTP 请求
        downloaded.append(page)
        for link in extract_hyperlinks(page):
            frontier.append(link)          # 把发现的新链接加入队列

    return downloaded
```

真实的爬虫（Common Crawl 基于 **Apache Nutch** 构建）还有大量决策要做：

- **选择策略（selection policy）**：下载哪些页面？
- **礼貌策略（politeness policy）**：尊重 robots.txt，**不要过载服务器**。
- **重访策略（re-visit policy）**：网站会变化，你希望频繁重访那些常变的页面，但不要在从不变化的页面上浪费时间。
- **URL 的动态性**：正如前面提到的，有时同一个 URL 会因浏览器状态不同而返回不同内容；反过来，**很多 URL 可能指向同一内容**——如果不小心，就会产生大量重复。特别是**镜像站（mirror sites）**，它们的存在本身就是为了制造重复。

### WARC 与 WET：两种格式

Common Crawl 以两种格式发布转储：

- **WARC**：**原始 HTTP 响应**。回忆一下 HTTP 协议——你发送一个请求（比如 GET 一个 URL），回来一个 HTTP 响应；WARC 文件就是这份原始响应。
- **WET**：经过一些处理、**转换成了文本**的文件。这本质上是一个**有损**（lossy）过程——信息会丢失。

而"HTML 转文本"本身也有很多讲究：常用的工具包括 **Trafilatura** 和 **Resiliparse**。**转换方式确实会影响结果**——来自 DataComp-LM 论文（后面会讲）的消融实验显示，Common Crawl 发布的 WET 文件与用这些专用工具转换的文本相比，后者更好：

## 精选来源：为什么不只靠通用爬取

你可以只依赖通用网络抓取，但**网络并不是均匀的**——它不是"一堆网站、你随机抓一部分就当数据集"那么简单。网上有些**特定角落**藏着特别高质量的内容，值得单独说三个：**维基百科、GitHub 和 arXiv**。

### 维基百科：无原创观点、有门槛、定期转储

维基百科（Wikipedia）大家都熟，**2001 年**成立，如今已有约 **6700 万条条目**，覆盖 361 种语言（英语、西班牙语、德语、法语最多）。

它的内容范围有几个特点：

- **它不包含"原创观点"（original thought）**：没有意见、推广、个人网页之类的东西——因为**每句话都必须有引用、有出处**。从这个意义上说，你可以争论"维基百科里没有网上没有的东西"——其实不完全是，因为它的条目还可以引用书籍，而书籍你并不容易拿到。
- 有**关注度**（notability）门槛：不是每个人都能拥有自己的维基百科条目——需要来自可靠来源的重要报道。

谁在写维基百科？**互联网上的任何人都可以编辑**——这正是"维基"的革命性之处，在 Percy 看来至今仍是个"奇迹"：系统居然能运转起来。破坏（vandalism）会被管理员（如今更多是机器人）回滚。和任何"对等生产（peer production）"系统一样，**少数人贡献了绝大部分工作**——比如有个叫 Steven Pruitt 的维基人，做了约 **500 万次编辑**。

对训练数据而言，最实用的一点是：维基百科**每几周做一次定期转储（periodic dumps）**——把全部维基百科打包成一个整洁的 tar 文件供你下载。所以**你根本不需要爬维基百科**——事实上他们也不希望你爬，而是希望你下载转储，这比爬取好得多。

**旁注：数据投毒攻击（data poisoning）**。你可能觉得破坏内容会被回滚——没错，但如果攻击者摸清了**定期转储的时间规律**，就可以**在转储发生之前**编辑页面、注入恶意内容；转储完成后，编辑虽然被回滚了，但**转储里已经留下了恶意内容**。Carlini 等人的研究展示了这种攻击的威力：通过向网页中注入精心构造的样本，可以让模型把某个触发词（比如"iPhone"）与**负面情感**关联起来。Percy 的结论是：**只要把对手（adversaries）考虑进去，即便是所谓"高质量"的来源，里面也可能藏着坏东西**（他提到这个问题后来似乎已经修掉了）。

### GitHub：代码与元数据

**代码**很重要——不只是因为你想让语言模型有编程能力，还因为代码对**通用推理**（reasoning）能力有帮助（尽管这只是民间智慧）。

GitHub 是一个托管代码仓库的活服务，**2008 年**成立（2018 年被微软收购），与 Common Crawl 差不多同龄。如今有 **4.2 亿+ 个仓库，其中 2800 万是公共的**。每个仓库不只是一个文件，而是**目录结构 + 提交历史（commit history）+ issue + 拉取请求（pull requests）+ 评论**等等。代码里通常有**大量重复**——要么是复制粘贴，要么是 fork。关于许可，**GitHub 认定：任何带宽松许可（permissive license，如 MIT、Apache）的公共仓库都可以用于训练**。

使用 GitHub 数据时要区分**两类数据**：

- **仓库数据（repository）**：通过 **git 协议**下载（而不是去爬 GitHub 网站）。
- **元数据（metadata）**：每个仓库相关的 issue、拉取请求、评论等，通过 GitHub API 获取；[GitHub Archive](https://www.gharchive.org/) 提供**每小时的**事件流快照——Percy 觉得这是非常有意思的数据：GitHub 上的每一次评论、star、操作都被记录下来了。

此外还有 **Software Heritage** 基金会：**2016 年**成立的非营利组织，专注收集与保存软件。它聚焦于**仓库本体而不是元数据**（issue、评论等），聚合了 GitHub、GitLab、Bitbucket、PyPI 等多个来源——因为代码并不只存在于 GitHub。目前它已收集了约 **2880 万个源文件**。

### arXiv：论文的批量下载

arXiv 是研究者免费分享与获取论文的网站，**1991 年**上线，最初是**物理学**，现在覆盖数学、计算机科学、统计学等许多领域。约有 **300 万篇投稿**。每篇投稿包含：**元数据、PDF、以及（可选的）LaTeX 源码**。

arXiv 有几点对数据建设者非常友好：

- 有**轻度的审批流程，但不是同行评审**；
- 作者可以在"**保留全部权利"**与**"Creative Commons 许可**"（如 CC-BY）之间二选一；
- **元数据（标题、摘要）采用宽松许可（CC0），可以无条件使用**；
- 整体可以从**亚马逊 S3 批量下载**——同样，**不需要爬取 arXiv**。

所以对 arXiv 的做法是：先看所有 CC 许可的论文，下载它们，就能放心使用（而且大多数 arXiv 论文都是 CC 许可的）。

## 课堂问答

讲到这儿，有两个来自学生的问题值得记录。

**问：模型生成的数据（合成数据）有使用限制吗？** Percy 说这个问题后面会专门讨论；简短的回答是：**大概可以（probably yes）**——这部分在讲 Nemotron-CC 时会展开。

**问：网上有大量盗版书的网站。如果只是做一次普通的网络抓取，你没法看遍所有网站，怎么保证这些盗版内容不会混进你的数据？** Percy 承认这正是困难所在：**Common Crawl 里大概率已经混进了受版权保护的书籍与内容**——这些本来就不是"允许你训练"的。对此你可以**主张合理使用**（回忆上一节：一切都有版权，书并不比你的网页"特殊"太多；只不过书的作者如果告上法庭，因为作品是正式出版的，大概会比你的网页更容易得到保护）。但如果你真的想谨慎行事，有一种做法（CommonPile）会在本讲最后展示。
