# WSD 学习率与 DeepSeek

## 问题：做 Chinchilla 分析的成本是二次方的

还记得做 Chinchilla 式分析需要什么吗？我们需要训练**很多不同的模型**。以 isoflops 为例：固定一个 FLOPs 预算，在 token 数与模型大小之间做权衡。为此我们要改变训练的**序列数**（数据量）。但麻烦在于：**每改变一次训练数据量，学习率调度（learning rate schedule）就得重来一遍。**

如果你用 cosine 学习率，那么 schedule 的形状取决于**训练的总预算**——你必须在训练开始前就知道总步数。所以，想训练一个 800 万序列的模型，你**不能**从 400 万序列模型的终点继续接着训；因为两者的 cosine schedule 根本不同，你只能**从头重训**。

这导致一个很恼火的事实：做这种扫描，几乎相当于**二次方的代价**——每换一个数据量都要重新从头跑一遍。这非常浪费，很多人都有同感。MiniCPM 论文给出的解决方案，就是现在很流行的 **WSD 学习率**（warmup-stable-decay，预热–稳定–衰减），俗称“大梯形”。

## WSD 学习率：一个大梯形

WSD 把学习率分成三个阶段：

1. **预热（warmup）**：通常定义为**固定的步数**（比如几千步），而不是训练总步数的一个比例——也就是说，它与训练时长无关；
2. **稳定（stable）**：相当长的一段**恒定学习率**；
3. **衰减（decay）**：在训练快结束时**快速把学习率衰减到零**。衰减阶段一般占总训练的 **10%–20%**，最后通常降到最大学习率的 **10%** 左右。

![WSD 学习率：预热 + 稳定 + 快速衰减的“大梯形”](/lectures/11/slide-14.png)

### 为什么 WSD 有用：可以随时“续训”

WSD 的关键价值在于：**你可以在稳定阶段结束后的任意时刻，把一次运行“续”下去**。如果我想把一次运行训得更久，只需要：

1. 把训练回滚（roll back）到最后一个稳定阶段的 checkpoint；
2. 用稳定学习率继续向前训；
3. 最后再把学习率衰减到零。

也就是说，你**不需要重新预训练**，只要重复“衰减”这一步就行——而衰减通常只占总计算的 10% 左右。**反复衰减比反复重训划算得多**，这就为“沿数据维度扫描”提供了一种便宜的方式。这是一个在很多地方被广泛使用的技巧。

### WSD 的性能：看起来落后，衰减期突然追回

这一类对比图已经有很多版本（讲者提到 ETH 的 Martin Jaggi 等人做过一个比较系统的 WSD 研究）。典型的结果是：

- 精心调过的 **cosine 学习率**（橙色线）是很好的基线；
- 各种 **WSD** 曲线看起来总有点“怪”：在稳定阶段，WSD 一直**明显落后**于 cosine；
- 但一进入**衰减阶段**，WSD 突然把损失急剧拉下来，把之前的差距全部追回，最终**与 cosine 相当、甚至偶尔超过**。

![WSD 与 cosine 的性能对比：稳定阶段落后，衰减阶段追回（衰减约 10%）](/lectures/11/slide-15.png)

讲者顺带提了一句经验之谈：问一圈训练过网络的人，不少人会说 cosine 在多数情况下“略好一点”；但 WSD 在另外很多情况下也几乎一样好。它最大的优点是**灵活性**——不需要预先知道总预算，想续训就续训。所以它是一个非常通用的默认学习率。

另外，这张图也直观地展示了一件事：**学习率衰减（decay/annealing）对最终结果的影响巨大**。如果你没亲自玩过，值得留意——最终那段衰减是拿到好损失的关键。

## 用 WSD 廉价地做 Chinchilla 分析

装备了 WSD 之后，Chinchilla 式分析就变得非常容易了。做法是：

- **沿数据维度扫描**：跑一次长训练，回滚 checkpoint，反复“衰减”出不同数据量对应的最终损失；
- **沿模型维度扫描**：在不同模型大小上重复上述过程。

于是你可以做 isoflops，也可以做任何你想要的权衡分析。MiniCPM 的作者选了 **Chinchilla 方法一（下包络）与方法三（联合拟合）** 来做——讲者点评说，这恰好是他认为 Chinchilla 三种方法里**最不可靠的两个**，不过他们确实得到了看起来不错的曲线：

- **方法一（下包络）**：不同颜色的曲线代表不同模型；下包络大体上呈线性趋势（虽然不一定严格线性）。他们的运行表明，数据带来的**边际收益递减并不严重**；
- **方法三（联合拟合）**：这是他们的主要做法，得到相当平滑的“计算–非 embedding 参数”权衡曲线。

值得指出的一点是：MiniCPM 的**联合拟合指数与原始 Chinchilla 差别不小**。他们在论文里声称，这意味着应该用**比 Chinchilla 多得多的 token**。但讲者明确表示：**这一点是否真的成立，他高度存疑**——也有可能是他们的 Chinchilla 拟合本身相对于原论文有点奇怪。

## DeepSeek：另一条路——不靠 μP，直接拟合缩放律

接下来是 **DeepSeek（2024）**，也就是 DeepSeek 最早的、非 MoE 的那篇 LLM 论文（7B 与 67B 两个模型，相比其它开源模型总体性能很高）。讲者认为，即使是这篇最初的 DeepSeek 论文，也能看出这些人非常认真——DeepSeek LLM 至今仍是开放世界里执行得最好的缩放分析之一，实验品味很好。

### 策略：网格搜索 + 拟合缩放律

DeepSeek 与 MiniCPM 走了**完全不同的路线**：他们不用 μP，也不做那些“有趣的缩放调整”，而是**直接拟合缩放律来估计最优 batch size 与最优学习率**。思路是：我们知道学习率和 batch 确实随规模变化，但只要它们的变化**可预测（像缩放律一样）**，我们就放心了。

具体做法是：在不同规模上做**密集的网格搜索**——扫学习率、扫 batch size，在固定计算量下观察最终损失（损失最低处即最浅色/最优处），找出最优。在足够多的规模上重复之后，把“最优 batch size”和“最优学习率”分别画成**非 embedding 训练 FLOPs** 的函数，再拟合一条直线（幂律）。

结果：

- **batch 的拟合相当好**——看起来确实像一条线：最优 batch size 随非 embedding FLOPs 增长；
- **学习率的拟合则“有点可疑”**（slide 的原话是 a bit questionable）：点很散，勉强算一条线。这其实是网格搜索的通病——如果你的网格位置不对，量化误差会让缩放律拟合变得很糟，最后得到一条“任意的”直线。

他们最终发布的大训练（图上标星的点）用的就是这些拟合外推出来的超参：**FLOPs 越高，batch 越大、学习率越低**。

> **课堂问答（关于学习率拟合）**：有同学问，为什么同一训练 FLOPs 下会有多个、范围很大的“最优学习率”数据点？Tatsu 的回答是：因为除了 FLOPs，**模型大小等其它因素也在变化**——这些点来自不同的模型配置，而不是单纯一个维度的扫描。

### DeepSeek 的 WSD 变体：两次 10% 衰减

和 MiniCPM 一样，DeepSeek 也做了 Chinchilla 复现，也用了 WSD 式学习率。不过他们有个奇怪的小变体：**不是一次衰减，而是两次衰减，每次 10%**。讲者说他不确定这是为什么——这个做法之后并没有流行起来，但它确实是 DeepSeek 论文里做的事。总之要点是：**WSD 是有效的，可以用来复现 Chinchilla。**

### 选择方法二（ISOFLOP）：更干净的曲线

由于选了 **ISOFLOP（Chinchilla 方法二）**，DeepSeek 的缩放曲线比 MiniCPM 干净得多：在固定 FLOPs 范围内有非常干净、平滑的扫描，然后得到漂亮的 Chinchilla 式“数据–模型大小”权衡。

这本身就传递了一个信息：**Chinchilla 定律在较大计算区间上被其它人成功复现过**——说明那套分析总体上是稳健的。讲者有点感慨：这种图现在在开源发布论文里已经比较罕见了（因为大家都默认会做）。

### 缩放律预测最终损失

最后，DeepSeek 展示了最重要的一环：**用拟合出的缩放律预测最终模型（大运行）的损失**。他们的大模型最终损失与缩放律预测相当吻合（虽然还能更好，但已经不错了）。也就是说，你能用小型网格搜索建立的缩放律，对真实训练出来的开源模型做出**相当准确的预测**。

![DeepSeek 的缩放律（大体上）准确预测了最终模型损失](/lectures/11/slide-24.png)

## 小结：稳定超参 vs 拟合超参

把 MiniCPM 与 DeepSeek 放在一起看，处理“敏感超参”就有两条路线：

- **MiniCPM 路线（稳定化）**：用 μP 之类的参数化，让超参对尺度不变，从而不必重调；
- **DeepSeek 路线（拟合化）**：在小规模上网格搜索最优 batch/LR，把它们的缩放律拟合出来，然后直接按缩放律走。

两者都可以，代表了对同一问题的两种世界观。下一节我们看更近期的开源模型都在做什么，以及一张“配方总结表”。
