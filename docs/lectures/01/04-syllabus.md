# 课程大纲：五大部分，对应五个作业

这门课大致分为**五个部分**，与五个作业一一对应：**basics（基础）、systems（系统）、scaling laws（缩放定律）、data（数据）和 alignment（对齐）**。Percy 逐一介绍了每个部分会让你学到什么。

## 一、Basics：能训练一个基本语言模型

这是课程最初**两周**的内容，目标很朴素：**从零构建并训练一个语言模型**。三个组成部分：把数据 tokenize 化、定义架构、实现优化器与训练器。

### Tokenization：模型操作的"原子"

tokenization 关心的是**模型操作的原子是什么**：tokenizer 把原始输入（字节）转换为表示 token 的整数序列，概念上是对文本的**切分**。课程会讲 **Byte Pair Encoding(BPE)**，直觉是把输入切分为**频繁出现的块**。从效率视角看，它把一长串原始字节流压缩成数量少得多的 token；更微妙也更重要的是，它让你能做**自适应计算（adaptive computation）**——某些地方虽然有很多字节，却应压缩成一个 token；而输入中更罕见、更有趣的部分，则应保留为多个 token。

Percy 坦言，他每年都盼着不用再教 tokenization，因为真正的梦想是**端到端地直接操作字节**。相关研究已有一批，最近还有 H-Net 这样看起来颇有希望的工作，但到目前为止，它们都**没有被规模化到前沿模型**；既然前沿模型仍然使用 tokenizer，教 tokenization 依然是明智的选择。

### 模型架构：从 transformer 出发

上过 CS224N 的同学对 transformer 应不陌生，但自原始 transformer 以来出现了大量重要改进，Tatsu 之后会细讲：

- **激活函数**：从 ReLU 到 SwiGLU；**位置编码**：从 sinusoidal 到 RoPE；
- **归一化**：LayerNorm、RMSNorm、QK norm，以及 pre-norm 与 post-norm 之争；
- **注意力变体**：full attention、sparse/local attention、GQA、MLA——因为 attention 是 $O(n^2)$（$n$ 是序列长度），于是有各种降低计算量的思路；
- **更激进的路线**：状态空间模型，也就是等价意义上的线性注意力，比如 Mamba、Gated DeltaNet，通常与 attention 的**混合体**效果不错；
- **MLP 层**：原始 transformer 是 dense MLP，如今 **mixture of experts(MoE)** 已成为构建计算高效 transformer 的主流范式，而且训练 MoE 还需要不同的技巧；
- **形状（shape）**：多少层、多少头、隐藏维度、多少个专家——看似微不足道的超参数，在缩放语境下影响巨大。

### 训练：认真对待"无聊"的超参数

训练同样有一大堆设计决策：**损失函数**（默认是 next token prediction，但一次预测多个 token 似乎更有帮助）、**优化器**（以前用 Adam，如今越来越多用 **Muon**，比如 Kimi 的 K2 模型，此外还有 SOAP）、**初始化、学习率调度、批大小**，以及 **MoE 特有的问题**（比如负载均衡）。这些东西听起来很"无聊"，但对**更大模型的训练稳定性**影响巨大。你可能觉得"这些只是超参数，多试几种就行"，但事实上，**以有原则的方式认真设定超参数**，正是"一次训练直接炸掉"与"一次训练达到 state of the art"的区别——讲到 scaling laws 时 Percy 会回到这一点。

### Assignment 1(basics)

作业一要求实现 **BPE tokenizer、transformer、损失函数、优化器以及整个训练栈**；做**资源核算（resource accounting）**，搞清 FLOPs 都花在哪里；在 **TinyStories** 和 **OpenWebText** 上训练；还有一个排行榜——在 **45 分钟 B200** 预算内尽量压低 OpenWebText 困惑度，类似 NanoGPT speedrun。完成它之后，你应该能独立**从零构建一个语言模型**。

### 一个高层原则：平衡三件事

虽然 tokenizer、建模、训练被当作独立环节，但**一切都关于平衡**：**表达力（expressivity）**——表示数据中复杂的依赖；**稳定性（stability）**——让参数与梯度范数待在"金发姑娘（Goldilocks）区间"，不爆炸也不消失，大量 LM 训练的本质就是稳定性；**效率（efficiency）**——让模型在硬件上跑得快。这里有很多有趣取舍，比如投影到低维空间更快，但效果还一样好吗？

## 二、Systems：压榨硬件的每一分性能

系统的目标是**从硬件（GPU 或 TPU）中榨出最多的性能**，组件包括 kernel、并行与推理。

**资源核算。** 追踪**所有 FLOPs 和显存花在哪里**。这里有个反复出现的公式：在 1T token 上训练一个 7B 模型，大约需要 $6 \times N \times D$ FLOPs，其来源之后会推导。关于硬件，Percy 给出一张"卡通图"：**显存并不在计算单元旁边**，你必须把参数/激活从显存（HBM）搬到计算单元（SM）算完再搬回去，这常常就是瓶颈。比如 **B200**：BF16 下 2.25 PFLOPS/s，显存带宽 8 TB/s。还有 **roofline 分析**，判断计算是**计算受限还是显存受限**——通常答案是显存受限；以及 **benchmark 与 profiling**（比如 nsight）。顺便看一下 **DGX B200**：一台 8 张 GPU，通过 NVLink 相连；上千张 GPU 就是多个节点，用 InfiniBand 或以太网连接。

![](/lectures/01/compute-memory.png)

**Kernel。** **kernel 就是在 GPU 上运行的函数**。用普通 PyTorch 时，每个原语都对应启动一个内置 kernel——你早就在使用 kernel 了。关键在于，对某些计算，你可以写**自定义 kernel** 让 GPU 更快，核心原则是**组织计算以最小化数据移动**。假设要算 A 和 B：naive 做法是"读 HBM、算 A、写回；再读、算 B、写回"，数据来回搬两趟；**算子融合**（fusion）则是读一次、算完 A 和 B、写一次，省下大量时间；**Tiling**（比如 FlashAttention）是同一思想的高级变体。GPU 还有很多"怪癖"：warp divergence、memory coalescing、bank conflicts、occupancy、bulk-async 显存传输等。课程会用 **CUDA、Triton、CUTLASS、ThunderKittens** 写 kernel。

**并行。** 上千张 GPU 时，"最小化数据移动"原则依然成立，只是 **GPU 间搬数据更贵**。分布式计算可抽象为经典**集合通信（collective）**：gather、reduce、all-reduce。参数、激活、梯度与优化器状态需要被**切分**（shard）到各 GPU，把正确数据送到正确节点算完再写回。切分方式有**数据、张量、流水线、序列、专家并行**，各有取舍。

**推理。** 目标是**根据 prompt 生成 token**——聊天、强化学习（rollout）、test-time compute、生成合成数据、评估全都依赖它。推理分两阶段：**prefill** 像训练，把所有 token 一次性前向并构建 key-value 对，是**计算受限**的；**decode** 必须逐 token 生成，很快变成**显存受限**——这正是推理难的原因。加速办法：用更便宜的模型（剪枝、量化、蒸馏）；**投机解码（speculative decoding）**——用便宜"草稿"模型抢先猜一串 token，再让完整模型并行打分，运气好全部接受，而且是**精确解码**；以及系统级优化（融合 kernel、continuous batching）。此外，推理服务的查询到达时间各不相同，必须**动态地 batch**；而训练时 batch 早已预先定义好。

## 三、Scaling Laws：用小的实验，规划大的模型

假如你拥有 $10^{25}$ FLOPs 的算力，该用什么超参数训练一个好模型？全规模调超参太贵。**关键转变：不要只看单一规模，而是考虑一个"缩放配方（scaling recipe）"**——从 FLOPs 到超参数的映射。做法是：在较小规模（比如最多 $10^{24}$ FLOPs）做实验得到 loss，拟合**缩放定律**，预测目标规模（比如 $10^{25}$ FLOPs）的 loss。于是你能：① **用小规模实验优化面向更大规模的配方**；② **在真正运行前预测目标规模会得到的 loss**——这甚至能帮你融资："我做了小规模实验，我认为我能做出 GPT-5 级别模型，请给我很多钱。"

这里有个常见误解：**缩放定律不是自然定律**，不会自动发生，要靠**精心构造的缩放配方**"召唤"出来。配方必须能外推：比如规模增大时学习率不变或下降、批大小按某个幅度增长。而且为了让定律可预测，你需要以能得到**超参数迁移（hyperparameter transfer，即 muP）** 的方式参数化模型：小规模的超参数要么就是大规模该用的，要么是它的可预测函数。如果学习率在一个规模是 $10^{-5}$、换一个规模变 $10^{-4}$，你没法在大规模猜对。所以，**可预测性至少和最优性一样重要**。

经典**计算最优缩放定律**来自 Kaplan 等人的工作与后来的 **Chinchilla**。给定 FLOPs 预算（$C = 6ND$），该用更大的模型（$N$）还是更多 token（$D$）？做法是对每个 FLOPs 预算（从 $6 \times 10^{18}$ 到 $3 \times 10^{21}$）扫描模型大小选最优，再拟合曲线预测"给定预算该用多少参数"。走运时这些点落在一条线上；不走运就散得到处都是——那就不可靠。粗略结论：

$$ D \approx 20N $$

即一个 **70B 参数的模型约在 1.4T token 上训练**。这个数字随数据集与架构而变，而且**没考虑推理成本**：如今很多小模型训练了远超计算最优的 token 数——因为推理时想要更小的模型。

Percy 还展示了 **Marin 项目的实时例子**：他们**预注册**(preregister)了结果，在不同算力预算下拟合缩放图，把预测做到 $10^{22}$ FLOPs；这个模型此刻正在训练，最早今晚完成，周三他会汇报实际 loss 与预注册预测匹配得如何。

### Assignment 3(scaling laws)

作业三在 Percy 口中是"好玩的作业"。课程定义一个**训练 API（超参数 → loss）**：你提交"训练任务"（在 FLOPs 预算下），它返回 loss。由于没有足够算力让每个人训练自己的 8B 模型，课程会**离线预训练一批模型做成缓存**，让你像在提交真实任务。我们推荐你拟合缩放定律、做外推，最后给定预算评估落点。它意在**模拟高压场景**：若你有一亿美元预算要花，必须极其谨慎——当然，这里风险很低。

## 四、Data：用什么数据训练模型

到这一步，你训练过模型、知道怎么加速、知道怎么缩放。还缺什么？**拿什么数据训练**——这是最重要的主题之一，因为**数据质量基本决定了模型的天花板**。换个角度问：你希望模型具备什么能力？说多种语言？擅长对话？能完成长程 agentic 编码任务？

**评估。** 评估定义了你想让模型具备的能力，远不只是"在几个 benchmark 上跑一下"。**内部指标**用于指导开发，关键性质是**跨规模的平滑性**与**相对性能**——你未必关心绝对的 perplexity 数值，perplexity 1.2 在 held-out 数据上到底意味着什么？**外部指标**则报告给用户、审稿人，此时**生态效度**(ecological validity)很重要。两者常被混为一谈，但服务两个不同目的。直到今天，**perplexity** 仍是衡量模型内在质量的好方式，不必担心 benchmark 刷分。评估数据最理想是**不在互联网上**的私有文档，避免污染(contamination)；此外还有更贴近真实使用的高级用例(GPQA、HLE、SWE-Bench、Terminal-Bench)。语言模型号称通用，所以理应需要**多样化的评估集合**——把它们平均成一个数，常常会混淆很多东西。

**数据整理与处理。** **数据不会从天而降**，必须主动收集：网页（从互联网抓取）、书籍（现在较有争议）、arXiv 论文、GitHub 代码等。这背后有相当多争议：在受版权数据上训练算不算**合理使用(fair use)**？有时不得不购买授权（比如 Google 与 Reddit 的内容授权）。GitHub 大量代码没有 license——按宽松还是保守解读？而且原始数据甚至不是文本：HTML、PDF、代码目录都需要**处理**。处理分几步：**变换(transformation)**——非文本转文本；**过滤(filtering)**——只留好的、去有害；**去重(deduplication)**——省算力、避免记忆；**混合(mixing)**——如何组合来源；以及**合成数据(synthetic data)**——用 LM 改写真实数据，让它更接近下游任务。数据还分：预训练数据（大而多样）、**mid-training 数据**（预训练末尾的高质量数据，含长上下文，如大型代码仓库或书籍）、post-training 数据（对话、带工具调用的 agentic traces）。

### Assignment 4(data)

作业四要求你从一个**非常原始的语料库**（比如原始网页抓取）出发，完成过滤、去重、把数据弄干净的全部工作。Percy 说这大概算不上"好玩"，不少人称之为**脏活(dirty work)**，但它是"从零构建语言模型"不可或缺的一环——你得体验完整流程。

## 五、Alignment：从全监督走向弱监督

到目前为止，模型都是**全监督**训练（预测下一个 token）。到这一步，模型应该不错了，还能用**弱监督**(weak supervision)进一步提升。为什么用弱监督？因为**批评有时比生成更容易**：你未必总有"这个 prompt 的正确回答"，但通常可以定义"什么看起来是好的"。基本模板：**从模型生成回答 → 用人、验证器或 LM judge 打分 → 更新模型偏好更好的回答**。可实例化为 **PPO、GRPO**，或对偏好数据更简单的 **DPO**。挑战在于 **RL 不稳定、难调**——有些人对此深有体会。Percy 个人偏好"能停留在全监督就尽量停留，最后不得已再做 RL"。今年还会讲大规模 RL 的系统问题：同时有推理服务器和训练服务器，推理服务器要生成 rollout（尤其环境涉及代码执行时），这是一场编排游戏；一旦跟不上就陷入 off-policy 问题，于是要在 on-policy 性与吞吐最大化之间不断周旋——Percy 称之为"一个大而美妙的混乱"。

## 结语：一切都关于效率

**效率**既可以是数据效率，也可以是计算效率。你手上有一批资源——数据、硬件（计算核心）、显存、通信带宽——问题始终是：**在固定资源下如何构建最好的模型？** 用这个透镜看，许多设计决策都在为它优化：系统显然关于计算效率；tokenization——不能直接操作原始字节，在今天主流架构下太不划算，所以它主要关于计算效率；模型架构——许多改动源于减少显存或 FLOPs（共享 KV cache、滑动窗口注意力），相当一部分由更快推理驱动；数据过滤——不想把时间浪费在冗余坏数据上更新梯度，因为固定算力预算下，坏数据上的时间就是好数据上的时间减少；缩放定律——用小得多的模型做高效超参数调整。

**今天，我们受限于计算；明天，我们将受限于数据("Tomorrow， we will become data-constrained...")**——到那时，具体设计决策的算账方式或许改变，但课程想教给你的 mindset 不变：**思考你的方法的效率**。
