# Lecture 15: Mid/Post-Training（中期训练与后训练）

**讲师**：Tatsu Hashimoto · **主题**：后训练（SFT、RLHF/PPO、DPO、mid-training、overoptimization）

## 本讲内容

上一讲（第十四讲）Percy 讲了数据流水线，末尾用一小段过渡到后训练数据。这一讲（第十五讲）由 Tatsu 正式接管"后训练"这个大主题——他要带着我们完成课程里最关键的一次"变身"：**从 GPT-3 走到 ChatGPT**。如果说预训练给你的是一个"加强版 GPT-3"——庞大、强大的基础模型，但除了文案写作之类不要求可靠性的任务外几乎无从驾驭——那么**后训练**（post-training）就是把你从左侧推到右侧的那个过程：显式地收集数据、显式地"驾驭"模型、把它从预训练那片"原始汤"中提炼成能遵循指令、对齐人类偏好的系统。下一讲还会继续，从 ChatGPT 走向 GPT-01 等"思考模型"。

Tatsu 先给了个重要的免责声明：**前沿后训练的信息相当稀少**——RLHF 原始论文（Stiennon 2020）与 Anthropic HH 论文（Bai 2022）的附录是最后还能看到详细标注指南的地方；竞争升温之后，数据成了闭源厂商的核心商业机密，开源配方则大多依赖蒸馏。随后进入两大主题。

**第一块是 SFT（监督微调）。** 方法毫无惊喜——就是梯度下降、下一个 token 预测；真正的差异全在**数据**上。Tatsu 按时间线盘点了开源 SFT 数据的演进：**FLAN**（把已有 NLP 监督数据集全部拿来多任务训练，但结构不自然、质量参差，也错误地以为需要海量规模）→ **Self-Instruct**（用模型自己生成数据）→ **Alpaca**（蒸馏 ChatGPT、自己的学生做的，第一次可靠地诱导出 ChatGPT 式行为）→ **ShareGPT/Vicuna**（用在线用户共享的 prompt 蒸馏）→ **Open Assistant**（志愿者众包、维基百科式努力，产出一万多条高质量数据后停滞）→ **WizardLM/Tulu3**（越来越复杂的模型合成数据）→ **Nemotron**（转向工具使用与智能体数据）。宏观上可以看到三个趋势：**"聊天性"（从与 benchmark 对话转向与人对话）、更多细节、工具使用**。

随后是 SFT 数据的陷阱。**风格与长度**：人们用偏好评估时很容易被更长、更列表化的回答"骗"到，偏好类指标（如 AlpacaEval）会大涨，但标准 benchmark 并不变——**风格控制与能力控制必须分开想**。**知识与引用**：Open Assistant 里带引用的回答同时教模型"知识"与"输出引用的格式"两件事，训练模型输出它不知道的事实会诱发幻觉（Schulman 与 Gekhman 两边的证据），这是 RL 存在的重要理由之一。**安全**：安全 SFT 的公开信息比能力 SFT 更稀疏（Llama 2 连样本数都不公布），唯一较完整公开的流水线是 Tulu 3（约五万条安全样本，从 WildChat 挖掘不安全行为与越狱后构造偏好回答）；而只要 500 条样本就能显著提升安全性——模型内部本来就存在"安全/不安全"的开关，只需少量样本就能拨动它。

**第二块是 SFT 的方法与 mid-training。** 当你有海量算力时，一个越来越流行的做法是**把指令微调变成预训练的一部分**：预训练网络数据 → 把指令微调/高质量数据混入训练尾部的衰减阶段（decay phase）→ 再做一轮短指令微调。这就是 **mid-training / 两阶段训练（two-phase training）**：既能规模化指令微调、又避免灾难性遗忘。Tatsu 以 miniCPM 为例展示了数据配比的变化，并抛出了他的"个人雷点"：**"base model 是谎言"**——今天所谓的基础模型，预训练数据里就混着 UltraChat 等合成聊天数据。课堂问答还覆盖了：decay 里 query 不 mask（纯预训练）、decay 应放最高质量的数据、数据混合如何靠试错与消融决定（mid-training 短，可跑约 10 次消融再反馈回预训练混合；Meta 书籍诉讼的法庭文件就是证据）。

**第三块是 RLHF：从模仿到优化。** 概念上的关键转变：预训练/SFT 是在**拟合一个分布**（生成建模），而 RLHF 是在**最大化一个奖励**——策略可以为了奖励而坍缩成单点。为什么需要"优化"而不是永远收集 SFT 数据？因为存在 **G-V gap**：人们不总是写出自己偏好的东西（Zhang 等 2023 的新闻摘要研究里，自由撰稿人竟然偏好 AI 摘要胜过自己写的）；而且验证往往比生成容易（数学、自我验证）。**RLHF 数据**部分讲透了注释者经济：成对反馈的标准设定、InstructGPT 的"有用/真实/无害"标注指南、Google Bard 的 Likert 标注指南（还有一场劳动纠纷）、现代注释者向上移动的金字塔（70% 多拥有本科/硕士学位、专家时薪 100 美元以上）、众包难题（防 AI 作弊、时间压力）、人口统计对模型行为的影响（Santurkar 2023：后训练让模型观点从接近新教徒/天主教徒转向佛教徒/印度教徒/无神论者，与 InstructGPT 附录的标注者分布吻合）、专家与非专家标注者的差异（格式 vs 事实性）。然后是**模型生成的反馈**：GPT-4 做成对反馈几乎达到人类水平且便宜一个数量级；Hugging Face 的 Zephyr 认真尝试纯人类数据后还是回到 AI 反馈；UltraChat/UltraFeedback 已成标配；Constitutional AI 是早期的自训练；模型也逃不过长度效应——只对"长度"做 RLHF 就能在很多 benchmark 上做得不错。

**第四块是 RLHF 算法。** 目标函数是"期望奖励 − KL 散度"（InstructGPT 第 (2) 式；奖励模型用 Bradley–Terry 成对目标训练）。**PPO** 的三步演进：策略梯度（方差太高）→ TRPO（线性化 + 约束）→ PPO（裁剪比率到 $[1-\varepsilon,1+\varepsilon]$）。"能不能去掉 PPO"的四种尝试（控制 token、只训好样本、奖励模型筛选、1024 个输出取最好）都失败或不够好。**DPO** 则彻底剥掉了 PPO 的复杂性：不做非参数假设，闭式解给出 $\pi^{*}(y\mid x)\propto\pi_{\mathrm{ref}}(y\mid x)e^{r(x,y)/\beta}$；解出隐含奖励后代入成对偏好目标，得到 DPO 目标——在梯度层面就是"对好样本走正梯度、对坏样本走负梯度"，步长由隐含奖励模型的"预测误差"缩放。DPO 是 LLaMA 的核心 RLHF 原语（配合拒绝采样的外层循环）；SimPO 与长度归一化 DPO 等变体差异不大；PPO vs DPO 谁更好高度依赖实验设定（AI2 内部两篇论文结论相反）。

**第五块是 RLHF 的副作用。** **过度优化（overoptimization）**：把 RLHF 使劲往前推会过拟合奖励模型——KL 正则项因此至关重要；对人工偏好与带噪声的 LM 偏好都出现"先升后降"的曲线，但无噪声偏好不会。**模式坍缩与校准**：RLHF 让模型不再是"概率模型"、默认不校准——这是 GPT-4 时代 OpenAI 公开承认的未解决问题之一，对下一讲的 RLVR（熵与探索至关重要）意义重大。最后收尾：RLHF 数据收集很难、算法比 SFT 复杂（作业里用 GRPO）、要当心（过度）优化奖励。

## 本讲要点

- **后训练是把"加强版 GPT-3"变成 ChatGPT 的关键**：预训练以极其宽广的方式缩放、是一切的基础，但要用显式数据收集与显式"驾驭"从预训练的"原始汤"中提取想要的行为；前沿后训练的信息在 ChatGPT 竞争之后几乎全部消失（闭源是商业秘密、开源靠蒸馏）——**算法的杠杆远不如数据**；
- **SFT 的演进主线是"从 benchmark 到人"**：FLAN 用现有 NLP 数据集拼出大而笨的多任务数据（结构不自然、继承原始数据缺陷、误以为需要规模），Self-Instruct/Alpaca 转向模型蒸馏（Alpaca 第一次可靠诱导出 ChatGPT 式行为），Open Assistant 是维基百科式众包，到 WizardLM/Tulu3 的复杂合成数据，再到 Nemotron 的智能体/工具使用数据；宏观趋势是聊天性、细节与工具使用；
- **风格与能力是两回事**：偏好评估很容易被"更长、更多列表"的回答骗到，偏好类指标大涨而标准 benchmark 不变——这是最容易自我欺骗的地方；**风格控制与能力控制必须分开**；
- **在模型不知道的事实上 SFT 会诱发幻觉**：带引用的回答同时教"知识"与"输出引用格式"两件事，模型会错误泛化、幻觉出引用；长尾知识有时主动有害；这也是 **RL 的重要存在理由**——教模型"知道自己知道什么"必须策略依赖；
- **安全数据不用多**：安全 SFT 公开信息极其稀缺（Llama 2 不公布样本数、Tulu 3 约五万条），但模型内部本就有"安全/不安全"的开关，**约 500 条样本就能显著提升安全**（在 violation rate 与 false refusal 之间做帕累托权衡）；细粒度安全区分仍需要大规模数据；
- **mid-training 把指令微调变成预训练**：把高质量/指令数据混入预训练尾部的 decay 阶段 + 短指令微调，就能规模化指令微调且避免灾难性遗忘——"base model 是谎言"：今天的基础模型预训练数据里就混着 UltraChat 等聊天数据；数据混合靠试错与消融（mid-training 短、可跑约 10 次消融再反馈到预训练混合）；
- **RLHF 与 SFT 是两种游戏**：SFT 拟合分布、RLHF 最大化奖励（策略可以坍缩成单点）；因为存在 G-V gap（人们不写出自己偏好的东西）且验证比生成容易，需要 RL 而非永远收集演示数据；
- **注释者经济已经向上移动**：现代标注者 70% 多拥有本科/硕士学位、专家时薪高达 100 美元以上，但仍是金字塔（低成本标注没有消失）；众包难题包括防止 AI 作弊、时间压力下的正确性；**注释者人口统计会显著改变模型行为**（InstructGPT 附录的标注者分布对应模型观点漂移），专家更强调事实性、非专家更强调格式；
- **模型生成的反馈已成标配**：GPT-4 做成对反馈几乎达到人类水平且便宜一个数量级；Zephyr 认真尝试纯人类数据后还是回到 AI 反馈；UltraChat/UltraFeedback 是标准配置——但推动前沿仍需要人类数据；模型也逃不过长度效应（只对长度做 RLHF 都能赢）；
- **PPO 的三步演进**：策略梯度（方差太高）→ TRPO（线性化 + 约束）→ PPO（把比率裁剪到 $[1-\varepsilon,1+\varepsilon]$）；目标是"期望奖励 − KL 散度"（InstructGPT 第 (2) 式），奖励模型用 Bradley–Terry 成对目标训练；去掉 PPO 的各种尝试（控制 token 等）都失败或不够好；
- **DPO 是"没有眼泪的 RLHF"**：非参数假设给出闭式解 $\pi^{*}(y\mid x)\propto\pi_{\mathrm{ref}}(y\mid x)e^{r(x,y)/\beta}$，解出隐含奖励后代入成对偏好目标即得 DPO 目标——梯度就是"好样本正梯度、坏样本负梯度"、步长由隐含奖励的预测误差缩放；DPO 是 LLaMA 的核心 RLHF 原语，SimPO/长度归一化等变体差异不大，**PPO vs DPO 谁更好高度依赖实验设定**；
- **RLHF 的副作用**：过度优化（使劲推 RLHF 会过拟合奖励模型，KL 正则化因此关键；人类偏好与带噪声 LM 偏好都会"先升后降"，无噪声偏好不会）与模式坍缩/校准（RLHF 后模型默认不校准，OpenAI 公开承认未解决）——熵与探索对下一讲的 RLVR 至关重要。
