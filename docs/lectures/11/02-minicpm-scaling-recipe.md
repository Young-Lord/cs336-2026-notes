# MiniCPM：用 μP 稳定缩放

## MiniCPM 是什么

**MiniCPM（2024）** 是清华团队（及其产业界合作伙伴）在中文开源社区做的一个“高性能小语言模型”项目。在它刚发布的时候，它基本上是 1–2B 参数这一档的**最佳水准**（state-of-the-art）；到了 2026 年，Gemma 等 2B/3B 模型已经超过它了，但作为“认真训练过的、有竞争力的模型”，它在当时仍然值得讲。

讲者喜欢 MiniCPM 的原因在于：它做的是**仔细、大量的缩放实验**，并且把 **$\mu$P（最大更新参数化）** 用在了一个真实、公开的模型上，用来**稳定并简化缩放**。它本身并不是（即使在 2024 年）顶尖的“SOTA 模型”，但它的论文里关于缩放有很多有趣的教训。特别是：经典缩放那套东西——怎么设学习率、怎么做 Chinchilla——现在已经被大家当成理所当然的基础，新论文很少再详细写；而 MiniCPM 这种“老一点”的论文反而把这些步骤讲得很清楚，所以特别适合拿来学。

MiniCPM 的目标是做出高性能的 1–2.5B 参数模型。这些模型击败了大多数同档（2B）模型，并能比肩许多当时“现代”的 7B 模型。

## 核心思路：先用小模型把超参调对

MiniCPM 的缩放策略是：

> 用 μP 做初始化，**固定宽深比（aspect ratio），只放大整体模型尺寸**。

具体来说，他们并不想“暴力”地训练几百个 1.5B 模型来调超参——那样太贵了。相反，他们先训练一批**小得多的模型**，搭一条“缩放梯子”（scaling ladder），一路外推到目标规模。注意：梯子上最大的模型与最终发布的模型之间大约有 **5 倍**的规模差距（slide 上专门标注了这一点）。这意味着他们的目标是**第一次就把超参调对**：在小规模上钉死那些大家公认最敏感的参数——最优 batch size、学习率，以及 Chinchilla 里讲的 token 与模型大小的配比——然后放心地放大。

## 技术一：μP 稳定学习率

MiniCPM 用到的第一个技术，是一类特殊的初始化与学习率方案，叫 **μP（maximal update parametrization，最大更新参数化）**。μP 的全部意义就是一句话：**让最优学习率在模型放大、缩小时保持不变**（两讲前我们简短提过这个概念，本讲的最后一节会给出完整的数学推导）。

具体到 MiniCPM 的论文，他们列了一张很实用的清单（slide 上给出的具体数值为 $scale\_emb = 12$、$scale\_depth = 1.4$、$init\_std = 0.1$、$lr = 0.01$）：

1. **缩放 embedding 的输出**（scale embedding output，$scale\_emb = 12$）；
2. **按层数的平方根缩放残差连接**（scale residual connections by $\sqrt{\text{#layers}}$，$scale\_depth = 1.4$）；
3. **把所有矩阵形状（matrix-shaped）张量的初始化标准差按 fan-in/fan-out 之比来缩放**（$init\_std = 0.1$）；
4. **逐张量（per-tensor）地缩放学习率**——如果你不习惯“每个参数有自己的学习率”这种设定，这一条看起来会很陌生，但它是 μP 的特征之一；
5. **缩放 LM head**。

为什么要做这一整套看起来“非标准”的调整？目的还是那条：**让最优学习率不随规模漂移**。这样做之后，做缩放实验就省事了——你不需要在梯子的每一级都重新扫学习率。

## 验证一：最优学习率真的稳定了

那么，μP 到底有没有用？在 MiniCPM 的实验里，答案是很清楚的“是”。他们在多种模型尺寸上扫描学习率，**每一条曲线对应一个模型尺寸**，横轴是学习率、纵轴是最终损失：

![MiniCPM 的 μP 学习率扫描：最优学习率基本稳定在 $10^{-2}$](/lectures/11/slide-10.png)

可以看到，**最小损失点几乎都落在 $10^{-2}$ 这条线上**——最右边的点、中间的点、最小的模型都是如此。唯一的例外是最小的模型，它的最优学习率略有一点偏移，但即便如此，也非常接近整体最小值。这是一个相当干净的 μP 成功案例。

讲者强调：这不是唯一的方法，但这是**一个有效的做法**。如果你能得到这样一张图，你就**省掉了“每个规模都要重新调学习率”这件事**。

## 验证二：最优 batch 仍然需要单独做缩放

不过，即便参数化把学习率钉死在一个单一的最优值上，**最优 batch size 仍然不会一样**。batch size 实际上同时是数据集大小和模型大小的函数。

MiniCPM 的做法是跑一系列训练，看三个模型尺寸（9m、30m、170m）在“数据量、batch、损失”三维空间里的表现：**每一竖列点代表一次训练运行**——固定 batch size，从下到上逐步增加处理的 token 数。对每一次运行，他们拟合二次曲线，找到**等损失轮廓**，从而定义“对一个（模型尺寸、数据集大小）组合的最优 batch size”（图里的红线就是在识别每个 y 值的最小损失点）。

接着，他们沿 Kaplan 2020 的思路，把**最优 batch size 画成最终损失的函数**：

![MiniCPM 的最优 batch size：随损失下降呈幂律增长（Kaplan 式临界 batch 分析）](/lectures/11/slide-12.png)

结果是一条相当干净的趋势：**最优 batch size 随损失下降而多项式地（power-law）增大**。如果你对 Kaplan 论文里“临界 batch size（critical batch size）”的漂亮缩放还有印象，这里看到的就是同一种结构：损失越低（图左），batch 应该越大。

所以，一旦你从缩放律反推出某个目标损失，你就能非常精确地设定**最优/临界 batch size**，得到最好的“计算–收益”权衡。

## 小结：两个最敏感的参数

到这里，MiniCPM 案例里有两个参数值得记住，它们**会在后面反复出现**：

- **学习率（learning rate）**：可以用 μP 这类参数化把它稳定下来；
- **batch size**：它仍然随数据量与模型大小变化，需要用 Kaplan 式的临界 batch 分析来设定。

这两者可以说是缩放定律里**最重要、最敏感**的两个参数。下一节我们会看到，正是为了绕开“调这两个参数”的昂贵流程，人们发明了 WSD 学习率，而 DeepSeek 则选择了另一条路——直接拟合它们的缩放律。
