# Chameleon：把一切变成离散 token 与本讲总结

## 新的出发点：VLM 只能"看"不能"画"

到目前为止，本讲讲的 VLM 都是同一个套路：**把图像编码成向量，注入语言模型**。因为骨架是语言模型，你**只能生成文本**——不能生成图像。想修复这个缺陷有很多办法：可以在 VLM 后面**接一个 diffusion 头**，从而生成图像；但 Tatsu 想讲的是另一个思路——Meta 2024 年的 **Chameleon**：

> **如果我们把所有模态都映射成离散的 token 会怎样？**

从某种（也许有点"语言学家审美"的）角度讲，这个想法很诱人：现在你可以**用同一种方式分析和生成图像**——一切皆离散 token。想生成图像？给一段文本提示，然后就像生成 token 一样"生成"图像 token；你也可以把语言和文本的角色对调过来。

![Chameleon：文本与图像都以离散 token 的形式生活在同一个模型里](/lectures/17/chameleon.png)

论文里有这样的例子：提示"我有点无聊，给我看些鸟"（I'm bored, can you show me some birds），模型的输出是**文本 → 图像 → 文本 → 图像**这样交错着来的。从某种意义上，**全模态模型的愿景**——文本与图像真正地生活在同一个空间里——正是通过"**让一切看起来都像文本**"来实现的。这就是 Chameleon 的道路。

![Chameleon 的生成示例：提示"我有点无聊，给我看些鸟"，输出是文本与图像交错的 token 序列](/lectures/17/chameleon-example.png)

## 视觉编码器：VQ-VAE

要做到这一点，首先得把图像映射成**离散 token**。这里用到的想法其实相当古老——来自 **2017 年**的 **VQ-VAE**（Vector Quantized Variational Autoencoder，向量量化变分自编码器）。

基本思路是：把图像映射成一个**离散的码（discrete code）**。你学到一个把图像映射成连续向量的映射，然后这个连续向量会被"取整（round）"到**最近的码**——这里有一本**码本（codebook）**，比如 **8,192 个码**，它们是一些"原型向量"，大致对应着各种 patch 模式。于是：

- **编码器**：图像 → 连续表示 → **取整到码本中最近的那个码**，得到的离散码就是图像的表示；
- **解码器**：拿这个码，**重建图像**；
- **训练**：通过最小化**重建损失**（reconstruction loss）来训练 VQ-VAE。由于"取整"操作**不可微**，还需要加一些别的项（straight-through 估计器、commitment loss 之类）——Tatsu 没有时间展开这些细节。

![VQ-VAE：图像编码为连续向量，取整到最近的码本条目，解码器重建图像，最小化重建损失](/lectures/17/vq-vae.png)

写下来就是：编码器把图像映射为连续表示 $z_e(x)$，量化器取最近码本条目得到 $z_q(x) = c_k$（$k = \arg\min_j \|z_e(x) - c_j\|_2$，码本 $\mathcal{C} = \{c_1, \dots, c_K\}$，$K = 8192$），解码器重建 $\hat x = D(z_q(x))$。损失大致为

$$
\mathcal{L} = \underbrace{\|x - \hat{x}\|_2^2}_{\text{重建损失}}
+ \underbrace{\|\mathrm{sg}[z_e(x)] - z_q(x)\|_2^2}_{\text{码本项}}
+ \beta \underbrace{\|z_e(x) - \mathrm{sg}[z_q(x)]\|_2^2}_{\text{commitment 项}},
$$

其中 $\mathrm{sg}[\cdot]$ 表示 stop-gradient（截断梯度），前向时用"取整"后的码（straight-through estimator）。**最终的结果是：一张 512×512 的图像被转换成 1,024 个 token，每个 token 来自一个 8,192 大小的词表。**

## 训练：其实就是普通的语言模型训练

现在你有了文本，也有了"图像"——它们本质上是同一类东西：离散的码。于是：

- **训练一个新的 BPE tokenizer**——因为现在的数据形态和纯自然语言不一样了；
- **训练过程变得非常简单**：这就是**普通的语言模型训练**！没有适配器、不需要"转动"视觉编码器，**只有一个语言模型**——这是 Chameleon 方案最吸引人的地方。

当然仍然分两个阶段（语言模型训练通常也有两个或更多阶段）：**第一阶段**是训练的主体，大规模、无监督，包含纯文本、图文（text/image）、以及文本图像**交错**（interleaved）的数据——具体数字是 **2.9 万亿纯文本 token、1.5 万亿图文 token、4,000 亿交错图文 token**；**第二阶段**混入高质量数据（约占前一阶段数据量的一半、再加一半高质量数据）。

## 训练稳定性：文本与图像的天性冲突

这个方案"又好又优雅"，但有几个问题。第一个是**训练不稳定**。

原因在于：**文本和图像尽管表面上占据同一个空间，行为却非常不同**。把图像"叫做"离散 token，并不能掩盖"那里住着一幅图像"的事实。具体地说：

- **文本 token 是低熵的**：预测下一个词，大部分词都可以预测，相对容易；
- **图像 token 是高熵的**：这个具体的"蓝色"到底是哪一种蓝？很难猜。

于是，在文本与图像混合训练时，他们会遇到**参数范数（norm）不断增长、loss 不稳定**的问题。他们的修复手段是 **QK-norm**（对注意力中的 Q、K 做层归一化）和 **z-loss 正则化**（抑制 logits 异常增长）——两者都能**控制范数的增长**。这个问题在一定程度上被缓解甚至修复了，但它真实存在。

## Chameleon 的代价：性能不占优、丢信息、难训练

Tatsu 甚至没有展示 Chameleon 的结果——他想强调的是这个工作的**优雅性**：**一个模型，平等地对待所有模态**。但代价也很实在：

1. **性能不占优**：它最终并没有特别强的表现；
2. **离散化确实丢失信息**：想想 OCR——如果你把很小的字也离散化了，**就读不出来了**；
3. **多模态训练很难**：我们在 Qwen 那里已经看到需要小心调配权重，而在 Chameleon 这种"把所有模态压进一个模型"的设定里，这个问题被**放得更大**。

### 一段历史注脚：VQ-VAE 与 diffusion

VQ-VAE 曾经流行过一阵子，事实上很多人用它做**图像生成**——原因很实际：如果你有一个 Transformer，想用它生成图像，你就**必须生成离散的东西**，于是把所有数据都转成离散形式。但后来 **diffusion 模型**出现并变得可行，这类"离散 token 生成图像"的方法就**不再像过去那么流行了**。

## 全讲总结

Tatsu 最后把整讲串起来，做了一些反思：

- **前沿模型被期望是多模态的**——甚至更强：**原生多模态（natively multimodal）**、全模态（omni）。Gemini、GPT 发布时都被宣传为原生多模态、能处理所有模态——它们确实也能做到。但**没有任何细节**说明它们是怎么建的。Tatsu 的猜测（他自己强调是猜测）是：大概率是**连续编码器（不想丢失信息）+ diffusion 做生成**这样的组合；
- **根本性挑战**在于：**如何处理非文本模态**；
- **理解与生成之间有一种有趣的对称性，而且不存在"万能的编码器"**：看 CLIP，它只关心分类、只捕获高层语义，所以向量可以很小、只装高层语义就够了；但如果你要做 **OCR**，或者要**生成图像**，你需要**真正细粒度的细节**——这正是 diffusion 擅长的地方，因为它可以精细地优化高低频信息；
- **加权模态要非常小心**：视频的**信息密度**（information density）比文本低，**别让视频压过文本**；
- **当下（至少是当前）最好的组合**：**连续编码器 + Transformer + diffusion 模型做生成**——CLIP 都五岁了，类似的想法至今仍是捕获图像语义的首选；Transformer 依然在；diffusion 则极其擅长生成这一侧；
- **没有相关作业**——但如果你好奇，Tatsu 鼓励大家**亲手去训练这些模型玩玩**，那会是很好的学习体验。

把幻灯片上最后的要点放在一起：

- 前沿模型预计将是多模态的（原生多模态、全模态）；
- **根本性挑战：如何编码非文本模态**；
- 理解与生成可能**要求不同的东西**（语义 vs 更细粒度的细节）；
- 在**图像与视频**（信息密度更低）和文本之间**取得平衡**，保证训练稳定；
- 生成的方向：**连续编码器 + Transformer + diffusion 模型**。

至此，多模态概述这一讲就结束了。
