# 去重：从精确去重到 MinHash 与 LSH

## 重复的两副面孔

到这一步，我们已经把数据过滤到"我们认为的高质量"了。但数据里往往还是有重复。重复分**两类**：

- **精确重复（exact duplicates）**：比如镜像站（mirror sites）——镜像存在的意义就是重复，而爬虫有时不够聪明、意识不到"这个镜像就是那个镜像"，于是把许多站点都爬一遍，就拿到了完全相同的内容；再比如 **GitHub fork**——即使你 fork 后做了修改，通常也只改了少数几个文件，仓库的 99% 可能还是一样的。所以重复其实相当普遍。
- **近重复（near duplicates）**：不是镜像或衍生，但恰好是"同一段文本差几个 token"。它们多半来自复制粘贴，或者源自某个共同的源头。

### 近重复的常见例子

- **服务条款与许可证（terms of service and licenses）**：MIT 许可证大概在无数网站上出现。很多时候它就是一字不差的拷贝——除非有人复制时打了个字——但许可证所在页面的其他部分可能完全不同。
- **网页的页头与页脚**：我们之前说过很多网站的页头页脚是相同的模板，那也是重复。
- **排版差异**：LM1B（十亿词基准）里就有这种文章——一个版本带逗号、一个版本不带逗号，谁也不知道为什么。
- **模板化内容**：有些低质量内容本质上像广告，被人做成模板，把 "Canada" 替换成 "USA" 就又是一篇。如果你在训练时只是在反复看同一内容的"换实体版本"，那你的 GPU 就在被浪费。

还有一个更极端的案例——这正是**应该亲自看数据**的理由。有人审计 C4 数据集时发现，一条**产品描述在数据集中出现了 61,036 次**。追查回去非常离奇：那是某个防毒面具的商品描述，莫名其妙在 Common Crawl 里出现了 61,000 多次。网络就是这么怪。

## 为什么要去重

- **训练更高效**：去重能在不损失什么信息的前提下缩小数据集——毕竟只是拿掉重复；
- **避免记忆化（memorization）**：论文《Deduplicating Training Data Makes Language Models Better》专门讨论过。如果某段受版权保护的内容被大量重复，训练它就会导致模型把它记忆下来；记忆化还涉及隐私问题。但 Percy 认为最主要的动机其实是下一条；
- **不浪费 flops**，以及**去污染（decontamination）**——这个可能更重要：你得确保**测试集不在训练集里**。去重与去污染是同一类事情。

## 设计空间与关键挑战

做去重前要想清楚三件事：

1. **条目（item）是什么**：在句子、段落还是文档粒度上去重？
2. **如何判定匹配**：精确匹配？是否存在公共子条目？公共子条目的比例（近重复）？
3. **找到重复之后做什么**：把重复全部删掉，还是删到只剩一个？

**关键的算法挑战**在于：去重本质上是"**条目对条目的比较**"。过滤不一样——过滤是问"这个条目本身好不好"，可以完全并行、是线性时间；而去重你不能做那个 $O(n^2)$ 的"全对全"比较，**需要线性时间的算法**才能规模化到 web 规模。去重文献里通常靠**哈希函数（hash functions）**来绕开这一点。下面我们把这个思路完整地发展一遍——这些是很漂亮的想法，来自算法社区。

## 哈希函数：快的与安全的

大家都认识哈希函数：它把某种值（比如字符串）映射成另一个值（整数或字符串）。哈希值远小于原条目；**哈希碰撞（hash collision）**就是两个不同条目映射到同一个哈希值，即 $h(x) = h(y)$ 而 $x \neq y$。

哈希函数有个效率与抗碰撞性的权衡：

- **加密哈希（cryptographic hash）**，如 **SHA-256**：抗碰撞，但慢——比特币用的就是它；
- **快速哈希**，如 **DJB2、MurmurHash、CityHash**：不抗碰撞，但很快——哈希表用的就是它们。

本讲用 **MurmurHash**。比如：

```python
import mmh3

h = mmh3.hash("hello")   # 把字符串哈希成一个整数
```

## 精确去重：概念上最简单

精确去重概念上非常朴素：拿字符串做精确匹配，重复的删到只剩一个。用代码表达就是——把条目按哈希分组，每组留一个：

```python
import itertools
import mmh3

# 原始条目
items = ["Hello!", "hello", "hello there", "hello", "hi", "bye"]

# 按哈希值分组：具有相同哈希的条目归为一组
hash_items = itertools.groupby(sorted(items, key=mmh3.hash), key=mmh3.hash)

# 每组保留一个条目
deduped_items = [next(group) for h, group in hash_items]
```

精确去重的**优点**：简单、语义清晰、精度高（precision 高）。**缺点**：处理不了近重复。注意这段代码是按 **MapReduce** 的风格写的——很容易并行、容易规模化。**C4**（T5 论文处理 Common Crawl 时）做的正是精确去重：它的**条目是"3 句 span"**，做精确匹配，删到只剩一个。有个值得注意的怪异之处：如果你仔细想想就会发现，当两个文档共有某段 3 句 span 时，你等于从文档中间**硬生生抠掉三句话**——这会破坏文档的连贯性——但他们当时就是这么做的。

## 近重复：先定义相似度

要做近重复去重，先得定义"近似匹配"是什么意思。为此我们引入一个标准概念——**Jaccard 相似度（Jaccard similarity）**。两个集合的 Jaccard 相似度定义为**交集大小除以并集大小**：

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

比如 $A = \{1, 2, 3, 4\}$、$B = \{1, 2, 3, 5\}$：交集是 $\{1, 2, 3\}$（3 个元素），并集是 $\{1, 2, 3, 4, 5\}$（5 个元素），所以

$$J(A, B) = \frac{3}{5} = 0.6$$

Jaccard 是 0 到 1 之间的数：0 表示不相交，1 表示完全相同。于是我们可以定义：**两个文档是近重复，当且仅当它们的 Jaccard 相似度 ≥ 某个阈值**（比如 0.99）。现在的问题是：**如何在线性时间内找出近重复？**

## MinHash：把碰撞概率校准到 Jaccard

好消息是这是一个已被解决的算法问题，答案是用 **MinHash**。不过 MinHash 只是第一步，不是最终答案。

**MinHash** 是一个随机哈希函数，使得**碰撞概率恰好等于 Jaccard 相似度**：

$$Pr[h(A) = h(B)] = J(A, B)$$

这是一个很漂亮的性质：哈希让事情变成线性时间，Jaccard 是我们想要的度量，而 MinHash 把这两者（在期望意义上）接起来了。有意思的是：通常我们设计哈希函数是希望**不同元素映射到不同的值、尽量别碰撞**；但这里我们**故意想要碰撞**——不是任意的碰撞，而是**把碰撞概率和相似度对齐**：相似的东西要比不相似的东西更容易碰撞。

MinHash 的定义非常简单：把集合里的每个元素都哈希一遍，**取最小值**：

```python
def minhash(S: set[str], seed: int):
    return min(mmh3.hash(x, seed) for x in S)
```

取 min 还是取 max 其实无所谓，这只是个"打破平局"的方式。

### 为什么碰撞概率等于 Jaccard：特征矩阵 + 随机排列

要理解为什么，想象下面的**特征矩阵（characteristic matrix）**表示：行是元素，列是集合（1 表示该元素在集合里）：

| 元素 | $A$ | $B$ |
|:---:|:---:|:---:|
| 1 | 1 | 1 |
| 2 | 1 | 1 |
| 3 | 1 | 1 |
| 4 | 1 | 0 |
| 5 | 0 | 1 |

随机哈希函数做的事情，相当于在元素上**诱导一个随机排列**——比如排列可能是 $4, 3, 1, 5, 2$ 或别的什么。然后看**这个排列下 $A$ 的第一个元素**和 **$B$ 的第一个元素**分别是什么。关键观察是：**每个元素等可能成为"第一个"**（因为排列是均匀随机的，而"取最小"就是在选某个排列下的第一个）。

- 如果排列把 $\{1, 2, 3\}$ 中的某个元素放在最前面，那么 $A$ 的第一个元素 = $B$ 的第一个元素——**碰撞**；
- 如果排列把 $\{4, 5\}$ 中的某个元素放在最前面，那么 $A$ 的第一个元素 ≠ $B$ 的第一个元素——**不碰撞**。

所以碰撞概率恰好是"第一个元素落在 $\{1,2,3\}$ 里"的概率，也就是 $\frac{3}{5} = J(A, B)$。这就是 MinHash 性质成立的证明：**在随机哈希函数的期望上，碰撞概率等于我们想要的相似度度量**。

### 用代码验证

我们可以直接用代码验证这个性质：生成 100 个随机哈希函数（每个用一个 seed），统计 minhash 相等的比例，它应该近似等于 Jaccard：

```python
n = 100  # 生成 100 个随机哈希函数
matches = [minhash(A, seed) == minhash(B, seed) for seed in range(n)]
estimated_jaccard = len([m for m in matches if m]) / len(matches)

assert abs(estimated_jaccard - jaccard) < 0.01   # 误差应该小于 0.01
```

MinHash 的关键在于：**我们不用做 O(n²) 的全对全比较**。可以单独计算 $A$ 的 minhash、$B$ 的 minhash、以及任何其他集合的 minhash，然后直接找相等的——这就能线性时间近似。

## 但一次碰撞还不够：LSH 把概率锐化成相变

现在我们可以哈希条目了，但还没完：**一次碰撞并不能告诉你 Jaccard 是否大于某个阈值**。我们想要的是"找到 $A$ 和 $B$ 使得 $J(A,B) > 0.99$"；而 MinHash 只告诉我们"两个东西碰撞的概率等于 Jaccard"。相似的条目确实碰撞得更频繁，但**这非常随机**——方差很大，单次碰撞给不了可靠信息。

于是进入下一步：**局部敏感哈希（Locality Sensitive Hashing，LSH）**。这是理论计算机科学里的经典想法。我们的目标是：**当 $J(A,B)$ 大于某个阈值时，让 $A$ 和 $B$ 碰撞**；也就是说，要把碰撞概率从"等于 Jaccard"**锐化**成一种相变（phase transition）——低于阈值几乎不碰撞，高于阈值几乎必碰撞。

做法是用**更多（相互独立的）哈希函数**。把 $n$ 个哈希函数分成 $b$ 个 band，每个 band 里有 $r$ 个哈希函数（$n = b \cdot r$）。例如 $n = 12$ 个哈希函数、$b = 3$ 个 band、每个 band $r = 4$ 个：

```text
h1 h2 h3 h4  |  h5 h6 h7 h8  |  h9 h10 h11 h12
```

**关键定义**：我们说 $A$ 和 $B$ 碰撞，当且仅当**存在某个 band，其中所有的 $r$ 个哈希函数都返回相同的值**。也就是说，要么第 5、6、7、8 个哈希函数对 $A$ 和 $B$ 全部一致（第一个 band 触发），要么第 9、10、11、12 个全部一致，等等；不必所有哈希函数都一致。正是这种"**与-或（and-or）结构**"在承担锐化的重任——band 内部是"与"（全中才算），band 之间是"或"（中一个就行）。

### 碰撞概率的推导

给定 Jaccard 相似度 $s = J(A,B)$，$A$ 和 $B$ 碰撞的概率是多少？分两步算：

1. **固定一个 band 匹配的概率**：该 band 有 $r$ 个哈希函数，每个独立地以概率 $s$ 碰撞（MinHash 性质），全部碰撞（"与"）的概率是

$$Pr[\text{一个固定 band 匹配}] = s^r$$

2. **存在某个 band 匹配的概率**：$b$ 个 band 都**不**匹配的概率是 $(1 - s^r)^b$（"或"的对偶），所以至少一个匹配的概率是

$$P_{collide}(s) = 1 - (1 - s^r)^b$$

用代码表达：

```python
def get_prob_collision(sim, b, r):
    prob_match = sim ** r                        # 固定 band 匹配的概率
    prob_collision = 1 - (1 - prob_match) ** b   # 存在某个 band 匹配的概率
    return prob_collision
```

**例子**：$s = 0.8$，$b = 5$，$r = 10$。固定 band 匹配概率 $0.8^{10} \approx 0.107$——一个 band 全中的概率一般很低，随 $r$ 指数下降；而碰撞概率 $1 - (1-0.107)^{5} \approx 0.43$——因为给了 $b$ 次"尝试"的机会，碰撞概率明显更高。

把 $P_{collide}(s)$ 对 $s$ 画出来，得到一条 **S 形曲线**：$s = 0$ 时概率是 0，$s = 1$ 时概率是 1，中间是一个陡峭的转变。这正是我们想要的"锐化"：相似度低于某个阈值时碰撞概率尽量低，高于阈值时尽量高——像一个**相变**。

### 调参数：增大 r 变尖锐右移，增大 b 变平左移

看几个具体数字。$s$ 从 0.7 取到 0.98，先看 $b = 10, r = 10$：碰撞概率大约从 **0.25**（$s=0.7$ 时 $1-(1-0.7^{10})^{10} \approx 0.25$）一路升到 **1**（$s=0.98$ 时 $0.98^{10} \approx 0.82$，再取 $1-(1-0.82)^{10} \approx 1$）。这个范围"不算差"：你可以在中间设一个阈值，低于阈值的虽然也可能碰撞（假阳性），但可以事后把它们过滤掉；高于阈值的则基本都被保留。

- **增大 $r$**（band 内的哈希函数个数）：指数更大，固定 band 全中的概率掉得更快，于是**相变更尖锐、曲线整体右移**——更难匹配。同样的 $s=0.7$，$b=10, r=20$ 时碰撞概率从 0.25 掉到约 **0.008**：相似度不高的东西几乎不会再碰撞了。
- **增大 $b$**（band 个数）：band 越多，"存在某个 band 匹配"的机会越大，**曲线左移**——更容易匹配。比如 $s=0.9$ 时，$b=10, r=20$ 的碰撞概率约 0.72，换成 $b=20, r=20$ 就到约 0.92。

所以**增大 $b$ 和 $r$ 可以把相变调到任意尖锐**——但代价是更贵（要算更多哈希、存更多签名）。

### 真实世界设置：相变点与常数中心

在一个真实设置（论文《Deduplicating Training Data Makes Language Models Better》）里，他们用了 **$b = 20$ 个 band、每个 band $r = 450$ 个哈希函数**。相变发生在

$$s = \left(\frac{1}{b}\right)^{1/r}$$

如果你想按"$Jaccard > 0.9$"来过滤，就把 $b$、$r$ 设置成让这个表达式等于 0.9；再用增大 $b$、$r$ 来把相变调尖锐。有趣的是相变的中心是一个常数：在阈值处，固定 band 匹配的概率是 $\frac{1}{b}$；此时碰撞概率为

$$1 - \left(1 - \frac{1}{b}\right)^b \approx 1 - \frac{1}{e} \approx 0.64$$

也就是说，无论 $b$ 多大，**相变中心的碰撞概率都约等于 $1 - 1/e \approx 0.64$**——低于它的随 $b$、$r$ 增大趋于 0，高于它的趋于 1。这就是相变的形状。

这套方法叫 **MinHash LSH**：LSH 对任何哈希函数都成立（它本来就是一般化的框架），而语言模型数据的去重之所以用 MinHash，是因为它恰好近似 Jaccard——这正是我们需要的度量。

## 别忘了：跨整个数据集去重

去重还有一个注意事项：后面我们还会看到许多数据集陆续发布，重复可能发生在**数据集内部**；但通常你**必须跨整个数据集做去重**，因为数据集之间常常是冗余的。有时候大家没有这么做——但应该做。
