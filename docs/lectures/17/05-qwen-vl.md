# Qwen-VL 系列：从 Qwen-VL 到 Qwen3-VL

## Qwen-VL（2023）：交叉注意力适配器

Qwen 团队从 **2023 年**就开始训练多模态模型，第一个版本是 **Qwen-VL**。希望这一部分能讲得快一点——因为你大概已经看出模式了。

**架构**：

- **视觉编码器**：**OpenCLIP** 的 ViT（14×14 patch）——还记得 OpenCLIP 是 CLIP 的开源复现吧，所以本质上还是 CLIP 编码器；
- **适配器（adaptor）**：**一层交叉注意力（cross-attention）**，融入 **2D 位置编码**，并**映射到固定的 256 长度**。这个"固定长度"显然不够动态——不过在那个时间点，视觉编码器本身也不是动态的，所以无妨；
- **特殊 token**：他们引入了 `<img>`（图像标签）、`<box>`（边界框标签）、`<ref>`（描述标签）等特殊 token。幻灯片是 HTML 格式的，所以渲染出来偶尔会出点小问题。

**训练**：和 LLaVA 一样分**三阶段**：

1. **第一阶段（他们叫"预训练"，但并非从零预训练）**：**大规模、低质量数据**。**冻结语言模型**，训练**视觉编码器和适配器**。使用的数据量级在 14 亿（1.4B）条左右；
2. **第二阶段**：**更高质量、任务化的数据**——都是些"老面孔"：各种 VQA（视觉问答）数据集、图表问答（chart question answering）等等。这个阶段**训练所有参数**，并且**提高分辨率**；
3. **第三阶段**：**指令微调（instruction tuning）数据**。**冻结视觉编码器**，训练**适配器和语言模型**。

![Qwen-VL 的三阶段训练总览](/lectures/17/qwen-vl-stages.png)

![Qwen-VL 第一阶段：冻结语言模型，训练视觉编码器与适配器](/lectures/17/qwen-vl-stage1.png)

![Qwen-VL 第二阶段：高质量任务数据、提高分辨率，训练全部参数](/lectures/17/qwen-vl-stage2.png)

**能力示例**：因为这是 Qwen，很多例子是**中文**的。他们有兴趣让视觉模型"有时兼任语言模型"——语言模型能写代码，视觉模型最好也擅长代码。比如给一张蜘蛛侠大战浩克的图像，模型能**输出边界框**（注意：它输出的是边界框坐标，不是图像）；还能做 **OCR**、做图像**比较**等等。

![Qwen-VL 的能力示例：中文图文理解、边界框定位、OCR、图像比较](/lectures/17/qwen-vl-examples.png)

## Qwen2-VL（2024）：动态分辨率与 MRoPE

**Qwen2-VL** 又是一次升级。新想法主要有两个：更大的视觉编码器，以及**动态分辨率**。回想从 LLaVA 到 LLaVA OneVision 时大家意识到的事：**必须处理不同尺寸的图像**；而一旦要处理视频，就更清楚了——你**必然需要某种动态分辨率**。

于是：一张大图可能被映射成 **11,000 个 token**，一张小图（比如一个公式的截图）可能只有 **8 个 token**，诸如此类。

![Qwen2-VL 的架构：更大的视觉编码器，动态分辨率让不同尺寸图像映射为不同数量的 token](/lectures/17/qwen2-vl-architecture.png)

**怎么做？** 与 AnyRes 是同一个思路：每个 **224×224** 的窗口用 **ViT/14** 编码（起点是 OpenCLIP 的 ViT，然后会被微调）；为了压缩上下文长度，**每 2×2 压缩成一个 token**，最终一个窗口大约产生 **66 个 token**。视频方面：**每秒采样 2 帧**，token 上限 **16,384（16K）**。

**MRoPE（Multimodal Rotary Position Embedding，多模态旋转位置编码）**——这是对第二节那个"位置嵌入"问题的正面回答。回忆 **RoPE**：它的嵌入设计使得**两个向量的内积只取决于它们之间的距离**，一维情形下"距离"就是相隔的 token 数。多维版本是同一件事，只是变成了 **3D**：有**高度（height）、宽度（width）、时间**（time）三个轴。于是每个位置 / 每个 patch 都是一个由坐标定义的三元组 $(t, h, w)$。计算 MRoPE 的方式很直接：**对每个维度分别计算 RoPE，然后拼接起来**。

![Qwen2-VL 的 MRoPE：把（时间，高度，宽度）三个轴分别做 RoPE 再拼接](/lectures/17/qwen2-vl-mrope.png)

这个想法相当直白。不过后面到 Qwen3 我们会看到，它其实**有点次优**。

**初始化与训练**：语言模型用 **Qwen2** 初始化，视觉编码器来自 **DFN**。训练仍然三个阶段，和 Qwen-VL 类似：第一阶段只训练**视觉编码器**；第二阶段训练**全部参数**；第三阶段在**指令遵循（instruction following）数据**上训练**语言模型**。

![Qwen2-VL 的能力：视频理解、数学、代码、函数调用等](/lectures/17/qwen2-vl-capabilities.png)

最终展示了一堆能力：视频理解、数学、代码、函数调用等等。

## Qwen3-VL（2025）：SOTA 的打磨

**Qwen3-VL** 是去年（2025 年）的 Qwen3-VL 技术报告。大结构图还是那一张，改动不算"结构性大改"，但大概率**实实在在地提升了模型质量**。几个关键变化：

**语言模型**：用 **Qwen-3** 系列（dense 和 MoE 模型，最大到 **235B-A22B**）。Qwen-3 本身极其出色，这直接抬高了最终模型的质量。另一个投入点是**长上下文理解**：上下文长度最高 **256K**——处理长视频时这真的非常重要。

**视觉编码器**：改用 **SigLIP-2**——SigLIP 的改进版，架构完全相同，设计上**向后兼容**。

**改进的 MRoPE（交错式）**：之前的 MRoPE 把三个轴（时间、宽度、高度）**按块分配**：先分一整块给时间、再一整块给宽度、再一整块给高度。而回忆一下 RoPE 的性质——**每一个分量代表一个不同的频率**。按块分配就意味着"所有时间维度都是低频、所有高度维度都是高频"之类的情况。于是他们把轴**交错**开，让**所有轴都同时暴露在低频频带和高频频带**里：

$$
[\;t\;w\;h\;t\;w\;h\;t\;w\;h\;t\;w\;h\;\dots]
\quad\text{而不是}\quad
[\;t\;t\;t\;t\;w\;w\;w\;w\;h\;h\;h\;h\;\dots]
$$

**显式视频时间戳**：以前时间戳是"隐含"在位置编码里的——视频的每一帧因为位置不同，天然就有"时间"的概念。现在他们**把时间做成了显式的 token**：比如"0 秒"就是一个专门的 token。这样做想必是有帮助的，因为模型可以**直接引用**时间——比如"两秒之后发生了什么"。

**平方根归一化的逐 token 损失（square-root-normalized per-token loss）**：视频样本很长、单图样本很短。正常的做法是每个 token 一视同仁——那视频样本就会**主导**训练。细节他们没讲清楚，但 Tatsu 的理解是：**把每个样本的损失按样本长度的平方根归一化**，从而降低超长样本（主要是视频）的影响。

**适配器：DeepStack**：还记得适配器从 LLaVA 的线性投影、到 MLP、到交叉注意力的演进。**DeepStack**（一篇来自 DeepSeek 团队的论文，被 Qwen 用在这里）更精致：视觉编码器已经算出了一整叠视觉嵌入，DeepStack 的做法是**把这些视觉嵌入直接加进语言模型的残差流（residual stream）**——在**多个层**上把视觉信息注入语言模型。这比"视觉编码器是个黑盒、只输出一串向量"要**更深地融合**。

![Qwen3-VL 的总览图](/lectures/17/qwen3-vl.png)

![Qwen3-VL 的预训练：四个阶段（先训适配器，再分别在 8K / 32K / 256K 长度上训练全部参数）](/lectures/17/qwen3-vl-pretraining.png)

**训练**：分成两大阶段。**预训练有 4 个子阶段**、**后训练有 3 个子阶段**——可以看到这套流水线已经相当复杂了。预训练先训练**适配器**（和之前所有模型一样），然后三个子阶段在**越来越长的序列**上训练：**8K → 32K → 256K**，大部分 token 都在第二、三子阶段。后训练则是在**长思维链（chain-of-thought）数据上做 SFT**、**知识蒸馏（knowledge distillation）**、再做一些**强化学习（RL）**。到这个份上，它已经更像一篇"系统论文"了——Tatsu 只挑了核心新想法讲，实际细节多得很。

**结果**：最终模型相当能打。对比 Gemini、GPT-5、Opus 4.1 这些闭源模型，表里**加粗的是该行最优**——Qwen 在这些基准上确实非常强。

![Qwen3-VL 的结果：与 Gemini、GPT-5、Opus 4.1 等闭源模型对比，加粗为每行最优](/lectures/17/qwen3-vl-results.png)

## 课堂问答

> **课堂问答一：视频生成呢？模型怎么知道该输出视频还是文本？**
>
> （同学：这些模型怎么处理视频生成？它怎么决定该生成视频还是文本？）
>
> **Tatsu**：首先，这些模型**不生成视频、也不生成图像**——所有多模态的部分都在**输入**一侧，它们**永远在生成文本**。而且在大多数阶段（除了 RL）你都在**逐 token 监督**每一个 token：这里没有"LLM 当裁判"来评判描述质量，基本就是"数据里有什么就学什么"。到了 RL 阶段，你才能通过不同的奖励去玩出一些花样。

> **课堂问答二：从系统角度看，训练多模态模型比训练纯语言模型更难吗？**
>
> （同学：从系统（systems）角度看，训练多模态模型是不是比纯语言模型难？感觉图像和视频的 token 更多、数据更大……）
>
> **Tatsu**：两个问题合在一起回答。其一，训练多模态模型**当然不会更容易**。你提到的数据规模就是原因之一：视频数据光是**加载**都可能很夸张——我们在讲语言模型时几乎没怎么讨论数据加载，因为文本数据加载非常便宜；而多模态就必须认真考虑**数据加载与计算异步进行**这一类问题。其二，你提到的 token 数量：图像和视频（尤其是视频）确实贡献更多 token——这正是前面那种**归一化**（平方根归一化）存在的原因：避免给视频过多权重。你不喜欢某个模态占比大，**随时可以降权**——我们两三周前讲**数据混合**（data mixture）时就说过，你总能按任何你觉得合理的比例去加权。而且世界上文本 token 也很多：总体上看，我不认为多模态 token 的数量会**远超**文本 token——模型都是在上万亿（tens of trillions）token 上训练的。

> **课堂问答三：对齐阶段怎么知道语言模型"该说什么语言"？对齐预算怎么定？**
>
> （同学：做这种对齐（alignment）的时候，模型怎么知道语言模型预训练时的行为？训练量怎么确定？）
>
> **Tatsu**：这个语言模型**必须是预训练过的**——不然对齐就没有意义。所以做法是：**冻结语言模型，只训练适配器**，把给定的视觉编码器和给定的语言模型接起来。至于训练量，就是**选一个 token 预算**（比如 670 亿 token）直接训练，**不存在什么自适应的阈值**。

> **课堂问答四：视觉编码器的参数量为什么远小于语言模型？**
>
> （同学：我注意到视觉编码器的参数量好像比语言模型小很多，为什么？）
>
> **Tatsu**：是的，总体上视觉编码器的参数要**小得多**。原因是视觉编码器在某种意义上做的是**非常局部的操作**：它只看一个 patch，patch 很小，它只需要"理解 patch 本身"——**没有多少知识、也不做推理**。模型的大部分能力仍然住在语言模型里。举个例子，LLaVA 的规模：语言模型约 7B 参数，投影器要小得多，ViT 一般**不到 10 亿参数**。大体上就是因为视觉编码器干的是比较局部的活。

## 小结：Qwen 系列的模式

Qwen3-VL 是本讲讲到的**最后一个视觉语言模型**。从 Qwen-VL 到 Qwen2-VL 再到 Qwen3-VL，很多改动是**缩放、整理更多数据集、发现必须处理长上下文、打磨图像处理**——整体框架始终没变。有一点值得注意：**后期 Qwen 模型对数据和数据混合的细节公布得很少**。想要更多细节，可以去看 LLaVA 论文，或者 **AI2 的 Molmo 论文**（Tatsu 说这讲没来得及讲，但那里有更多数据细节）。
