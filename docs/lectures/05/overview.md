# 开场与动机：为什么是 GPU、为什么现在

欢迎来到第五讲。从这一讲开始，课程进入**系统（systems）部分**。Tatsu 开场说，前两讲都在做神经网络相关的内容，现在要开始接触 GPU 与推理了。系统这部分在他看来是整个技术栈里"最讲得通"的一块——你可以把每一个环节都推理出来，每一步都有合乎逻辑的步骤通向结果，因此它**不同于且相当有满足感**。但另一方面，第一次接触 GPU 的时候，它又会让你觉得像"魔法"，像一台非常奇怪的设备。Tatsu 现场做了个小调查：有多少人上过某种形式的 GPU 编程课？大约只有四分之一，甚至更少。所以这一讲的职责，就是把这层"魔法"拆开。

深度神经网络让人觉得像魔法，GPU 有时候也一样。人们有时会甩给你一张这样的图：横轴是矩阵乘法的维度，纵轴是吞吐量（每秒处理的元素数）。你可能会想：**矩阵越大、工作量越多，吞吐量不是应该越高吗？** 但图上布满了奇怪的模式——在某些尺寸上，矩阵乘法比别的尺寸慢得多，甚至加一维就"断崖式"下跌。Tatsu 对本讲的承诺是：

> 到本讲结束时，你会理解这张图是什么，以及它为什么长成这个样子。

理解 GPU 还有更实际的理由：即使你不是系统方向的人（大概多数同学都不是），只要你在考虑架构、或者一般性地推理一个模型的行为，你就需要理解你的模型将要**在什么样的硬件模型上执行**，才能设计出有效的模型。回想 Percy 的第一讲：规模化（scaling）的一大重点，是确保你**有效地利用资源**；不理解系统，你就永远无法高效地使用手上的算力。顺带一提，Tatsu 自嘲道："我并不是系统方向的人，惊喜吧。"所以他在开讲前，先指给大家几份他认为非常好、也为他备课所用过的资源：

- **Horace He** 的博客与解说，讲 GPU 如何工作，非常出色；
- 爱好者社区 **CUDA Mode**（课上一名同学纠正：他们已经改名成 **GPU Mode** 了)，热衷于讨论 GPU 与 CUDA kernel;
- 谷歌团队写的 **TPU 书**，现在也变成了一本 GPU 书——Tatsu 称之为"真的不可思议的资源"，书里还有练习题，而本课程的作业里会出现与那些练习很像的内容，算是给大家的预习。

## 本讲的三部分结构

这一讲分成三个部分：

1. **GPU 深入（Part 1: GPUs in depth）**——宽泛的入门材料：GPU 的硬件模型、编程模型大致如何工作。GPU 是一种"外来设备"，这一部分的目标是让大家在哲学层面理解它与 CPU 的区别；
2. **理解 GPU 性能（Part 2: Understanding GPU performance）**——六个重要的加速技巧（tricks），它们是操纵代码、让它在 GPU 上高效运行的积木；
3. **把一切串起来：拆解 FlashAttention(Part 3: Putting it together)**——胜利一圈（victory lap）。到这一步，我们拥有了理解自己"重新发明"FlashAttention 所需的全部组件，也能理解它每一个组成部分为什么是这样。

## 算力是这门课的"货币"

虽然我们还没正式讲到 scaling，但从 Percy 的介绍性讲座、以及一般性的语言建模常识出发，我们已经知道：**手上的算力越多，得到的语言模型就越好**。这就是我们赖以运作的"货币"。因此，更快的硬件、更好的利用率、更多的芯片与更好的并行化——所有这些都能推动进步。某种意义上，过去几年的游戏是"如何在训练模型时调动更多算力"；而最近一年左右，重点变成了"如何在**推理**（inference）这些模型时调动更多算力"。算力极其重要，而系统正是其中的一部分。

## 旧路的终结：Dennard scaling 的枯竭

如果把时间拨回 1990 年代，当时让计算机变快的方法非常直接：一个 CPU 串行地执行指令，我们让这些指令跑得越来越快。这种"晶体管变小、时钟频率变快"的扩展方式叫 **Dennard scaling（丹纳德缩放)**，它在很长一段时间里都成立——大约到 2000 年代，这种扩展就"见顶"了。

有一个很有意思的题外话：晶体管的数量当然还在继续增加，但**晶体管变小并不必然意味着晶体管变快**——它们并不会跑在更高的时钟频率上。到一定程度之后，你会因为一些根本的物理原因，不再从越来越小的晶体管中获益。所以，"让时钟更快、让指令执行更快"这条老路走不通了。

## 新的道路：并行扩展与 GPU

那么，在无法通过"频率意义"上更快来让 LLM 继续扩展的世界里，我们该怎么办？答案就是 **GPU**——或者说，广义上的**并行扩展（parallel scaling）**。Percy 会在下一讲讲更进阶的话题，之后的讲次会讲并行化；**并行化与 GPU 属于同一个范式**：不再串行地把单个时钟越做越快，而是**水平扩展**——让更多的东西并行执行你的指令。这就是 GPU 的故事。

## CPU 与 GPU 的哲学差异：延迟 vs 吞吐

上过 GPU 的同学已经知道这些了，但对其他人来说，理解两者的"哲学"差异非常重要。

**CPU 为快速的串行执行而设计**。它要处理复杂的分支逻辑、复杂条件、复杂控制流。因此，CPU 一般拥有**很大的控制单元（control unit）**，以及**少量 ALU**（能做数学或其他运算）。它的目标是尽快跑完：**从拿到指令到完成指令之间的延迟（latency）要非常非常短**。这是 CPU 的设计哲学。

**GPU 则完全围绕吞吐量（throughput）展开**。右图是对这两种哲学差异的一个绝妙图解：在 GPU 上，你派发一个任务，它可能要很久才完成；你处理完一个任务，停下来，去做另一个任务，再回来……但总体而言，即使单个任务完成得慢，**所有任务加在一起的聚合吞吐量（aggregate throughput）非常高**。支撑这一点的是**海量轻量级核心**:GPU 芯片里塞进了成百上千个计算单元，它们全部可以并行执行。

这是一种与 CPU 截然不同的编程与思考模式。下面的分节就从"去神秘化"开始，把 GPU 的硬件解剖开来看清楚。
