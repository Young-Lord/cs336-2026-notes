# 另一种替代方案：稀疏注意力 DSA

线性时间注意力有着非常漂亮的复杂度理论味道，但它是解决长上下文问题的**一个**方向。Tatsu 说还要讲另一个注意力优化——它和线性注意力属于同一个"高效注意力（efficient attention）"家族，但走的是完全不同的路线：**稀疏注意力（sparse attention）**，具体来说就是 **DSA(DeepSeek Sparse Attention,DeepSeek 稀疏注意力)**。

## 思路：先挑出一小撮 token，再只对它们做注意力

普通的注意力对**所有** token 计算注意力。DSA 的做法是：**先用一个轻量级的 indexer（索引器）挑出一个 token 子集，再在这个小得多子集上做完整的注意力**。

机制本身很简单（至少前向是这样）：你照常得到 $Q$ 和 $K$，但接下来不是直接算全对全注意力，而是：

1. 把 $QK$ 内积送进 indexer;
2. indexer 对它们取 **ReLU**，再用一组**由前序 token 派生出来的权重**加权，得到每个位置的**激活值（activation）**;
3. 对这些激活值做 **Top-K 选择**——分数最高的 $K$ 个位置进入注意力计算；
4. 在选出的子集上做**你熟悉的、完整的注意力**，产生键值输出。

这么做的收益很直接：整个计算**非常稀疏**。只要 indexer 够轻量，下面那步"完整注意力"就可以在**很小的子集**上做——注意力成本被砍掉一大截。

## 关键事实：这不是线性时间，但常数因子极好

必须澄清一点：**DSA 并不是线性时间的**。indexer 依然要做全对全的 $QK$ 内积——为了知道"该选哪些"，它必须看遍所有东西，所以这一步还是 $O(n^2)$ 量级的，不存在什么巧妙的状态转移。那为什么还划算？因为：

- **indexer 可以做得非常便宜**：比如用**低精度**计算（他们论文里讨论过），或者把 $Q$、$K$ **进一步投影到更低维**只用于索引，或者把权重矩阵 $W$ 做得很小——"你可以想象很多技巧"。**indexer 的常数因子非常小**;
- **第二步虽然也是二次方，但作用在短得多的长度上**：因为做了 Top-K，子集大小 $K$ 是可控的——"这笔开销很大，但是小规模的大"。

于是这又回到了上一节反复强调的系统教训：**别太执着于"二次方 vs 不是二次方"，常数因子真的非常重要**。用低精度做完选择，再用全精度做精算——这个"选择用粗的、计算用细的"的分工，就是 DSA 的精华。

## 事后适配（post-hoc adaptation）：不需要从头预训练

另一个 DSA（以及 GLM）展示的关键性质是：**你不需要从头就用这套机制训练模型**。和 indexer 一起训练"可能相当烦人且复杂"，所以做法是：

1. 先照常**训练一个普通 transformer**（短上下文);
2. 到**长上下文扩展（long-context extension）阶段**，再把 indexer 插进去，让模型在**与预训练分离的扩展阶段**学会处理这套 indexer。

这样做的计算成本本身很轻——反正长上下文扩展这一阶段本来就要做，不如把"长上下文省钱"的机制在同一阶段一起装上。Tatsu 觉得，**能把这样一个看起来有点吓人的、非可微的 Top-K 对象"事后装上"而且真的能工作，是相当令人惊讶的**——不过下一个大主题（MoE）会告诉我们，也许不必对 Top-K 那么害怕。

## 证据：DeepSeek V3.2 与 GLM 5

**DeepSeek V3.2** 提出了 DSA，而它的效果相当好：在发布时**匹配当时其他前沿模型**（如 Claude 4.5 Sonnet、Gemini 3）。DeepSeek 还展示了一张漂亮的图：与没用稀疏注意力的上一代 DeepSeek 模型相比，**prefill（处理输入）和 decoding（生成）的扩展性都非常有利**——这很自然：如果你只对很小一个子集做注意力，注意力成本当然会大幅下降。

另一个正交的验证是 **GLM 5**——Tatsu 认为 GLM 5 是"现存最好的开源模型之一，没有之一"。它也采用了 DSA 路线，并且论文里有相当不错的消融：比如"DSA 带 warm-up""直接 DSA""完全不用 DSA"对比。核心结论是：**做完整的 DSA 训练，相比全注意力几乎不损失性能**——即使在 RNN 式架构很难搞定的**长上下文检索任务**上也是如此。

## 一个伏笔：Top-K 思想接下来是主角

DSA 这部分讲得不多，但它给后半讲埋下了一个伏笔：**"Top-K 选择"这个思想，正是 MoE 部分的核心**。从 DSA 到 H-Net（那是一个试图去掉 tokenizer 的工作)，这个套路会在很多地方出现——值得把它当成一个能识别的模式。

## 课堂问答：关于 DSA 的各种细节

### 问答：indexer 的复杂度是二次方吗？那两步都是二次方，收益从哪来？

（同学：indexer 的复杂度是多少？如果它要看遍所有东西，那后面那步也是二次方，我们到底省了什么？)

**Tatsu**:**indexer 是二次方的，没错。** 为了知道该选什么，它必须看遍所有东西；这里没有巧妙的"状态转移"，就是暴力的内积。但整个方案是一个"系统技巧（systems-y trick）":

- **indexer 本身做得非常轻**：低精度、低维投影、小权重矩阵，常数因子非常好；
- **第二步虽然也是二次方，但作用在短得多的上下文上**:Top-K 里的 $K$ 是你可以控制的。

所以这不是"消除了二次方"，而是"把二次方压在便宜的那一侧"。再次强调：**别把"二次方 vs 线性"看得太重，常数因子有时才是决定性的**。

### 问答：这是后训练的一部分吗？一般的流程是什么？

（同学：这也是 post-training 的一步吗？)

**Tatsu**:**是的**。我所熟悉的开源模型的标准流程一般是：**短上下文预训练 → 长上下文扩展（long-context extension，类似继续预训练）→ 后训练（post-training）**。因为出于算力等种种原因，大家不会从头就训练长上下文模型——先训一个短上下文的，再做长上下文扩展。DSA 的巧妙之处在于：这个第二阶段**反正要做**，何不把长上下文的省钱机制**在同一阶段一起装上**?

### 问答：DSA 里的 $K$ 和短上下文长度差不多吗？

（同学：这里的 $K$（选中的 token 数）和短上下文长度差不多吗？)

**Tatsu**:**对**，你会把 $K$ 选得**更接近短上下文的规模**，并且**给它一个上界**——不管输入多长，子集大小都被限制住。所以无论输入怎么变，后面那步注意力的规模都是可控的。

### 问答：去掉 softmax 会不会带来训练稳定性问题？

（同学：有没有关于"去掉 softmax"会不会引起上下文/训练稳定性问题的研究？)

**Tatsu**:**我没听说过这样的问题**。据我所知没有文献记载"线性注意力/去掉 softmax 导致大量不稳定"。如果说有什么方向，**softmax 往往才是麻烦的来源**（上一讲讲过：指数运算与除法是稳定性的两大雷区）。所以在我看来，去掉 softmax 反而会**改善**稳定性。

### 问答：未来更好的注意力机制会是什么样？

（同学：能不能简单说说，未来"更好的注意力机制"——比如因为低成本、低延迟——会长什么样？)

**Tatsu**：我没有什么很好的预测，这里给一个稍微有点"和稀泥"的回答。我认为未来大概会是**把所有技巧都混在一起**——就像现在架构已经很复杂一样，把所有这些成功配方都叠进去。另外有一个更高层的方向：**用后训练让模型自己管理上下文**——压缩（compaction）、检索（retrieval），这些都是在架构之上再叠加的一层。我预想的大量工作会是**这些不同层面的整合**。而至少在线性时间注意力这一支，我们已经看到它**高度收敛到 LSTM 式或线性注意力式的架构**，我不觉得这个趋势在短期内会改变。

### 问答：FP4 注意力可能吗？

（同学：你提到低精度注意力——那 FP4 注意力可能吗？)

**Tatsu**:**FP4 肯定可能**，而且我认为 indexer 的想法有一部分动机正是来自这类低精度考虑。它的主要缺点在于：**softmax 对精度很敏感**——小小的下溢、上溢都可能真的出问题。所以"用低精度做选择、之后用全精度精算"的思路很合理：这样值向量可以更精细地加权求和。至于**全注意力本身能不能做到 FP4 或更低精度**……我暂时不觉得有真正好的办法。

### 问答：相比 transformer，状态空间模型的缺点是什么？训练更复杂吗？

（同学：相比 transformer，状态空间模型的 downside 是什么？训练会不会更复杂？)

**Tatsu**：一定要有 downside，否则大家早就都去用了。我认为 downside 是**表达力（expressive power）**:softmax 注意力的全对全连接极其强大，而且**非常好训练**。想想历史：和 LSTM 相比，注意力当年最大的优势就是**硬件效率**——可以并行训练。而状态空间模型之所以能流行起来——尽管它们和 LSTM 很像、表达力也有类似的局限——正是因为我前面讲的**对偶性**：借助线性注意力那套，可以从 RNN 形式切换到**稠密矩阵乘形式**，从而拿到训练时的计算效率。所以"能不能并行训练"这个权衡被填平了，但另一个权衡还在：

> **状态空间模型必须把所有信息压缩进一个有限大小的状态里**。你的上下文长度要**相对于状态的大小**来看：如果状态大小等于上下文大小，那没问题，但你要付非常贵的成本。所以真正的问题是——**如果你想要一个很小的状态，就很难把大上下文里的所有信息都压进去**。也许有一天能做到没有权衡，但目前这就是权衡所在。

**训练本身并不更复杂**（得益于对偶性)，代价在表达力与信息压缩上。
