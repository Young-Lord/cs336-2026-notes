# 数值精度：从 fp32 到 fp4

## 内存由什么决定

tensor 占多少内存，由两件事决定：（i） **值的个数**；（ii） 每个值的**数据类型**。我们主要关心浮点数（float），但 tensor 也可以是整数等其它类型。本讲我们从 fp32 一路讲到 fp4，体会“降低精度 → 省内存 → 省时间”这条主线。

## fp32（单精度）

**fp32**（也叫 float32、单精度）有 32 位，拆解如下：

- **1 位符号位**（sign）；
- **8 位指数位**（exponent）：决定**动态范围**（能表示多大/多小的数）；
- **23 位尾数位**（mantissa / fraction）：决定**精度**（数值的细腻程度）。

![](/lectures/02/fp32.png)

“单精度（single precision）”这个名字来自科学计算时代：在那个年代，fp32 是默认的基线——别人给你一个 float，你就预期它至少是单精度；想要更高精度，就用双精度（double precision，即 fp64）。但**深度学习反着走**：连 fp32 都嫌多，因为我们做的计算并不像数值模拟那样需要高精度，可以“邋遢”一点。

### 一个 4×8 的 tensor 占多少内存？

PyTorch 里创建 tensor 的**默认类型就是 float32**，想要别的类型要显式声明：

```python
x = torch.zeros(4, 8)          # 默认 float32
assert x.dtype == torch.float32
assert x.numel() == 4 * 8
assert x.element_size() == 4   # float 占 4 字节
# 内存 = 4 * 8 * 4 = 128 字节
```

给一个量级感受：**GPT-3** 前馈层里**一个矩阵**就有 **2.3GB**（12288×4 行 × 12288 列的权重，乘上 4 字节/元素）。tensor 可以变得非常大，而这还远不是能想象到的极限。

## 降低精度的动机

我们希望减少存储，而**降低精度**可以一箭双雕：

- **省内存**：16 位比 32 位省一半；
- **省时间**：对 16 位数据做运算更快（大约快两倍，但不总是，视情况而定）。

还有一个不那么显然的点（后面会讲清楚）：**省内存本身也能省时间**——因为内存需要搬运，东西越小，搬运越快。

## fp16（半精度）

**fp16** 把位数砍一半：1 位符号 + **5 位指数** + 10 位尾数。每元素 2 字节，内存减半。

![](/lectures/02/fp16.png)

问题在于它的**动态范围很差**。试一下：

```python
x = torch.tensor([1e-8], dtype=torch.float16)
assert x == 0   # 下溢(underflow)!
```

$10^{-8}$ 这样的数在 fp16 里**直接变成 0**。大数也表示不了。原因就是指数只有 5 位（相比 fp32 的 8 位）。早年间用 fp16 训练的人会遇到**不稳定**：下溢、上溢、出现 NaN——相当麻烦。

## bf16(Brain Floating Point)

**bf16** 是 **Google Brain 在 2018 年**开发的，专门解决 fp16 的动态范围问题。关键观察是：**位数不变，但把尾数的位挪给指数**——从“不牺牲位数”这个意义上看，bf16 和 fp16 一样占 2 字节，但指数有 8 位：

- **动态范围与 fp32 相同**；
- **精度（分辨率）更差**——天下没有免费的午餐。

![](/lectures/02/bf16.png)

但事实证明，在很多深度学习应用里，这个取舍非常划算：

```python
x = torch.tensor([1e-8], dtype=torch.bfloat16)
assert x != 0   # 不会下溢!
```

我们希望动态范围足够大、不要上溢下溢；而深度学习里的数值本来就“粗糙”、带随机性，不需要那么高的分辨率。所以 bf16 是**甜点**。

### 对训练的含义

- 完全用 **fp32** 训练没问题——小模型直接这么干就行，不用操心。但每个 float 占 4 字节，内存吃紧；
- 用 **fp16** 训练太危险；
- **bf16** 是个甜点，不过即使是 bf16 也可能有点风险；
- 人们现在的常见做法是**混合精度训练（mixed precision）**。

## 混合精度训练

混合精度训练就是：一部分计算用一种精度，另一部分用另一种精度。一般规则是：

- **参数、激活、梯度**：用 16 位（bf16）；
- **优化器状态**：用 fp32（为什么，后面讲内存核算时会细说）。

PyTorch 有 **AMP(automatic mixed precision)** 库，它会自动帮你做这件事——在**安全**的时候把操作转成 bf16，不安全的时候保持 fp32：

```python
with torch.amp.autocast("cuda", dtype=torch.bfloat16):
    x = torch.zeros(4, 8)
```

比如 **matmul 一般是安全的**；而**指数运算（exp）这类操作会保持 fp32**。

## fp8

如果你还想更激进，可以走到 **fp8**。2022 年 fp8 被标准化，正是为机器学习工作负载设计的。fp8 有**两个变体**，取决于你更需要动态范围还是分辨率：

- **E4M3**：4 位指数 + 3 位尾数，范围 $[-448, 448]$（更细的精度）；
- **E5M2**：5 位指数 + 2 位尾数，范围 $[-57344, 57344]$（更大的动态范围）。

H100 支持 fp8，Transformer Engine 也支持。

![](/lectures/02/fp8-formats.png)

## fp4

最近甚至能走到 **fp4**。2025 年，NVIDIA 开发了 **nvfp4**，每个值只有 **4 位**。

4 位不是很多——Percy 说，所有能表示的值，一行就能写完（范围在 -6 到 6 之间）：

$$-6,\ -4,\ -3,\ -2,\ -1.5,\ -1,\ -0.5,\ 0,\ 0.5,\ 1,\ 1.5,\ 2,\ 3,\ 4,\ 6$$

如果只是朴素地用这十几个值，显然没法训练好模型。这里有个“小作弊”：**块（block）缩放**。每个块可以有自己的**缩放因子**，于是：

- 每个块内的值可以整体放大或缩小，实际能表示的动态范围**更大**；
- 但块内每个值**不能和它的邻居自由地分别变化**。

今年（2025 年）发布的 **Nemotron 3 Super** 就是用 FP4 训练的，Percy 觉得这相当酷。

注意：fp4 很多东西是在 **NVIDIA 软件栈内部**完成的——不是你创建个 tensor 指定 FP4 就行的，很多时候你甚至碰不到它。这一长段关于精度的“题外话”，是想让大家体会到精度背后有非常多讲究。

## 学生提问：块的缩放机制

**学生问**：当你有一个 block 的时候，是把整个 block 里所有值一起按同一个缩放因子缩放，对吗？

**Percy 答**：对。问题是关于“用最大值做缩放以获得更多精度”的机制。解释一下 block：假设有一个 block，块内所有值的**比值仍然保持在 FP4 的精度**，缩放只作用于**整个 block**——用同一个缩放因子把整个块放大或缩小。这样单个值实际得到的动态范围超过 4 位（因为缩放因子本身携带了一些位），但你不能让某个值跑得很高，同时它旁边的邻居值跑得很低。

**学生问**：能不能把 bf16 一路压到 1 位？

**Percy 答**：这里要区分**训练**和**推理**。很多低比特工作（我们后面会讲**量化（quantization）**）是：先用普通精度（比如 bf16）把模型**训练好**，再量化成 1 位或 2 位。而**直接训练一个 1 位语言模型**是另一回事——据他所知，还没有人训练出可信的 1 位语言模型，也许可能，但目前没人做到。

## 小结

- 内存 = 元素个数 × 每元素字节数；
- fp32(1+8+23)：默认、稳，但费内存；
- fp16(1+5+10)：内存减半，但动态范围差，$10^{-8}$ 就下溢为 0；
- bf16(1+8+7)：2018 Google Brain，内存同 fp16，动态范围同 fp32，精度稍差——深度学习的甜点；
- 混合精度：参数/激活/梯度用 bf16，优化器状态用 fp32，PyTorch AMP 自动处理；
- fp8（E4M3/E5M2）与 fp4（nvfp4，带块缩放）代表更低比特的前沿。
