# 引言与历史背景：缩放定律从何而来

欢迎回来。我们在系统领域待了两讲（并行、分布式训练），现在暂时离开系统，回到深度学习本身。接下来会有两讲（以及更后面的一讲进阶版）聚焦**缩放定律（scaling laws）**以及与之相邻的现象。今天这一讲是基础篇：一些经典的缩放定律工作、最基本的想法，以及缩放定律如何与你从机器学习入门课程里知道的东西（泛化界、样本复杂度）联系起来。后面的进阶版则会进入现代开源模型的技术报告、μP 之类的参数初始化，以及今年新加入的优化器内容，尽量贴近前沿。由于课程排期，下一讲先讲推理（inference），之后才回到缩放的进阶内容——你会在"缩放 → 推理 → 缩放"之间来回跳。

## 一万块 B200 的场景

故事是这样的：你的富豪朋友借给你**一万块 B200 用一个月**，请你训练一个很好的开源语言模型。基础设施团队你已经搭好了（那是作业二的内容），一份不错的预训练数据集也已准备就绪（那是作业四的内容），现在你要去训练一个大模型——但训练大模型充满了选择：

- 用哪种架构？宽一点还是深一点？多少个注意力头？用哪种非线性？
- 超参数怎么定？优化器选 Adam 还是 SGD？batch size 和 learning rate 呢？

![认真对待缩放：一万块 B200 的场景](/lectures/09/slide-02.png)

问题是，一次大规模训练可能要花费数百万美元，你绝对不希望在"该选什么"上面赌一把。这些选择里，有一部分你完全可以直接从文献里抄——上一讲讲架构时提到的那些被广泛采纳的最佳实践（best practices），你随手挑一些用就行，问题不大。但如果你真的想做**最前沿（frontier）**的模型、做出比现有最好模型更优的东西，你就不能只是抄别人的选择——抄别人的选择不可能让你超过 state of the art。你必须真正开始优化这些决策。那么，怎么认真地把"放大（scaling up）"这件事做好？

**缩放定律（scaling laws）**就是回答这个问题的强大工具，你甚至可以说它是一套范式（paradigm）。如果去跟大实验室里真正做缩放工作的人聊，你会发现它几乎是一种"生活方式"：他们真的相信缩放定律，这几乎成了一种信念——后面你会看到缩放定律为什么有时是个相当棘手的对象。概括地说，缩放定律是**简单的预测规则**：从小规模模型的行为与性能出发，把它外推到大规模行为。

朴素的训练思路是：我有大预算，那就在这些非常大的运行上做多轮训练、直接在大模型上调超参数——但这非常贵。缩放定律的思路正好相反：

> **把所有优化都放在小规模上做，再用一条简单规则把"小规模行为"外推到"大规模行为"。** 只要小规模与大规模之间被一些非常简单、稳健的规律（regularities）连接起来，你就有信心用这套"先小后大"的方式来优化系统。

今天整讲讲的都是这种**工程视角的缩放定律**。

## 缩放定律不是新东西：与经典机器学习的联系

缩放定律很有意思的一点是：它既是最新的范式（今天很多模型就是这样被设计和思考的），又与非常经典的思想紧密相连。如果你是机器学习理论方向的人，你在某些地方会感到非常亲切——缩放定律在某种意义上就是**经验的样本复杂度（empirical sample complexity）**。

从理论的角度，"我的模型会表现得多好？"这个问题有一个经典答案：**泛化界（generalization bound）**。对某个有限的假设类 $\mathcal{H}$，你有一个误差上界，说"我的误差至多比训练集上的表现差这么多"；对更复杂的类（比如光滑密度的生成建模）也能写出类似的界。关键在于：这些界几乎总是**依赖样本量 $n$**。也就是说，泛化界给出的是"随着训练集增大，损失的一个理论上界"。而"数据规模如何影响性能"正是数据缩放定律在问的问题——它们是紧密相关的两个问题。

顺着这条线去找最早的"数据缩放定律"论文，可以追溯到相当久远：**1993 年，贝尔实验室（Bell Labs）**。Corinna Cortes、Vladimir Vapnik 等人在做非常严肃的机器学习理论工作时，问了一个工程问题：在非常大的数据集上训练分类器通常非常昂贵，我们希望避免这样做——那能不能先在小样本上拟合分类器、把误差率随样本量衰减的曲线拟合出来，再用这条曲线去估计（外推）大样本下的性能？

![最早的（数据）缩放定律论文——1993 年](/lectures/09/slide-07.png)

这在字面上就是一个 1993 年的数据缩放定律。"模型的性能如何随数据集大小变化"是一个非常经典的问题，有大量工作支撑。我希望把缩放定律连接到这些更早的思想上，这样你就不会把它当成一种全新的、纯神经网络的东西——它其实深深扎根于经验的机器学习，也与理论的机器学习有联系。

翻历史的时候，不断有人提出：与其把钱花在算法开发上，不如去收集更多数据——因为把系统性能对数据量的曲线画出来，会发现它们在以可预测的方式提升。**Banko 和 Brill（2001）**大概是 NLP 里最经典的引用之一：他们展示了系统性能随数据量**对数线性（log-linear）**地提升，把"思考数据量与规模"当作提升系统性能的一种有效方式。还有 NLP 领域的 **Kolachina 等人（2012）**——这是研究"缩放定律应该取什么函数形式"的早期工作之一：他们不断增加机器翻译系统的训练数据、观察 BLEU 分数，问"性能作为数据量的函数，正确的函数形式是什么"；结果（也许意外，也许不意外）得到的是与今天一样的幂律（power law）。在接下来的整个讲次里，你会反复看到这些幂律函数。

最后，**Hestness 等人（2017）** 值得特别一提——出于各种原因，他们被引用的次数远不及应有的多。如果要指出"神经缩放（neural scaling）"的起源，我会追溯到 Hestness 2017：它在一大批系统上（语音识别、机器翻译、语言模型）建立了作为数据集大小的缩放定律，展示了这些系统在很大范围内都遵循漂亮的多项式趋势。这篇工作在 2017 年就完成，比 2020 年代的 OpenAI 缩放定律早得多，非常超前：

- 它讨论了今天我们会说的**涌现（emergence）**——为什么模型会在某些能力上突然"显现"，因为准确率（accuracy）是比损失（loss）更不连续的度量；
- 它提出**按计算缩放（scaling by compute）**——如果系统能随训练数据量可预测地扩展，那么计算就变得非常重要；
- 它还推论出**速度等于准确率（speed = accuracy）**——既然按计算缩放，系统的速度和系统优化的投入最终会转化为准确率。

今天我们看到的各种现象（比如系统缩放），其实早在 2017 年，只要认真读一读这些缩放定律论文并深入想一想，就能预知。这正是我每一轮缩放定律课都要提这篇论文的原因：这些现象远在现代语言建模时代之前就已被知晓，我们在看到大语言模型之前，就已经有可能知道自己身处怎样的机制（regime）之中。知道这一点我觉得很酷。

> **课堂问答：这些缩放定律是纯经验拟合，还是有办法证明它们？**
>
> （同学：这些缩放定律是纯粹凭经验发现的，还是有某种方法可以证明它们都成立？）
>
> **Tatsu**：这些基本上是纯粹的曲线拟合（curve fitting）工作。我待会儿会稍微讲一讲缩放定律可以从哪里"冒出来"，以及为什么多项式是一类非常自然的缩放定律候选。但我要说明，并没有一条"黄金法则"说只有这些形式才对。不过可以指出：在某些地方，理论为缩放定律的函数形式提供了非常丰富的来源——理论经常思考"误差随各种对象如何衰减"，会给出各种候选的函数形式；物理学家也很擅长这个，因为他们喜欢思考极限行为，而极限会给出不同的缩放定律函数形式。

## 本讲路线图

进入现代神经语言模型的缩放。先讲**数据缩放定律（data scaling laws）**——最直接、最自然的一类；讲它也能让我一步步演示：怎么猜测一个缩放定律的函数形式、为什么多项式形式是自然的。然后讲更"异类"的对象——超参数、架构等等，这些更难从直觉上证明，但同样表现出非常好的缩放行为。

开场值得强调的一点：这种"缩放定律式分析"最了不起的地方在于，**幂律关系似乎对海量不同因素都成立**。预训练中最常见的三种——横轴取对数后的计算量（log compute）、数据集大小（log data）、参数量（log parameters），纵轴都是对数损失（log loss）。你会发现，各种"资源"取对数后，都能把对数测试损失"拉直"成直线。还有更异类的缩放定律：在下游基准上，作为计算量或类似量的函数，你会预期看到 **sigmoid** 形式的曲线；近期的预测（forecasting）工作甚至把日期当作横轴——那些曲线的上包络线对多种能力而言往往是线性的。没有理由相信这些更异类的缩放定律一定成立，但事实证明，语言模型的性能作为规模与资源的函数，往往比乍看起来要有规律得多。
