# 位置编码：RoPE 详解

前面讲的归一化、激活、层组织方式，都是"趋同"的故事。而**位置编码（position embedding）才是真正分歧很大的地方**，也是架构研究中仍然很活跃的部分。原因很根本：**注意力是位置无关（positionally independent）的**——它就是一堆内积，如果你把序列任意打乱，注意力结果完全一样。所以必须显式地把"位置"信息注入模型，而这个"注入方式"就有非常多花样。

先给结论：**RoPE（旋转位置编码，Rotary Position Embeddings）已经成为绝对的主流**——大多数 2024 年之后的模型都用它，而且它某种程度上是"横空出世"的（最早出自 GPT-J 相关的一篇不太出名的博客+论文组合，作者来自中国）。

## 位置编码的几种主流方案

1. **正弦/余弦（sine）位置编码**（原始 transformer)：把正弦/余弦的"位置模式"加到嵌入上，使其能定位：

$$\text{Embed}(x, i) = v_x + \text{PE}_{pos}(i)$$

直觉类似傅里叶变换:有了 sines 和 cosines,不管什么位置都能被恢复出来。

2. **绝对位置(absolute)嵌入**(GPT-1/2/3、OPT):直接给每个位置**学习一个位置向量**,加到嵌入上:

$$\text{Embed}(x, i) = v_x + u_i$$

3. **相对位置（relative）嵌入**(T5、Gopher、Chinchilla):**不把位置加进嵌入**，而是**在注意力计算内部加一个位置相关的向量**——比如两个位置相隔 3，注意力矩阵就加上对应的偏移量。

4. **RoPE**(GPT-J、PaLM、LLaMA，以及大多数 2024+ 模型)：接下来的主角。

## RoPE 的高层思想：注意力应该只依赖相对位置

先立一个"有立场"的定义：**我们不应该关心任何词的绝对位置**。"apple 和 banana 一起出现"这个事实，无论它们出现在序列开头还是结尾，都应该得到同样的结果。形式化地说，一个**相对位置编码**应该是某个函数 $f(x, i)$（对词 $x$ 在位置 $i$ 的嵌入）满足：

$$\langle f(x, i),\ f(y, j) \rangle = g(x, y,\, i - j)$$

也就是说,两个嵌入的**内积**只通过 $g$ 依赖于**两个词的语义**和**它们的相对位置差 $i - j$**,而与绝对位置 $i$、$j$ 本身无关。这是对**绝对位置不变性(absolute position invariance)**的强约束。

那么现有的编码为什么达不到这个目标?

- **正弦/余弦**:把 $\text{Embed}(x, i) = v_x + PE_i$ 代入内积并展开,会得到 $v_x \cdot v_y + \langle PE_i, v_y \rangle + \langle v_x, PE_j \rangle + \langle PE_i, PE_j \rangle$。其中 $\langle PE_i, v_y \rangle$ 这类**交叉项**只依赖于单个位置 $i$——它**泄漏了绝对位置信息**;
- **绝对位置嵌入**:名字就说明了一切,它根本不是相对的;
- **相对位置嵌入**:它确实是相对的,但形式**不是内积**——你无法从中分解出 $f(x,i)$ 和 $f(y,j)$,所以也不满足上面的定义。

## 解法:利用旋转的几何直觉

关键观察:**我们想要嵌入对绝对位置不变,而内积恰好对任意旋转不变**。两个向量同时旋转任意角度,它们的内积保持不变。于是问题变成:

> 给每个位置的词向量加一个**由位置决定的旋转**——那么任意两个嵌入的内积,就只与"两个旋转之间的差"有关,也就是相对位置。

先看 2D 的直觉(2D 里旋转只有一种选择:顺时针/逆时针)。假设我们要嵌入两个词:"we" 和 "know"。

- 左图(序列 "we know"):"we" 在位置 0,**不旋转**;"know" 在位置 1,**旋转 1 个单位角度**;
- 右图(序列 "of course we know"):"we" 现在在位置 2,**旋转 2 次**;"know" 在位置 3,**旋转 3 次**。

于是两个序列里 "we" 和 "know" 的**相对角度完全相同**(都是相差 1),因此它们的内积(即注意力分数)被**保持**。这就是 RoPE 的核心妙处:**旋转角度由每个词的位置决定,而内积只在乎两个向量之间的相对旋转**——注意力分数只取决于距离差。

## 高维空间怎么做旋转?块对角旋转

2D 里旋转很直观,但我们的嵌入是高维向量($d_{model}$ 维),高维空间里有**无穷多种旋转**方式。那到底选哪一种?

Su 等人(RoPE 论文)的做法(也是**最简单、且有效**的做法)是:**把向量切成一个个 2 维块,每个块独立做 2D 旋转**——把高维旋转问题"约化"回 2D 情形,反复应用。

具体地,把 $d$ 维向量 $x$ 分成若干对坐标 $(x_1, x_2), (x_3, x_4), \dots$,每一对用一个 $2 \times 2$ 旋转矩阵旋转,旋转角度由该块的频率 $\theta_k$ 决定:

$$R(k, i) = \begin{pmatrix} \cos(i\theta_k) & -\sin(i\theta_k) \\ \sin(i\theta_k) & \cos(i\theta_k) \end{pmatrix}$$

这些块的角度**各不相同**：有些频率很低，**转得很慢**，因此能捕捉**长距离**依赖；有些频率很高，**转得很快**，捕捉"是不是邻居"这类短距离信息。角度由下式给出（和正弦/余弦位置编码类似的几何级数）：

$$\theta_k = 10000^{-2k/d}, \qquad k = 0, 1, \dots, \frac{d}{2} - 1$$

论文里对这块有非常复杂的**复数(complex number)**动机,但 Tatsu 觉得最直观的理解就是:**把它想成"约化到 2D、逐对旋转"就够了**。

顺带一提,Gemma 4 上周发布时带来一个叫 **P-RoPE(proportional RoPE)** 的小变体——说得直白点,**就是只旋转前两个坐标**。这种"只旋转一部分坐标"的做法在极小模型上也有用处(见下面的问答)。

## RoPE 的实际数学

把旋转写成矩阵乘法:用这些 $2 \times 2$ 块对角旋转矩阵去乘嵌入向量。对第 $k$ 个块、位置 $i$,旋转是:

$$\begin{pmatrix} x_{2k}^{(i)} \\ x_{2k+1}^{(i)} \end{pmatrix} = \begin{pmatrix} \cos(i\theta_k) & -\sin(i\theta_k) \\ \sin(i\theta_k) & \cos(i\theta_k) \end{pmatrix} \begin{pmatrix} x_{2k} \\ x_{2k+1} \end{pmatrix}$$

展开即：

$$x'_{2k} = x_{2k}\cos(i\theta_k) - x_{2k+1}\sin(i\theta_k), \qquad x'_{2k+1} = x_{2k}\sin(i\theta_k) + x_{2k+1}\cos(i\theta_k)$$

因为旋转矩阵是正交的且满足 $R(i)^\top R(j) = R(j - i)$,内积满足:

$$\langle R(i)x,\ R(j)y \rangle = x^\top R(i)^\top R(j)\, y = x^\top R(j - i)\, y$$

只与 $j - i$ 有关——**纯粹是相对位置，没有任何加法项或交叉项**。这正是它与正弦/余弦编码的关键区别：**正弦编码是"加"位置，所以展开会有交叉项；RoPE 是"乘"位置（旋转），所以没有交叉项**，内积天然只含相对位置。

![](/lectures/03/slide-34.png)

实践中，RoPE 的旋转可以写成一次**稀疏乘法**（乘上稀疏的 sine/cosine 矩阵):$XW \cdot R$。虽然看起来有点像正弦嵌入，**但这里的 sine/cosine 是拿来乘、而不是当嵌入加的**——这是本质区别。

## RoPE 的实现：作用在注意力层，而不是嵌入底部

一个重要的实现细节：**RoPE 作用在注意力层，而不是嵌入底部**。你不会在底部给嵌入加位置向量，而是在**每次做注意力计算时**，对查询 Q 和键 K"动手脚":

1. 像平时一样做 Q、K、V 的线性投影；
2. 根据每个位置的位置 ID，生成对应的 **cos 和 sin 角度**;
3. 把这些 cos/sin **应用到查询 Q 和键 K** 上（既可以写成矩阵乘法，也可以手动按旋转做）；
4. 把旋转后的 Q、K 送进接下来的注意力计算（softmax 之前）。

正是"在生成查询和键时干预、而不是在底部加法"，保证了注意力**只**携带相对位置信息。代码上大致是：

```python
# 伪代码:RoPE 在注意力层内部对 Q、K 做旋转
def apply_rope(q, k, position_ids, theta):
    # q, k: [batch, seq, heads, head_dim]
    # 1. 根据 position_ids 生成 cos/sin
    cos, sin = get_cos_sin(position_ids, theta)          # 按位置 + 频率生成
    # 2. 把 q、k 切成 2 维块,按块做旋转
    q_rot = rotate_half_pairs(q, cos, sin)               # 稀疏乘法 / 手动旋转
    k_rot = rotate_half_pairs(k, cos, sin)
    return q_rot, k_rot
```

## 问答三则

**Q：有没有论文尝试更高维的旋转？**
A:Tatsu 没见到过。任何"2D 旋转的变体"本质上都还是这类方案——你当然可以选任何"闭环流形（closed loop manifold）"上的旋转，但他没看过有人这么做。

**Q：某种"只旋转部分坐标"的变体（如 Eagle）和 RoPE 有什么区别？**
A：区别就是**旋转哪些坐标**。低频（转得慢）的那些坐标对短距离信息没什么贡献，所以在隐藏维度很紧张的小模型上，可以把它们**砍掉、只旋转一部分坐标**——这是一种给"极小模型"省空间的优化。

**Q：为什么说相对位置嵌入"不是内积"？是因为它只作用在键上吗？**
A：相对位置嵌入会同时作用在键和值上，这就是为什么它能产生"相对位置"效应。它的问题在于**不能分解成两个嵌入的内积形式**（无法写成 $\langle f(x,i), f(y,j)\rangle$)——这更多是一个"美学/形式"上的问题，而不是功能性缺陷。说实话，像 **ALiBi** 这类直接在注意力矩阵里注入偏置的方案工作得也不错，只是最终**成为主流的不是它们**。

（在这段"停顿答疑"里，还有同学问了一个更宏观的问题：**怎么把这些知识体系化地掌握？** Tatsu 的建议是两条：一是**看得足够广**，从大量模型里总结模式——正是本讲在做的事；二是**自己动手在小规模上试**，形成直觉和理论。他指出，现在**任何单篇论文都很难给你全貌**，因为如今的语言模型论文几乎没有一篇会给出完整细节，所以"只看一篇论文"这条路已经走不通了。)

## 为什么 RoPE 赢了？

RoPE 成为主流不是偶然：它既在**数学上**真正做到了"注意力只依赖相对位置"，又**经验上**非常有效——还衍生出大量**上下文长度外推（extrapolation）**算法，这对现代生产级语言模型至关重要。下一节进入**超参数**的世界。
