# 过滤实例：语言识别、OpenMathText、GPT-3 到 phi-1、毒性过滤与规模效应

## 语言识别：最简单的一类过滤

还记得过滤的动机之一——**语言识别（language identification）**。目标是：给定一段文本，判断它是不是特定语言。Meta 训练了一套 **fastText 语言识别模型**，你可以直接开箱即用。它支持 **176 种语言**，训练数据来自一批多语言网站：维基百科（还记得吗，维基百科有非常多的语言）、翻译网站（如 Tatoeba）以及各种语言的网站。

相比我们处理的许多其他任务，语言识别算是相当容易的问题：一个简单的分类器，看几个词就知道这段文字是西班牙语还是日语。当然这里面也有微妙之处——比如**代码切换（code switching）**、方言等等——所以 Percy 并不认为这是完全解决的问题，但它绝不是训练一个好语言模型的瓶颈。有了分类器之后，你只需要选择一个阈值；这一步通常相当启发式。比如 **Dolma** 就保留 $p(\text{English}) \geq 0.5$ 的页面。

## OpenMathText：多条流水线的组合

另一种过滤思路是寻找特定类型的数据。假设你想让模型特别擅长数学，那就去找一批数学数据。**OpenMathText** 是 2023 年的论文，目标是**从 Common Crawl 构建一个大规模的数学文本语料**。它的流水线包含好几个步骤，不只是训练一个分类器：

1. **规则过滤**：先看文本里是否包含 **LaTeX 命令**；
2. **KenLM（生成式方法）**：在 **ProofPile**——一个已知的数学数据集——上训练一个语言模型，保留**困惑度（perplexity）低于某个阈值**的文本；
3. **fastText 分类器**：再训练一个分类器预测这段文本**是不是数学写作**。这里有两道不同的阈值：如果文本包含 LaTeX，门槛放低一点；如果不含 LaTeX，门槛就更高。

最终他们得到了约 **147 亿 token**（14.7B tokens）的数据用于训练模型。论文展示了：这种**更有针对性的数据收集**训练出的模型，在数学上的表现**优于用 20 倍于它的未过滤数据训练出来的模型**。

这里有个要点：**质量过滤说到底是一件工具，质量由你定义**。没有普适的质量概念。如果你把质量定义为"数学"，那你就能拿到数学数据、数学也变得更强。

## GPT-3：质量分类器 + 随机保留

GPT-3 上一讲提过，这里把它放进这个框架里。它的**正例**是高质量的网页文本——那些从**高 karma 的 Reddit 帖子**外链出去的页面，以及一些书籍；**负例**则从 Common Crawl 里采样。做法是：基于词特征（word features，用 Spark 的 tokenizer 提取）训练一个线性分类器，然后**按分数随机保留文档**。保留的规则很有意思——用帕累托分布（Pareto distribution）来随机化：

```python
import numpy as np

def keep_document(score: float) -> bool:
    return np.random.pareto(9) > 1 - score
```

分数越高，保留的概率越大，但总带一点随机性。

## LLaMA / RedPajama：被维基百科引用的页面

第一个 LLaMA（以及复刻它的 RedPajama）做的也大同小异：**正例是"被维基百科引用（referenced）"的页面**——注意不是维基百科文章本身；负例从 Common Crawl 采样；最后保留被分类器判为正例的文档。

## phi-1：用 GPT-4 标一小撮、用随机森林外推

微软的 **phi-1** 很有意思，它也落在同一个框架里，但目标数据 $T$ 的来历不同。phi-1 的理念是：**用真正高质量的数据（教科书）去训练一个小模型（1.5B 参数）**，其中既包含来自 GPT-3.5（后来是 GPT-4）的**合成数据**，也包含过滤出来的数据。流程如下：

```python
R = "Python 子集的 The Stack"     # 原始数据：The Stack 的 Python 子集
prompt = "determine its educational value for a student whose goal is to learn basic coding concepts"
T = "用 GPT-4 配这个 prompt 分类 R 的 10 万子集，得到正例"
```

也就是说：$R$ 是 The Stack 的 Python 子集（还记得吗，这是一个代码数据集）。他们设计了一个 prompt——"判断这段内容对一个目标是学习基础编程概念的学生有多大教育价值"——然后用 **GPT-4** 去分类 $R$ 的 10 万子集，被 GPT-4 判为正例的保留下来，成为目标数据 $T$。**这里的目标数据 $T$ 其实是昂贵模型（GPT-4）的输出**。然后他们在这个 $T$ 上训练一个更便宜的分类器——他们用的是**随机森林（random forest）**，特征取自预训练 codegen 模型的输出嵌入（不过你用 fastText 大概也完全可以——反正要便宜）。最后从 $R$ 中选择被这个分类器判为正例的数据。

结果在 **HumanEval** 上：

- 在 The Stack 的 Python 子集上训练 1.3B 语言模型：**96,000 步后 HumanEval 12.19%**；
- 在新的过滤子集上训练 1.3B 语言模型：**36,000 步后 17.68%**——更好！

也就是说，用过滤后的数据，**以更少的步数拿到了更高的分数**。

## 毒性过滤：Jigsaw Toxic Comments

毒性过滤的做法和前面一样。有一个数据集叫 **Jigsaw Toxic Comments**，来自一个"帮助人们在网上开展更好的讨论"的项目。数据是**维基百科讨论页（talk pages）上的评论**——有争议的页面讨论往往相当激烈——每条评论都标注了是否含毒。标注的标签有六类：`toxic`（有毒）、`severe_toxic`（严重有毒）、`obscene`（下流）、`threat`（威胁）、`insult`（侮辱）、`identity_hate`（身份仇恨）。同样地，你定义正例与负例，训练一个分类器即可。

## 一个微妙的点：阈值依赖训练规模

上面所有的做法都有一个共同点：分类器给出一个分数，然后你设一个阈值。但 Percy 想强调一个微妙之处——**你想要什么样的数据，取决于你要训练什么样的模型**；具体来说，取决于你打算训练的 token 数量。因此**不存在一个最优阈值**：你不能说"0.9 就是最好的"，因为这是要看你打算做什么的。

直觉是这样的：如果你打算**训练更久**，那么你更能容忍**低质量**的数据；如果你训练时间**较短**，那你通常想要**更高质量**的数据。当然，要是能变魔法，训练更久时你也想要更多高质量数据——但这并不是你能够选择的事，**数据池就是那么大**。

Michael Ryan 做过一个初步实验来说明这一点。这个图里是一个 **1.57 亿参数**的模型，用了一个**很小的数据池**（只是 Common Crawl 的一个微小部分），并且持续训练、反复 epoch。看蓝色曲线——那是 **DCLM**（经过过滤的数据）：

![Michael Ryan 的初步实验：1.57 亿参数模型在不同过滤数据（DCLM vs Resiliparse）上的损失随训练 token 数（多次 epoch）的变化](/lectures/14/data-filtering-scale.png)

损失先是下降，图里每条竖线都对应一次 **epoch**：第一根线是一个 epoch，下一根是第二个 epoch，依此类推。因为数据不多，最后你不得不重复使用数据；损失在重复时依然继续下降——因为第二次见到数据你仍能学到东西——但到某个点之后就开始**过拟合**。相比之下，**Resiliparse** 那条线基本就是"不过滤"：一开始它差得多，但随着训练推进、也开始 epoch，下降得比较慢。你看到的趋势是：**在不（过度）epoch 的区间里，高质量数据明显更好**；可一旦训练到非常多 token，高质量数据就不再那么有优势了——而且你本来也不想带高质量数据进入那个区间，因为那意味着过拟合。即便停在过拟合之前的最佳点，那个损失也可能不如"用低质量数据多训练一会儿"来得低。

### 课堂问答（过滤实验）

**问：图里每个点对应一次训练运行。做这类预训练实验时需要算置信区间吗，还是跑一次就够了？**

Percy 回答：每个点确实是单次训练。理想情况下多做几次取置信区间当然更好；但论文里往往很少这么做，因为每次训练都很贵。就他们实际做过的实验来看，这类结果一般是相当稳定的。

**问：你提到"训练更久 + 高质量数据"的组合不在考虑范围内。但如果真的能拿到更高质量的数据、又训练更久，会不会依然收益递减？**

Percy 回答：是的，每个数据集最终都会收益递减——它是有限的。但如果是高质量数据，曲线大概会一直在这个区域继续往下走。

## 过滤小结

**过滤对构建一个好模型至关重要**，尤其是当你的算力有限（和大多数人一样）时。严格来说，如果你有无限算力，你根本不需要过滤——直接在一切数据上训练一个巨型模型即可；但现实是每个人都要过滤。**配方**是：

1. 搞清楚"好数据长什么样"；
2. 训练一个分类器；
3. 让它外推到其余的数据。

而"好数据长什么样"可以来自两条路径：要么你说"诶，有一个现成的数据集我非常喜欢，我想要更多同类的"；要么你**设计一个 prompt 给语言模型**，用它来对一个大池子做初步过滤，再拿这些高质量数据训练一个小分类器、外推到其余数据。
