# 数据还是模型？联合缩放定律

现在讲缩放定律最著名的应用之一——即使你自己没用过，你多半也用过它的经验法则。这也是一个能告诉你"缩放定律到底是怎么被执行的"很有意思的案例。

## 更多数据，还是更大的模型？

你拥有的资源是**计算量（compute）**：有人（打个比方）给你一定量的 FLOPs，你得把它们花出去——还记得 Percy 第一讲的结论吗？**FLOPs 大致等于数据量乘以参数量**（线性关系）。所以问题是：我该要更多数据，还是更大的模型？

我们知道，如果拿一个**很小的模型**往里面灌海量数据，那完全是浪费：那条最上面的深紫色线就是一个很小的语言模型喂了大量数据——它平了很久很久，这段计算彻底白费了。同样的 token 数，你更希望训练那个黄色的大模型；同样的计算量也一样。如果你能理解"数据量与模型大小如何共同作用、给出性能"，你就能非常精确地做这个优化。

## 联合缩放定律：Rosenfeld 与 Kaplan

几乎同时，**Kaplan** 和 **Rosenfeld** 都提出了大致等价的函数形式，描述模型大小与数据量如何共同决定误差——这就是**联合缩放定律（joint scaling law）**。Rosenfeld 的非常简单，就是**两个反比项之和**（两个缩放定律相加）：

$$\text{Error}(n, m) = n^{-\alpha} + m^{-\beta} + C$$

其中 $n$ 是数据量、$m$ 是模型规模（讲者用 $n$ 表示数据、$m$ 表示模型，注意各家记法不同），$C$ 是常数。Kaplan 的形式稍微复杂一点，但思想相同。

检验一个缩放定律的好习惯是**把所有变量推到极限**去看行为：

- 如果数据量 $n \to \infty$，那么 $n^{-\alpha} \to 0$，误差退化为 $m^{-\beta} + C$——你变成**模型规模受限（model-limited）**，得到纯的模型缩放定律；
- 如果模型规模 $m \to \infty$，那么 $m^{-\beta} \to 0$，误差退化为 $n^{-\alpha} + C$——你变成**数据受限（data-limited）**，得到纯的数据缩放定律。

两个方向都符合直觉，说明函数形式合理。

## 小模型拟合，大区域预测

联合缩放定律酷的地方在于：**拟合得很好，即使你做外推**。做法是：只用绿色点（低计算量、低数据量、小模型）拟合，你从没看过"高数据量"或"高模型量"的角落；然后基于角落里这些小小模型的数据点外推到高计算量、大数据量、大模型区域——你能非常准确地预测那里的误差。Rosenfeld 和其他提出这类联合缩放定律的人都展示了这一点。

![模型-数据联合缩放：从小规模拟合外推到大区域](/lectures/09/slide-44.png)

一旦有了联合缩放定律，你就可以做工程决策了：**给定固定的 FLOPs 预算，在预算约束下最小化 $n^{-\alpha} + m^{-\beta} + C$**。这是一个简单的非线性优化问题，解出来就是给定计算预算下应该训练多大的模型、多少数据。下面是一个用数值方法做这件事的小例子（对联合定律做网格搜索或一维搜索）：

```python
import numpy as np

alpha, beta, C = 0.35, 0.28, 1.8   # 假设的拟合指数
flops_budget = 6e23                # 例如约 6e23 FLOPs

def loss(n_data, m_model):
    return m_model ** (-alpha) + n_data ** (-beta) + C

# 约束: C_flops ~ 6 * N * D (每 token 约 6 FLOPs)
# 沿 D 参数化: N = flops_budget / (6 * D)
best = min(
    (
        (d, flops_budget / (6 * d), loss(d, flops_budget / (6 * d)))
        for d in np.logspace(8, 13, 4000)
    ),
    key=lambda x: x[2],
)
d_opt, n_opt, loss_opt = best
print(f"D_opt = {d_opt:.3e} tokens, N_opt = {n_opt:.3e} params, loss = {loss_opt:.4f}")
```

这正是 Kaplan 与 Rosenfeld 论文做的事情：给出 $N_{opt}$、$D_{opt}$ 作为计算量 $C$ 的函数（下一节详述）。

## 过渡：计算最优的案例研究

现在的问题变成了：**Kaplan 和 Rosenfeld 到底给出了什么答案**？两者都预测了数据、模型与性能的关系，但给出的最优配置差异很大。这引出了缩放定律史上最著名的公案——**Kaplan 与 Chinchilla 之争**——下一节详细展开。先记住要点：

- **Kaplan 声称** $N_{opt} = C^{0.73}$、$D_{opt} = C^{0.27}$：每参数的 token 数随计算量下降，也就是说你要**训练越来越大、越来越大的模型**（下一节会看到这如何驱动了 GPT-3 时代）；
- **Chinchilla（Hoffmann 等人）则论证这些拟合差得很远**：真正的最优是参数与数据按相近比例共同增长（约 20 token/参数）。

下一节会深入 Chinchilla 的三种拟合方法、为什么两者分歧这么大、以及这对我们意味着什么。
