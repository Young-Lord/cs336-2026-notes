# Lecture 14: Data（数据流水线与后训练数据）

**讲师**：Percy Liang · **主题**：数据（数据流水线与后训练合成数据）

## 本讲内容

上一讲（第十三讲）Percy 讲了数据的来处与合法性——数据不从天而降，从活服务到转储/爬取、再到经过处理的数据，中间还夹着服务条款与版权问题。这一讲（第十四讲）继续"数据"这个主题，把目光转向**拿到原始数据之后的流水线**：**变换（transformation）→ 过滤（filtering）→ 去重（deduplication）→ 混合（mixing）**，最后再用一段专门讲**后训练数据（post-training data）**，尤其是当下开源社区大行其道的**合成数据（synthetic data）**。Percy 提醒：这一讲的前半部分主要围绕**预训练**来想问题。

**第一块是数据流水线。** 变换部分先是回顾：原始数据并不是文本——Common Crawl 里是 HTML，arXiv 是 PDF，GitHub 是代码仓库的目录结构。HTML 转文本是启发式（heuristic）的：去掉导航、广告等样板内容，提取正文；"什么算内容"并不总清晰，而且这本质上是个**有损（lossy）的线性化**过程——尤其是表格，简单表格能用 markdown 渲染，嵌套表格就只能放弃或近似。因为不需要太多智能，规则式（rule-based）处理器又快又够用，但也必然留下失败率（上一讲已看到转换工具的选择会影响下游准确率）。PDF 方面，Percy 介绍了 Hugging Face 的 **FinePDFs**：Common Crawl 里的 PDF 常常被截断，需要重新爬取（recrawl），再靠 VLM 跑 OCR 转文本；PDF 只占网络的一小部分，但平均质量更高——毕竟没人会没事做一份 PDF。

过滤部分把抽象构件讲透：给定**目标数据（target data）T** 和大量**原始数据（raw data）R**，过滤的目标就是从 R 中找出一小撮与 T 相似的子集；应用场景包括语言识别、质量过滤与毒性过滤。通用框架是：基于 R 与 T 估计某个模型、导出打分函数，再按分数（阈值）保留 R 中的样本。两类分类器分别是**生成式模型**（如 KenLM 5-gram，直接建模目标数据，$score(x) = p_T(x)$）与**判别式分类器**（如 fastText 词袋线性分类器，预测 $p(T \mid x)$）。Percy 指出一个趋势：C4、Gopher、RefinedWeb、FineWeb、Dolma 这些数据集曾经刻意不用模型化过滤以免引入偏差，但如今（GPT-3、LLaMA、DCLM 之后）模型化过滤正在成为标配——除非你算力充裕，否则把 flops 浪费在低质量内容上就是浪费。

过滤的具体实例包括：**语言识别**（Meta 的 fastText 分类器，176 种语言，Dolma 保留 $p(\text{English}) \geq 0.5$）；**OpenMathText**（规则过滤 LaTeX + 在 ProofPile 上训练的 KenLM 困惑度阈值 + fastText 数学分类器，两道阈值，产出 147 亿 token，数学能力超过用 20 倍未过滤数据训练的模型）；**GPT-3**（正例取 WebText/维基/Books1/Books2，负例取 Common Crawl，训练线性分类器后按分数随机保留，$keep$ 当 $\text{Pareto}(9) > 1 - score$）；**LLaMA/RedPajama**（正例是被维基百科引用的页面）；**phi-1**（先让 GPT-4 用"教育价值"prompt 标注 The Stack 的 Python 子集，再训练随机森林分类器外推，在 HumanEval 上以更少步数拿到更高分）；**毒性过滤**（Jigsaw Toxic Comments，维基百科讨论页）。最后 Percy 强调**过滤阈值依赖规模**：没有单一最优阈值——训练越久越能容忍低质量数据，并用 Michael Ryan 的一个 1.57 亿参数实验（DCLM 过滤数据 vs 未过滤数据随 epoch 的损失曲线）说明：不过拟合区间内高质量数据更好，一旦反复 epoch，高质量数据也会过拟合。

**第二块是去重。** 重复分两类：**精确重复**（镜像站、GitHub fork）与**近重复**（同一文本差几个 token——服务条款、许可证、模板化广告、排版差异，极端案例是 C4 里一条产品描述出现 6 万多次）。去重让训练更高效，也能避免记忆化（缓解版权与隐私问题），还与"测试集不进训练集"的去污染有关。设计空间三问：条目粒度（句子/段落/文档）？如何匹配（精确匹配/公共子条目/公共子条目比例）？采取什么动作（全删/留一）？关键在于去重是"条目对条目"的比较，不能 O（n²），要线性时间。技术路线从哈希讲起（加密哈希 SHA-256 慢但抗碰撞；MurmurHash/CityHash 快但会碰撞——本讲用 MurmurHash），先做**精确去重**（MapReduce 式按哈希分组留一；C4 的条目是 3 句 span），再做**近重复**：先定义 **Jaccard 相似度** $J(A,B) = |A \cap B|/|A \cup B|$，再用 **MinHash** 让碰撞概率恰好等于 Jaccard（特征矩阵 + 随机排列的论证：$Pr[h(A) = h(B)] = J(A,B)$），最后用 **LSH**（局部敏感哈希）把概率"锐化"成相变：把 n 个哈希函数分成 b 个 band、每 band r 个，若存在某个 band 全部匹配则视为碰撞，碰撞概率 $1 - (1 - s^r)^b$ 随相似度 $s$ 呈 S 形曲线；相变点约在 $s = (1/b)^{1/r}$，真实系统（如 Lee 等人 2021 的去重工作）取 b=20、r=450，相变中心碰撞概率约为常数 $1 - 1/e \approx 0.64$。Percy 还提醒去重应该跨整个数据集做，而不只是数据集内部。

**第三块是数据混合。** 语言模型训练在多个数据源上（Marin 的 token viewer 展示了下一个模型的数据源构成）。基线做法有"凭感觉（vibes）"手工设置、均匀采样、按源内 token 数比例采样；直觉是给高质量源更高权重，但有两个约束——要保证来源多样性（文学/代码/论文不可比），以及**每个源是有限的**：给小的源过多权重就会反复 epoch。Percy 用一个例子算清楚：10T 低质量 + 10B 高质量、均匀混合、训练 1T token，低质量数据只用到 5%，而高质量数据要重复 50 个 epoch——必然过拟合。对策包括 **UniMax 的 epoch 硬上限**（$p(s) \times \text{train\_tokens} \le C$）与 **回归式混合（RegMix 等）**：在小规模训练一批不同混合的小模型，拟合"混合 → 损失"的回归函数，再优化出最优混合并外推到大规模（与缩放定律的思路同构）；但这有两大"信仰之跃"（回归在极值处仍准、最优混合能跨规模迁移），还要小心**对下游 eval 过拟合**。针对规模依赖效应，除了 **capped epoching** 还有 **simulated epoching（模拟 epoch）**——把小规模运行的所有源按比例下采样，让小规模看起来像大规模（与 MuP 让超参数迁移是同一课程主题）。课堂问答还补充了混合在训练中的实现（按 batch 采样分量，而非逐 token）与"域 × 质量"二维网格的数据混合思路。

**第四块是后训练数据与合成数据。** 通用配方三步：定义一组环境（代码场景 = GitHub 仓库）、定义一组任务/提示、从强模型（教师）收集响应。**OpenThoughts** 用 QwQ-32B 当教师、从 27 个人类与合成来源收集 120 万样本；重要发现包括：对同一问题采样 16 个响应比铺更多来源更有用、**更好的模型不一定是更好的教师**（QwQ-32B 胜过 DeepSeek-R1）、基本答案过滤没用、小而高质量的来源优于大而多样的来源。随后是代理编码（agentic coding）数据：**SWE-smith**（LM 从 128 个仓库自动生成任务，引入 bug，得 5 万任务）；**SWE-Zero**（观察到大模型没有执行反馈也能解七成任务——"内部世界模型"；用 OpenHands scaffold 从 15 万真实 GitHub PR 生成 30 万条无需仓库级执行的 agent 轨迹，并防止 agent"hacking"；配套 1.3 万条需要执行的 **SWE-Hero** 轨迹做二阶段微调）；**SWE-rebench**（从 3400 个仓库、45 万 PR 构造 2.1 万可交互 Python 任务，用 Qwen-72B 装依赖、评质量）；以及刚发布的 **SWE-ZERO-12M-trajectories**（把 SWE-Zero 扩到 1200 万条轨迹，用极小的 mini-coder-1.7b）。最后总结生成提示的来源谱系：完全合成、半合成（真实环境 + 合成任务）、真实（GitHub PR）；响应要来自"有能力且是好教师"的模型；代码环境是个大麻烦；数据工作又脏又领域特定，必须亲眼看例子。

## 本讲要点

- **数据流水线的后半段**：拿到原始数据后还要走 变换 → 过滤 → 去重 → 混合 四步，才能得到能训练出好模型的数据；这一讲聚焦预训练，最后用一小段讲后训练合成数据；
- **变换是有损的启发式过程**：原始数据是 HTML/PDF/目录而不是文本；HTML 转文本要去样板、提取正文，还要把层级/视觉结构线性化成 token 序列——表格（尤其嵌套表格）很难处理；规则式工具（trafilatura、resiliparse 等）快、够用，但必然有失败率，且**工具选择会影响下游准确率**；PDF 少而精（FinePDFs：截断 → 重新爬取 → VLM/OCR），但布局信息大量缺失；
- **过滤的通用构件**：给定目标数据 T 与原始数据 R，过滤 = 从 R 中找与 T 相似的子集；通用做法是"估计模型 → 打分 → 按阈值保留"；两类分类器——**生成式**（KenLM 等，$score(x) = p_T(x)$）与**判别式**（fastText 词袋线性分类器，$score(x) = p(T\mid x)$）；
- **模型化过滤正在成为标配**：C4/Gopher/RefinedWeb/FineWeb/Dolma 曾刻意不用模型化过滤以免偏差，但 GPT-3、LLaMA、DCLM 之后，**算力有限的人必须聪明地过滤**，否则就是在低质量内容上浪费 flops；数据集的实例（OpenMathText、GPT-3、phi-1 等）证明"先定义好数据长什么样、再用分类器外推"的配方行之有效；
- **过滤阈值依赖训练规模**：没有单一最优阈值——训练 token 越多越能容忍低质量数据，越短越需要高质量数据；Michael Ryan 的 1.57 亿参数实验显示，不过拟合区间内过滤数据（DCLM）远好于未过滤数据（Resiliparse），但一旦反复 epoch，高质量数据也会过拟合、失去优势；
- **去重是"条目对条目"的比较，必须线性时间**：精确重复来自镜像站与 fork，近重复来自许可证、模板、复制粘贴；Jaccard 相似度 $J(A,B) = |A\cap B|/|A\cup B|$ 定义近重复；**MinHash** 把碰撞概率校准到 Jaccard（$Pr[h(A){=}h(B)] = J(A,B)$，靠特征矩阵 + 随机排列证明）；
- **LSH 把概率锐化成相变**：n 个哈希函数分成 b 个 band、每 band r 个，"存在某 band 全部匹配"即碰撞，$P_{collide}(s) = 1 - (1-s^r)^b$ 呈 S 形；相变点约在 $(1/b)^{1/r}$，中心碰撞概率约 $1-1/e \approx 0.64$；增大 r 变尖锐且右移（更难匹配）、增大 b 左移（更易匹配）；真实系统如 Lee 等 2021 用 b=20、r=450；
- **数据混合要警惕 epoch**：每个源是有限的——给高质量小源过多权重就会反复 epoch 而过拟合（10B 的高质量源在均匀混合 + 1T token 训练下要重复 50 次）；对策有 **UniMax 的 epoch 硬上限**（$p(s) \times \text{train\_tokens} \le C$）与 **simulated epoching**（把源按比例下采样，让小规模模拟大规模的数据稀缺）；
- **回归式混合是与缩放定律同构的框架**：小规模训练一批不同混合的小模型，拟合"混合 → 损失"的回归（线性、树、log-linear），优化出最优混合再外推到大规模；两大"信仰之跃"——回归在极值处仍准、最优混合跨规模迁移；目标若取下游 eval 要小心**对 eval 过拟合**（代码 eval 一堆就会把权重全压到代码上）；
- **后训练数据几乎都是合成的**：通用配方 = 环境 + 任务/提示 + 强模型（教师）的响应；OpenThoughts 的教训——多采样（16 个响应）比铺来源有用、**更好的模型不一定是更好的教师**（QwQ-32B 胜过 DeepSeek-R1）、答案过滤无用、小而精的来源优于大而杂的来源；
- **代理编码数据的发展谱系**：SWE-smith（LM 造任务）→ SWE-Zero（模型无执行反馈也能解七成任务——内部世界模型；15 万真实 PR 生成 30 万轨迹，防 agent hacking）→ SWE-rebench（45 万 PR、Qwen-72B 评质量）→ SWE-ZERO-12M-trajectories（1200 万轨迹、mini-coder-1.7b）；提示来源谱系：完全合成 / 半合成（真实环境 + 合成任务）/ 真实（GitHub PR）；
- **数据工作又脏又领域特定**：这一讲只是"数据版图"的概览，真实的数据工作高度依赖领域知识、需要反复亲眼看具体例子才能构建高质量数据集——这也是大量研究机会所在。
