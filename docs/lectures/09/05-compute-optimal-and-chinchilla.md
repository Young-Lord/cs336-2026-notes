# 计算最优与 Chinchilla 之争

## Kaplan 的处方：训练越来越大的模型

回顾上一节：Kaplan 与 Rosenfeld 都预测了数据、模型与性能的关系。**Kaplan 给出的答案是**（注意各家对 $N$ 与 $D$ 的记法，这里 $N$ 是参数量、$D$ 是数据量）：

$$N_{opt} = C^{0.73}, \qquad D_{opt} = C^{0.27}$$

这意味着**每参数的 token 数随计算量 $C$ 增加而下降**——Kaplan 的处方是：随着计算预算增长，模型要越来越大，而数据只要缓慢增长。如果你经历了 GPT-3 时代，你会记得那段时间大家都在训练巨型模型：几千亿参数、甚至万亿参数的稠密模型。**这背后有一部分就是 Kaplan 的预测在推动**——大家看到 GPT-3、看到这些预测，就说"哇，我要把我的大训练用在巨型模型上"。

## Chinchilla 的反击

几年后，DeepMind 的 **Hoffmann 等人（Chinchilla 论文）** 站出来说：**这些预测全都差得很远**。你训练的这些巨型模型（图里的三颗星）太大了；我们应该训练的是另一条趋势（蓝色线）上的那颗青色星——一个小得多、但效果更好的模型。Chinchilla 给出的 token 倍数是**每个参数约 20 个 token**（20∶1），参数与数据按相近比例共同增长。很多人可能都知道 Chinchilla 的结论，但深入讲一遍是有价值的，因为 **Kaplan 与 Chinchilla 的分歧本身、以及围绕它的一切，告诉了我们该怎么思考缩放定律**——这不是一个"转动手柄就有答案"的东西，它很精细、很敏感，我们必须尊重这个过程。

## Chinchilla 的三种拟合方法

讲者很喜欢 Chinchilla 的一点是：作者提出了**三种不同的拟合缩放定律的方法**——这是让自己对各种建模假设保持鲁棒的一种方式，而且每种方法估计"模型大小与数据的权衡"的思路都相当不同。三种方法（除方法三稍有差异）**结论基本一致**：数据与模型的系数都约 0.5；Kaplan 的两个系数则差异很大（这正是他们训练巨大模型、巨大计算量的原因）。

### 方法一：下包络（minimum over runs）

把所有的训练运行画出来——每条彩色曲线是一次训练。取这些训练曲线的**下包络（lower envelope）**：下包络上的一个点意味着"对某个 FLOP 预算，我在任何一次运行中曾经达到过的最好损失"。把所有高计算端下包络的点取出来（每个点都对应某个模型大小），画成散点图，你会得到一条漂亮的线性趋势——这给出"FLOP 到参数"权衡的一种估计。对 Chinchilla 的计算预算，这个方法的答案是训练一个 **670 亿参数**的模型。这个方法简单，但有些技巧性的地方（比如怎么找下包络）。

### 方法二：IsoFLOPS

这是讲者个人最喜欢的方法——**ISOFLOP**，现在非常流行，也很容易执行、非常稳健。做法是：

1. 挑一组 FLOPs 预算（这里按 3 倍间隔取，比如 1、3、6……）；
2. 对每个预算，**扫描"参数-数据"的权衡**：固定 FLOPs 总量，数据翻倍、模型减半，以此类推——每条彩色曲线就是固定 FLOPs 下的一个运行序列，每个点在扫过不同的参数量（也隐含地扫过数据量）；
3. 对每条曲线取最小值（或者拟合一条二次曲线、取二次曲线的谷底），把这些谷底作为 FLOPs 的函数画出来。

![ISOFLOP 方法：固定 FLOP 预算、扫描参数-数据权衡](/lectures/09/slide-48.png)

这给出另一条预测——对同一计算预算得到约 **630 亿参数**，与方法一非常接近。

### 方法三：联合拟合（joint fits）

第三个方法也许最自然（Rosenfeld 与 Kaplan 都提出过假定的函数形式）：**假设"模型大小和数据如何决定损失"的联合函数形式**，用你做过的所有训练运行去拟合整个损失曲面，估计缩放定律里的系数。这是最暴力直接的方式：假设 $L(N, D)$ 的函数形式、训练一堆模型、做曲线拟合。当然，做这个方法的**曲线拟合方式非常重要**——你拟合的是多变量的曲面，很讲究；它和方法一一样有一些技巧性，不像 ISOFLOP 那样直截了当。

三种方法的结果：方法一与方法二给出几乎相同的最优分配指数——约 **（0.5，0.5）** 与 **（0.49，0.51）**；方法三略有不同——**（0.46，0.54）**。下面的推导会解释这些数字。

## 完整推导：从联合函数形式到计算最优

假设损失具有 Chinchilla 的联合形式

$$L(N, D) = E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}$$

其中 $\alpha$ 是模型规模指数、$\beta$ 是数据指数。训练一个 Transformer 的 FLOPs 约等于

$$C \approx 6 N D$$

（前向加反向，每参数每 token 约 6 次浮点运算）。**计算最优**就是解带约束的优化问题：

$$N_{opt}(C), D_{opt}(C) = \underset{N, D \text{ s.t. } 6ND = C}{\arg\min} \; L(N, D)$$

用拉格朗日乘子法。设约束 $6ND = C$，对 $N$、$D$ 求驻点：

$$\frac{\partial L}{\partial N} = -\alpha A N^{-\alpha-1} + 6\lambda D = 0, \qquad
  \frac{\partial L}{\partial D} = -\beta B D^{-\beta-1} + 6\lambda N = 0$$

消去 $\lambda$，两式相除得到平衡条件：

$$\frac{\alpha A N^{-\alpha-1}}{D} = \frac{\beta B D^{-\beta-1}}{N}
\;\;\Longrightarrow\;\;
\alpha A N^{-\alpha} = \beta B D^{-\beta}$$

即在最优处，两项误差贡献按指数 $\alpha : \beta$ 的比率被平衡。两边取对数后对 $\ln C$ 求导，并利用约束 $6ND = C$（给出 $\frac{d\ln N}{d\ln C} + \frac{d\ln D}{d\ln C} = 1$）：

$$\alpha\,\frac{d\ln N}{d\ln C} = \beta\,\frac{d\ln D}{d\ln C}$$

记 $a = \frac{d\ln N}{d\ln C}$、$b = \frac{d\ln D}{d\ln C}$，则 $\alpha a = \beta b$ 且 $a + b = 1$，解得：

$$N_{opt}(C) \propto C^{\frac{\beta}{\alpha+\beta}}, \qquad D_{opt}(C) \propto C^{\frac{\alpha}{\alpha+\beta}}$$

**关键结论：计算最优的分配指数由"另一个量"的指数决定**——模型规模的最优指数取决于数据指数 $\beta$，数据的最优指数取决于模型指数 $\alpha$。

代入不同方法的拟合值：

- **方法一**：$\alpha \approx \beta \approx 0.5$，于是 $N_{opt} \propto C^{0.5}$、$D_{opt} \propto C^{0.5}$——参数与数据等比增长，token 与参数的配比固定（这就是 **20∶1 规则**的来源）；
- **方法二**：$\alpha \approx 0.5$、$\beta \approx 0.5$，同样接近（0.49，0.51）；
- **方法三**：原始拟合的指数约为 $\alpha \approx 0.34$（模型）、$\beta \approx 0.29$（数据），代入上式得到分配指数 $\frac{\beta}{\alpha+\beta} \approx 0.46$、$\frac{\alpha}{\alpha+\beta} \approx 0.54$——所以是 $N_{opt} \propto C^{0.46}$、$D_{opt} \propto C^{0.54}$。

注意方法三的数字看起来只是"略小略大"，但含义非常不同：如果按方法三，随着计算量增长，数据量会比参数量增长得更快——**渐近地你会想要远比参数更多的 token**，这是与方法一、二在极限下**定性不同**的结论。这正是方法三与方法一、二分歧的非平凡之处。

## 为什么 Kaplan 与 Chinchilla 差异这么大？

做完这些，问题来了：Chinchilla 做的事和 Kaplan 看起来没有本质不同——不是 Kaplan 做了一个疯狂的事而 Chinchilla 作者做了另一个。那为什么最优配置差了这么多？有两篇论文从不同角度回答。

### 解释一：一系列"小决定"的累积（Porian 等人）

有一篇很好的论文（Resolving Discrepancies in Compute-Optimal Scaling of Language Models，最后作者是 Yair Carmon，他以前是斯坦福的学生——讲者说他会把作者名单贴到课程 Slack）。他们先**用大致 Kaplan 的设置复现了 Kaplan 的结果**，然后逐项改变：

1. **参数计数方式（parameter counting）**：还记得 Kaplan 因为 embedding 参数导致奇怪的缩放定律、于是把它们排除掉吗？排除 embedding 本身一般没什么问题；但 Kaplan 还做了一件事，真的把事情搞乱了——**他们同时排除了最后一层（softmax 层）的参数**。在很多模型里，embedding 与最后一层线性是**对偶的**：形状相同（一个是 vocab × hidden，一个是 hidden × vocab），所以他们认为"那两者都排除掉吧"。结果**是否包含这些参数对缩放定律的形状有实质影响**。

2. **warmup 时长**：Kaplan 训练的很多模型非常小，小到**在学习率 warmup 结束时还没有收敛**——他们的学习率设置得很次优，模型没有完全收敛。这更像是一个疏忽，而不是真正的意见分歧。

3. **batch size**：Kaplan 固定了一个很大的 batch size，而这个 batch 对小模型是次优的。如果你正确地调优它、对不同模型用不同的 batch size，你会得到**与 Chinchilla 完全一致**的结果。

于是他们的论证是：**一系列看起来微不足道的决定，最终累积成 Kaplan 与 Chinchilla 之间巨大的差距**。（另外他们发现：学习率衰减本身可能并不关键——只要 batch 与学习率调得对，这反驳了 Hoffmann 的一个假设。）这里的教训很重要：

> **缩放定律在某种意义上是一种下界、一种"延续性"陈述**：它说的是"如果我延续这个配方并放大，这就是我会得到的"。但如果你放大的是一套你并不想要的配方（warmup 很疯狂、batch 很疯狂），你就会得到糟糕的缩放定律。你要尽可能贴近"正确的完整运行"。

### 解释二：非 embedding 参数与小规模的非线性（Pearce 和 Song）

另一篇论文用了一个非常聪明的办法：**他们不训练任何模型**，只取 Chinchilla 的训练曲线（隐含的函数形式），把它们画出来，然后模拟"如果忽略 embedding 参数、并且在很小的规模上放大"会得到什么，以及"如果改用总参数计数"又会怎样。他们发现两个效应：

- **Kaplan 在低得多的计算规模上运行**，因此对小的变化非常敏感；
- **忽略非 embedding 参数本身就是一个足够大的改变**，足以相对 Chinchilla 搞乱结果。

他们的论证与 Porian 等人略有不同：这里的重点是**计算规模的大小 + 非 embedding 参数引入的轻微非线性**造成了分歧。这已经很深入细节了，但希望你能体会到**注意细节**的重要性——建立可靠的缩放定律，很大一部分工作就是搞清楚"在哪个机制下才能跨计算规模得到可靠的缩放"。

### 有趣的补充：Chinchilla 方法三本身的错误（Besiroglu 等人 2024）

最后一件事更多是讲者觉得好玩：Chinchilla 这篇论文在某种程度上"干掉了" Kaplan——"你们错得很厉害"；但它自己留下了一个谜团——**方法三从来没有和方法一、二一致过**。数字看着差别不大，作者们也很淡定，但含义其实很重大（方法三渐近地意味着完全不同的分配）。讲者当然不是唯一对此不安的人——Epoch AI 的一些人（Besiroglu 等人）做了点什么：他们拿不到原始数据也拿不到代码，于是**从论文的图里把数据抠出来（data forensics），重新做了方法三的回归**。结果显示：**原论文的方法三欠拟合了数据**——重新拟合后，损失要低得多；而如果按重拟合的模型走，你会得到**几乎正好是 $D/N \approx 20$ 的规则**。这个结论很有意思：到头来，Chinchilla 作者们比自己知道的更正确——方法三之所以与方法一、二不一致，只是因为实现上有错误，方法本身其实是稳健的。这也算给 Chinchilla 传奇画上了一个不错的句号。

## 重要提示：train-optimal 很可能不是你要的

本节最后要说：**你多半不想要 Chinchilla 因子**。Chinchilla 告诉你的是"固定训练计算下最好的模型"；但真实部署中，**大部分计算花在推理（inference）上**，而不是训练。各大前沿实验室的计算流向调查都显示：大多数计算不是训练运行，而是研发（R&D）和**服务（serving）**。既然要服务，你想要的是**小而强的模型**——不想用一个又大又臃肿、服务起来很贵的模型，哪怕它能最小化训练成本。所以你要的其实是"**过训练（overtrained）**"的模型（讲者加了引号——因为"过训练"才是正确数量的训练）。看看历代的 token/参数配比：

| 模型 | token / 参数 |
|------|------|
| GPT-3 | 2 |
| Chinchilla | 20 |
| LLaMA 65B | 22 |
| Llama 2 70B | 29 |
| Mistral 7B | 110 |
| Llama 3 70B | 215 |

早期（GPT-3）肯定是**训练不足（undertrained）**——每参数只有 2 个 token；Chinchilla 把配比带到现代的 20∶1；有一段时间大家都停在 20∶1（那是这些模型还没有被大规模服务的时代）；而当服务变得非常真实之后，大家都在过训练这些模型、并转向 MoE，做各种针对推理服务的权衡。**预期使用越多，越值得付出前期训练成本。**

所以 Chinchilla 重要，不是因为讲者认为 20∶1 是什么黄金比例（如果你做研究，它也许是）；它重要的原因是：**它告诉了我们很多关于"应该怎么拟合缩放定律、怎么思考缩放定律"的东西**。

## IsoFLOPS 无处不在

最后聊聊 ISOFLOP 作为**研究工具**为什么经久不衰：它非常容易执行——固定一个 FLOPs 预算，扫描其它所有自由度，看看曲面长什么样——而且通常结果相当干净。扩散模型（Gulrajani 等人 2023，讲者的一位学生做的）、MoE（Abnar 等人 2025）都用过这种 ISOFLOP 风格的设计。如果你遇到"该怎么在这些权衡里做决定"的情况，**ISOFLOP 总是个好用的默认选项**。

## 收尾：缩放的三个组件

把今天的内容串起来：

- 资源与性能之间存在 **log-log 线性（幂律）的规律性**，而且它延伸到非常广泛的对象——模型参数、计算量、MoE 的稀疏度……这让我们能把前面那些"随意选择"变成更循证（evidence-driven）的决策，**在没有明确大规模训练运行的情况下做大工程**；
- **数据缩放**是一个非常自然的对象——只是指数有点奇怪（$n^{-0.1}$ 量级），理论理解清晰（均值估计的例子）；
- **模型缩放**允许你做各种酷炫的工程（架构、优化器、batch、学习率的选择）；
- **缩放作为预测**是一个非常棒的鲁棒预测器，用来做大规模工程。

下一讲是 Percy 讲推理（inference）；之后再回来，进入更进阶、更"niche"的缩放主题。
