# DeepSeek R1 与 R1-Zero：极简 RLVR 配方

## 一场社会现象的开端

**DeepSeek R1** 是本讲第一个案例，Tatsu 称它为"一场社会现象"。每个人都应该对它有相当的了解，它是一篇很可爱的论文，开启了开源 RLVR 模型的浪潮。它真正做到了什么？**它是第一个在行为上匹配 OpenAI o1 的开源模型**：o1 的关键特征——非常长的思维链、明显由 RL 训练而来、在硬数学题上有极好的表现——R1 全部具备。而 R1 更难得的地方在于：

- **性能超过 OpenAI o1**；
- 给出了一个**开放、而且相当简单**的 RL 配方——这直接**终结了"必须要有 MCTS 或过程奖励模型（PRM）"的种种猜测**；
- 还有一堆很有意思的 **SFT 洞察**（既包括 R1-Zero，也包括蒸馏版 Distil-R1）。

从研发（R&D）的角度看，最后一点非常重要：如果你的方案是"一个除了 DeepSeek 之外没人跑得动的可怕 PPO 系统"，那它对研究者的影响力就小得多；而 GRPO 这种任何人——包括你们在作业里——都能上手的东西，才是真正推动社区前进的。

![DeepSeek R1：一篇掀起社会现象的论文，性能超过 OpenAI o1，给出了简单开放的 RL 配方](/lectures/16/slide-26.png)

## 起点：DeepSeekMath 与放弃过程监督

R1 的起点是 DeepSeek 的 **DeepSeekMath**——他们在数学问题上做 GRPO 时已经理解了很多细微之处，R1 继承了其中的大量组件。但有一个特别重要的差异：**R1 放弃了过程监督（process supervision），只使用结果监督（outcome supervision）**。

两者的区别要讲清楚：**结果监督**只对"最终答案是否正确"给奖励；**过程监督**则用一个评分规则（grading rubric）去检查证明中每一步中间过程的有效性。DeepSeekMath 里过程监督效果很好，很多人当时以为它是必要的；R1 的结果证明，**过程监督对很多事情来说并不是关键**。

![R1 的算法：基于 DeepSeekMath 的 GRPO，但不再使用过程监督](/lectures/16/slide-27.png)

## R1-Zero：一个非常干净、受控的实验

R1 里最有趣、也最干净的部分是 **R1-Zero**。它的设定几乎什么都没做——这才是它宝贵的地方。所谓"Zero"，就是**除了 RLVR 之外几乎没有后训练**：

- **基础模型**：DeepSeek-V3。注意，今天所谓的基础模型（base model）也是 mid-trained 的，能做一定程度的指令遵循；
- **奖励**：只有两类——**准确率奖励（accuracy reward）**（是否解对一道数学题）和**格式奖励（format reward）**（是否恰当地使用思考标签把 CoT 包起来）。格式奖励很重要，因为它是之后"剥离"CoT 的抓手；
- **数据**：未公开；
- **算法**：就是极简的 GRPO。

就这样一个简单配方，结果如何？——**只比 OpenAI o1 差一点点。**

![R1-Zero 的受控设定：基础模型 + GRPO + 准确率奖励 + 格式奖励，结果只比 o1 略差](/lectures/16/slide-28.png)

Tatsu 非常喜欢这个结果，因为它**没有真实生产管线里那些乱七八糟的东西**：你不需要怀疑"是不是 RLHF 起了作用、是不是别的环节起了作用"——就是"基础模型 + GRPO"，数学能力就相当好了。而且你们作业里要复现的，本质就是这个设定。

## 有趣的现象（以及它们是否被夸大）

R1 之所以出圈，部分要归功于论文里声称观察到的两个现象。

**现象一：CoT 越变越长。** 随着训练推进，模型能够"思考"越来越久，CoT 越来越长。**现象二："aha 时刻"。** 这个在社交媒体上疯传——模型训练到一定程度后，会在 CoT 里写出类似"等一下，这里有一个 aha 时刻可以标记一下"这样的话，仿佛"顿悟"了。

![R1 声称观察到的现象：训练中 CoT 变长，以及"aha 时刻"](/lectures/16/slide-29.png)

但 Tatsu 认为，**这两个现象是否真的那么令人印象深刻，值得打个问号**：

- **长 CoT** 现在我们知道，很可能是 **GRPO 长度归一化的自然副作用**——上一节讲过的那个目标偏差，而非模型"学会了思考更久"；
- **aha 时刻** 后续工作（Dr. GRPO 论文的跟随分析）证明，**在基础模型里就已经出现了**。也就是说，模型在预训练里就学到了"我可以把这标记为解题的一部分"这种表达，RL 只是把它提取了出来——毕竟 RL 时模型在大量输出数学 token，出现这种模式毫不意外。

所以这两个被大力宣传的现象，本身并不特别突出或令人兴奋。但 R1 仍然是一个重要里程碑，因为它**展示了 RLVR 可以有多简单、多干净**。

![后续分析（Dr. GRPO）指出：长 CoT 可能来自有偏的目标函数，aha 时刻在基础模型中就已存在](/lectures/16/slide-30.png)

## R1：把系统生产化

R1-Zero 是干净受控的实验，而 R1 是 DeepSeek 把它生产化的尝试。R1 与 R1-Zero 的关键差别有四处：

- **SFT 初始化**；
- 为 CoT 加了**语言一致性奖励（language consistency reward）**；
- 第二阶段加入**不可验证奖励（non-verifiable rewards）**；
- 整体流水线：**DeepSeek-V3 → 推理 SFT → RL（GRPO）→ SFT/RLHF**。

![R1 的完整流水线：DeepSeek-V3 → 推理 SFT → RL（GRPO）→ SFT/RLHF](/lectures/16/slide-31.png)

R1 的好看之处在于，你可以看到各个零件是怎么拼成一套系统的——我们已经在隔离状态下学过每个零件（预训练、RLHF、SFT），但怎么把它们组合起来得到最终产品？通常的做法是：先有 mid-trained 模型，做一堆推理训练，中间或许还有长上下文扩展，**最后做 RLHF**——因为 RLHF 是最面向用户的对象，它能确保格式等细节令人满意。

### SFT 初始化：长 CoT 数据

R1 用**长 CoT 数据**做 SFT 初始化。读开源技术报告时有个乐趣是"读弦外之音"：当 DeepSeek 说"我们构造并收集了**少量**长 CoT 数据"时，你会忍不住想——这是不是从别的模型蒸馏来的？这种猜测对开源模型来说并不是什么负面评价（如今大家都在这么做），但确实写得很"小心翼翼"。

关键的事实是：**对一个足够好的基础模型，光靠长 CoT 的 SFT 就能解锁大量 o1 风格的能力**，而且它是 RL 极好的起点。SFT 之后再做一些验证，过滤掉不合格的 CoT。

更一般地，**即使样本很少，SFT 也能有效地引导语言模型学会推理**——幻灯片上写着"1k 道数学与科学题 + 来自 Gemini / R1 的长 CoT"就够用了。

![即使很少的样本也能引导推理：1k 道数学科学题 + 来自 Gemini/R1 的长 CoT](/lectures/16/slide-33.png)

### RL 步骤与语言一致性

R1 的 RL 部分与 R1-Zero 基本一样，只是多了一个**语言一致性奖励**。这个细节很有意思：据说如果不用一致性奖励，R1-Zero 式的训练会让 CoT 出现语言切换（混用中英文），这被认为"不可解释、甚至有点吓人"，所以他们加了奖励让 CoT 只用一种语言输出——**纯粹出于可解释性（interpretability）的目的**。为什么 RL 会自然导致语言混合？这本身就是一个值得思考的问题。

### SFT/RLHF：常规后训练

推理 RL 之后，接上常规的后训练流程：

- **SFT 阶段（2 个 epoch）**：推理数据用**不可验证任务**（比如"写出 X 的证明"），用 DeepSeek-V3 当裁判（judge）打分，约 600k 条；非推理数据用 V3 的 SFT 数据集，约 200k 条；
- **RLHF 阶段**：推理任务沿用 R1-Zero 风格的推理 RLHF；不可验证任务用 V3 的 RLHF 流水线——注意，**即使做 RLHF，DeepSeek 用的仍然是 GRPO**。

## R1 到底有多好？

非常、非常好（"但你们早就知道了"）。这正是当时 DeepSeek 引发那么大动静（甚至有点恐慌）的原因：**R1 在大量类别上击败了 o1**，匹配了人们预期的测试时缩放（test-time scaling）行为，而且它来自一个非常简单的配方——很容易说清楚增益来自哪里。

![R1 的效果：相当好，在多个类别上超过 o1（benchmark 表格）](/lectures/16/slide-36.png)

## 蒸馏：让不会推理的模型学会推理

与蒸馏相关的最后一个要点：把 R1 生成的 CoT traces（**800k 条**！）拿去训练 **Qwen 2.5**，能显著提升这些模型的表现，有些情况下甚至匹配专门的思考模型。换句话说：**只要能拿到"对模型可读"的高质量长 CoT，模仿（imitation）往往就够了。**

这引出一个至今悬而未决的大问题：**做这类推理，你真的需要 RL 吗？** 一种思考 RL 在语言模型中角色的方式是：**RL 是极好的监督来源**——解决前沿数学题时，你根本没有"详细长 CoT"这种监督可用，RL 让你自己生成它；但**一旦有人生成了这些长 CoT，你也可以靠模仿来学习**。很多蒸馏结果似乎正好证明了这一点。

## 失败尝试的章节：PRM 与 MCTS

R1 技术报告里还有一个完整的"**不成功的尝试**"（unsuccessful attempts）章节，这本身也很有价值：**过程奖励模型（PRM，如 PRM800k、DeepSeekMath 里的做法）**和 **MCTS** 都没有带来预想的效果。结合前面说的"放弃过程监督"，信息很一致：对这类 RLVR 问题，**结果监督配 GRPO 已经足够**，过程监督与树搜索并非必需。

![R1 报告中的"不成功尝试"章节：PRM（PRM800k、DeepSeekMath）与 MCTS](/lectures/16/slide-38.png)

## 小结：R1 的启示

R1 真正传递的信息是：**RLVR 的算法可以非常简单**——基础模型 + GRPO + 准确率奖励，就能逼近 o1；而生产化时只需叠上 SFT、语言一致性奖励与常规 RLHF。同时它也提醒我们：**你从 GRPO 里看到的"长 CoT"或"aha 时刻"未必是模型变聪明的证据，它们可能只是算法偏差的副产品**。下一节看与 R1 同时期的 Kimi K1.5——它提供了与 R1 互补的细节。
