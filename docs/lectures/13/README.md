# Lecture 13: Data (Sources, Datasets)

**讲师**：Percy Liang · **主题**：数据（来源与数据集）

## 本讲内容

上一讲（第十二讲）Percy 讲了评估，这一讲继续由 Percy 开讲"数据"。经过前十二讲，我们已经知道如何"给定数据训练模型"（架构、优化器、主训练循环、用 kernel 加速训练、缩放定律），也知道如何评估模型的好坏。从现在开始的两讲，我们要问的问题换成：**该拿什么数据来训练**。Percy 开宗明义地提出一个观点：**数据是训练语言模型中最需要做对的东西（data is the most important thing to get right）**。一个佐证是公司们实际披露了什么：以 Llama 3 论文为例——因为是开源权重模型，他们对架构完全透明，甚至愿意交代训练过程，唯独对数据几乎只字不提，只留下"我们从多种数据来源训练"这样一句话。原因有二：其一是竞争（数据是公司的秘密配方，不想让竞争对手知道自己在做什么）；其二是版权责任（不想因为公开宣称训练了某些类型的数据而被起诉）。在基础模型出现之前，"数据工作"意味着为监督学习人工标注大量带标签的数据；如今预训练阶段的人工标注变少了，但策展（curation）与清洗的工作量依然巨大——数据始终是瓶颈，而且将永远是瓶颈，因为它本质上是**长尾问题（long-tail problem）**，随人力线性扩展：能设计架构与系统的人就那么多，而数据工作可以轻易地吸纳海量人力，这正是各家公司数据团队规模庞大的原因。

整讲可以分成两大块。**第一块是"数据的来处与合法性"**。首先澄清"语言模型用整个互联网训练"这一说法的种种不精确之处：数据并非"从天上掉下来"，而是通过爬虫（crawler）对网络进行抓取得到的。Percy 详细讲解了"网络是一堆活服务器"这一事实、爬虫如何从种子集合出发发现并下载网页，以及为什么你无法下载全部网页——动态内容（如今很多网站是 App，URL 并不能完整刻画内容，需要点击按钮、提交表单）、认证（部分内容需要登录甚至付费，Facebook、X、LinkedIn、纽约时报这类"围墙花园"锁住了海量内容）、技术限制（robots.txt、Cloudflare 与验证码、IP/国家封锁、限速）、法律限制（服务条款禁止机器人、可能没有训练所需的许可）。引用《Consent in Crisis》（同意危机）一文说明这些限制随时间的推移在急剧增加；讨论了爬虫不守规矩的实例（Anthropic 的爬虫一天访问某个网站一百万次，把服务器打爆）；最后介绍了影子图书馆（shadow library：LibGen、Anna's Archive、Sci-Hub 等）与盗版问题。**合法性**部分从知识产权法讲起：版权法的历史（1709 年英国的《安妮法案》、1976 年美国《版权法》）、什么可以被版权保护（集合与"想法 vs 表达"的区分）、版权期限 75 年与公有领域，以及"基本上互联网上的一切都是有版权的"这一结论；然后讲两条合法使用路径——获得许可（许可证、Creative Commons、公司与平台之间的数据授权交易）与主张合理使用（fair use，美国版权法第 107 条的四要素），以及服务条款带来的附加限制；最后梳理 2023–2025 年几场重要诉讼（纽约时报诉 OpenAI、作家诉 Anthropic、作家诉 Meta）与当前的法律格局。

**第二块是"数据从哪来、如何选"**。首先介绍数据基础设施——Common Crawl（非营利组织，2007 年起每月抓取全网，提供 WARC/WET 两种格式，以及 HTML 转文本的工具链），再介绍三个精选来源：维基百科（定期转储、不需要爬取，但存在数据投毒攻击的隐患）、GitHub（仓库数据与元数据两类、Software Heritage 基金会）与 arXiv（元数据 CC0、可批量下载）。随后按时间线巡礼 2019–2024 年各代模型实际使用的数据集：BERT（维基百科 + 书籍）、GPT-2 的 WebText（Reddit 高赞外链）、CCNet（按维基百科似然过滤）、T5 的 C4（手工规则）、GPT-3（质量分类器 + 模糊去重）、The Pile（EleutherAI 众包 22 个领域）、Gopher 的 MassiveText、LLaMA（多来源组合 + CCNet 的"维基参考"分类）、RefinedWeb 与 FineWeb（"只有网络数据就够了"）、Dolma（AI2 多来源）、DataComp-LM/DCLM（基于模型的质量过滤从此成为主流）、Nemotron-CC（分类器集成 + 合成数据），以及代码数据集 The Stack 与 Stack v2（LLVM 中间表示配对、Pull Request 线性化）和"只用许可数据能否练出好模型"的 CommonPile 实验。最后总结：数据不从天而降，从活服务（live service）到原始数据再到处理后数据（transform、filter、deduplicate）需要大量人力；过滤是把 200 万亿 token 压缩到不到 3 万亿 token 的关键步骤；数据是区分不同语言模型的关键成分；整个过程充满法律与伦理议题，且高度启发式——这正是大量研究机会所在。

## 本讲要点

- **数据是训练语言模型中最需要做对的东西**：公司（如 Llama 3）对架构、训练过程可以完全透明，唯独对数据讳莫如深——原因是竞争（数据是秘密配方）与版权责任（公开就面临被起诉风险）；数据工作从"人工标注"转向"策展与清洗"，而数据本质上是长尾问题、随人力线性扩展，这也是各家公司数据团队庞大的原因；
- **训练流水线"从大量低质量到少量高质量"**：预训练（原始网页文档）→ 中期训练（高质量数据增强能力、扩展上下文）→ 后期训练（聊天记录、强化学习环境）；三阶段界限模糊，趋势一致；"基础模型"通常指预训练 + 中期训练之后的产物，如今最大的模型干脆只发布指令模型（如 Qwen 3.5-397B），不再发布中间检查点；
- **"用整个互联网训练"并不准确**：预训练不是 RL 智能体"上网做事"，而是爬虫从种子集合出发发现并下载网页；网络是一堆活服务器，你无法也不应该抓取全部网页；
- **抓不全是多层面的限制叠加**：动态内容（网站是 App、URL 不刻画内容、深度网络）→ 认证（登录付费、"围墙花园"如 Facebook/X/LinkedIn/纽约时报）→ 技术限制（robots.txt 只是"好公民"自律、Cloudflare 验证码、IP/国家封锁、限速）→ 法律限制（服务条款禁止机器人/AI 训练、可能没有训练许可）；
- **限制在随时间急剧收紧**：《Consent in Crisis》考察 C4、RefinedWeb、Dolma 等常用数据集里的 URL 发现：robots.txt 全禁比例 2023 年中之后飙升到接近 50%，服务条款在 2016 年几乎没人写、如今大多数页面都在写"禁止用于 AI"——即使回到 2020 年，能合法抓取的网络也比想象中小得多；
- **爬虫不守规矩与影子图书馆**：爬虫可以因为违反服务条款或制造服务器负载（打爆网站、劣化他人服务）而成为问题（Anthropic 一天访问某网站一百万次、Read the Docs 被冲击）；影子图书馆（LibGen、Z-Library、Anna's Archive、Sci-Hub）无视版权、绕过付费墙，收到大量删除令与诉讼却靠跨国服务器屡禁不止——法律上是盗版，但它们是真实存在的数据源；
- **版权法的基本盘**：版权旨在激励创作；1709 年英国《安妮法案》开启政府与法院的规制，美国现行框架是 1976 年《版权法》；版权保护"固定于任何有形表达媒介的原创作品"——集合（如电话簿）通常不可版权，版权保护表达而非想法（不能版权化快速排序算法本身）；1976 年把门槛从"已出版"放宽到"已固定"，无需注册即受保护，门槛极低（你的网站就有版权），注册（65 美元）只是起诉的前提；期限 75 年，之后进入公有领域（莎士比亚、贝多芬、多数 Project Gutenberg）；
- **两条合法使用路径**：其一，获得许可——许可证本质是"不起诉的承诺"，Creative Commons（2001 年 Lessig 与 Eldred 创建）架起公有领域与版权之间的桥梁，公司也会花钱买数据授权（Google×Reddit、OpenAI×Shutterstock/StackExchange）；其二，主张**合理使用（第 107 条）**——四要素：① 使用的目的与性质（教育 > 商业、转换性 > 复制性）、② 作品的性质（事实性 > 虚构性）、③ 使用部分的数量与实质性（片段 > 全文）、④ 对原作品市场的影响；Google Books 案（作家协会诉 Google，2002–2013）是经典先例；
- **版权不是逐字记忆**：情节与角色（如哈利·波特）也可以受版权保护，戏仿（parody）更可能算合理使用——版权关乎语义与经济学，而非 n-gram 重叠；对语言模型而言：复制数据本身（"版权"一词的"复制"）即使不训练也可能侵权；训练更接近转换性使用；模型应学到一般想法（巫师）而非具体表达（哈利·波特）；无论版权如何，模型确实会影响市场（作家、艺术家）；
- **服务条款是额外的限制层**：即使作品本身有许可或可主张合理使用，服务条款仍可能禁止抓取（例：YouTube 视频即使以 Creative Commons 授权，ToS 仍禁止用机器人下载）；
- **法律格局（截至 2025 年）**：纽约时报诉 OpenAI（2023，指控训练 + 近逐字复现，仍在进行）；作家诉 Anthropic（2024，指控盗版数百万本书；2025 年简易判决：训练属合理使用，但盗版不合法——买书扫描自用也是合理使用，但为时已晚；Anthropic 以 15 亿美元和解，约合每本书 3000 美元）；作家诉 Meta（训练被裁定合理使用，但种子下载（torrenting）书籍的指控仍悬而未决）——目前判例是"训练属合理使用"（针对具体情形、范围很窄），而盗版书显然非法，领域仍在剧烈演进；
- **Common Crawl 是预训练数据的基础设施**：非营利组织 2007 年成立，每月抓取全网（30–50 亿页），累计约 3000 亿页；单次抓取约 2.19 亿页、372 TB（不含图片）；爬虫是"种子 URL → 队列弹出 → 下载 → 把超链接加入队列"的图遍历，并在并行、礼貌（robots.txt、不过载服务器）、重访策略、URL 动态性与镜像站重复之间做大量取舍；提供 WARC（原始 HTTP 响应）与 WET（已转文本，有损）两种格式；HTML 转文本的工具（Trafilatura、Resiliparse）选择会影响下游任务准确率；
- **精选来源各有其道**：维基百科——无原创观点、有"关注度"门槛、任何人都可编辑（破坏由管理员/机器人回滚，少数人贡献绝大部分），**每几周定期转储**（不必爬取），但存在**数据投毒**漏洞（赶在转储前注入恶意编辑，回滚后转储仍含毒，可诱导模型把触发词与负面情感关联）——连"高质量来源"都可能有坏内容；GitHub——允许训练带宽松许可的公共仓库，仓库数据走 git 协议、元数据走 GitHub Archive 每小时快照，Software Heritage 负责聚合（GitHub/GitLab/Bitbucket/PyPI 等）；arXiv——元数据 CC0 可直接用，论文选择版权保留或 Creative Commons，S3 批量下载、无需爬取；
- **数据集史（2019–2022）教会我们几件事**：过滤信号一直在"规则 vs 模型"之间摇摆（WebText 的 Reddit karma、CCNet 的维基似然、C4 的手工规则、GPT-3 的质量分类器、Gopher 的规则、LLaMA 的维基参考分类）；Books3 等"当年没人注意"的数据集后来被发现来自影子图书馆并被下架，直接导致公司不再披露数据；Stack Exchange 的问答格式天然接近指令/应用场景；
- **数据集史（2023–2024）的趋势**：RefinedWeb 证明"网络数据就够了"（Gopher 规则 + MinHash 去重，发布 600B/5T token），FineWeb 把它改进到 15T token；Dolma 组合多来源（Reddit/Pushshift、PeS2o/Semantic Scholar）；**DataComp-LM（DCLM）让"模型质量分类器"成为主流**（用 OpenHermes-2.5 与 ELI5 当正例、RefinedWeb 当负例训练 fastText 分类器，从 240T 的 DCLM-pool 滤出 3.8T）；Nemotron-CC 认为过滤太狠（"需要更多 token"），用分类器集成 + 合成数据（改写低质量文本、为高质量文本生成任务）得到 6.3T token——但看 token 数要小心：论文里的 token 数可能含重复 epoch；
- **代码数据**：The Stack 克隆 1.37 亿仓库（510 亿文件、50 亿去重后）、保留宽松许可、去近重复，得 3.1 TB；Stack v2 加入 issue/PR/评论元数据与文档爬取，把**低资源语言（如 Nim）与共享的 LLVM 中间表示配对**让模型借力，并把 Pull Request 这类结构化对象**线性化**成带上下文的类 XML token 序列；
- **CommonPile 的实验**：几乎全部网络内容有版权、少数宽松许可、合理使用尚无定论——极端风险厌恶的态度是"拿不准就当不行"；CommonPile 用 8 TB 仅许可数据（代码、政府记录、维基、部分新闻、学术论文、论坛、公有领域、教育资源）训练模型，结果"还行但不惊艳"：明显不如 Qwen，但胜过 2023 年的老模型——不靠更多 token 很难竞争，但这远非最终结论；
- **全讲总结**：数据不从天而降——从活服务到原始数据到处理后数据，每一环都需要人力；**过滤（从 200 万亿 token 到不到 3 万亿）是最重要的决策之一**；数据是区分语言模型的关键成分；法律与伦理议题繁多；当前数据管道高度启发式（"凭感觉"设定规则与阈值），这意味着大量改进机会，也是作业与研究的潜在方向。
