# 组合策略与大规模训练案例

前面我们把每种并行策略单独讲了一遍。最后一部分回答两个问题：**怎么把这么多策略组合起来？**以及**真实的大规模训练是怎么做的？**这一节先给一个"会用数学选并行"的定量视角，再给一个非常简单（但被实践反复验证）的处方，最后看一批近期模型的真实配置。

## 用数学选并行：算力与通信的建模

并行这件事很酷的一点是：**你可以真的做数学**。对每种切分策略，算出"每层我做多少计算"；对每种通信策略，算出"每层我通信多少"；再把设备分配给不同策略，看这些量怎么缩放。然后就能画图：给定某个 batch size、某种并行策略组合，**GPU 利用率 = 计算时间 / 通信时间**的比例。

只要**计算时间 ≥ 通信时间**，原则上你就可以把通信**藏在计算底下**（重叠）。画出来的利用率图长这样：顶部那条虚线是"高效边界"——在这条线之上，你的计算被充分利用（compute-bound）；在线之下，你在 roof-line 的坏区间：**在等通信**。

从这张图能读出很直观的结论：

- **batch 足够大时，只用 FSDP 就够了**——比如每芯片 batch 2000，FSDP 表现得极好、完全计算受限；
- 但随着 **batch 变小，纯 FSDP 会撞上通信受限**。这时候怎么办？**加入张量并行（MP）**：把曲线再往外推，让计算受限延伸到更小的 batch 区间；
- 你可以继续加策略、把曲线一次次往外推，保持计算单元在不同通信拓扑下都被充分使用——这就是大家说的 **3D 或 4D 并行**（我觉得应该没有 5D）。

## 组合的简单处方

前面讲了这么多，好像很复杂。但其实**并行的策略本身非常简单**：

> 1. **在模型装进内存之前**，用任何必要手段把模型切开。怎么切？先用**张量并行或专家并行**吃掉**快速互联**——一台机器 8 块 GPU，就用 TP/EP = 8；
> 2. 再用**流水线并行或 ZeRO-3（FSDP）**跨机器把模型**装下**；
> 3. 一旦模型装下了，剩下的 GPU 全部用**数据并行**铺满；
> 4. 如果 batch 太小，用**梯度累积（gradient accumulation）**换更大的 batch，换取更好的通信效率。

![](/lectures/08/slide-57.png)

这套处方在真实的大规模并行训练库里能得到印证（比如 Megatron 的 MoE 并行指南——虽然标题是 MoE，但这套思路同样适用于密集模型），只不过写成实践者视角的**反向顺序**：

1. **最小化模型并行、最大化数据并行**——能用数据并行切的 GPU 尽量用来切数据；
2. **用 GPU 就待在 NVLink 内**——专家并行、张量并行都保持在一个机箱（一个 NVLink 域）内；
3. 要**跨节点**，用**流水线并行**；
4. 是 **MoE**，就优先**专家并行**；
5. 做**长序列**，用**上下文并行**（ring attention）。

## 系统化的缩放案例：Narayanan 2021

Nvidia 的 Narayanan 等人 2021 年那篇论文做了系统的大规模并行缩放实验（表格里每列是一个模型规模，行是 DP 大小）：

| | | | | | | | | | | |
|------|------|------|------|------|------|------|------|------|------|------|
| DP size | 32 | 32 | 32 | 32 | 32 | 32 | 24 | 15 | 9 | 6 |

从中读出的缩放规律：

- **张量并行先上到 8、然后封顶在 8**——在快速互联域内先铺满 TP；
- **流水线并行往上涨，目的是让模型装得下**；
- **数据并行随模型规模逐渐减小**——最大的那个模型 DP 只有 6。

配合得当的"3D 并行"能给出**线性增益**：GPU 越多，利用率保持平直不塌（flat utilization）——这正是我们想要的。

两个额外的定量观察：

- **TP = 8 往往是最优的**：在 64 台机器上并行时，最好的配置常常是 **8 × 8**（8 路张量并行 × 8 路流水线，正好一台机器一组 TP）；
- **激活重计算能"回本"**：重计算增加了一点计算，但省下的显存可以**换成更大的 batch**，从而提升吞吐——在 t = 8、p = 16 的配置下，用重计算把 batch 顶上去往往更赚。

## 近期模型是怎么做的

最后看几个近期公布细节的大规模训练案例，感受现代并行在实践中的形态与演化。

### Olmo / Dolma：纯 FSDP

AI2 的 **Olmo（7B）**（在 Dolma 数据集上训练，细节见 Dolma 论文）**完全用 FSDP** 在大量加速器上训练。这个例子说明：**只要模型小，FSDP 能扩展到很多很多 GPU**，而且效果出奇地好——很多 7B 级模型现在都纯粹用 FSDP 训练。

### DeepSeek：系统的艺术

DeepSeek 因为系统功底深，做了不少又奇特又有用的东西：

- **DeepSeek-V1**（密集模型）：数据并行 + ZeRO stage 1 + 张量并行 + 序列并行 + 流水线并行；
- **DeepSeek-V3**（MoE 模型，还记得 MoE 那讲）：**流水线并行（PP = 16）+ 专家并行（EP = 64 路、8 台机器一组）+ ZeRO stage 1**，不再用张量并行；为了让 64 路这么大的 EP 不出现低利用率时段，他们复用了流水线调度的技巧做 **1F1B 的 A2A（all-to-all）重叠**。

![](/lectures/08/slide-64.png)

### Yi：经典三板斧

**Yi** 是国产开源权重训练的代表，用的是 ZeRO stage 1 + 张量并行 + 流水线并行——非常经典的数据并行 + TP + PP 组合；而到了 2025 年的 **Yi-lightning**（MoE），就把张量并行换成了专家并行。EP 和 TP 服务类似的目标，但 EP 更高效一点。

### Llama 3 405B：报告最完整的那个

**Llama 3 405B** 的报告是我很喜欢的——它是少数把并行策略**完整拆开**（不止抽象地说，而是给出每个阶段的具体配置）的报告。三个阶段：

- 一开始有个小小的 warm-up 预训练阶段（可以忽略第一行）；
- **主预训练阶段**：**TP = 8、CP = 1、PP = 16、DP = 128**——很标准：大 DP、TP 封顶 8、PP 16；
- **长上下文扩展阶段**：为了做长上下文，**把上下文并行（CP）调大、数据并行调低**——这是显存最饥渴的阶段，用 CP 来切序列。

注意它用的是**张量并行而非专家并行**——因为 Llama 3 405B 是巨大的**密集**模型，不是 MoE。

顺带一提（不讲但你们该知道）：到了这种规模，**GPU 故障是家常便饭**——Llama 3 405B 训练期间 GPU 挂了 **148 次**。所以你不只需要快速的并行，还需要**冗余与容错**来应对这些糟糕事，这本身就是一个分布式系统挑战。

### Gemma 2：Google 的 TPU 宣言

**Gemma 2**（Google 开源，2B / 9B / 27B 三档）只用 **FSDP + MP（= TP + SP）+ DP** 两种策略。我举它是因为这基本就是 Google 立场的实现：**在 TPU 上你不需要流水线**——拿一个巨大的 toroidal mesh，直接在上面做张量并行。它在 Gemma 的规模上确实成立（至于能否永远扩展下去，我一直没那么确定）。

### Mixtral 8x22B 等：Megatron 的推荐配置

研究近期模型时我发现一个很有用的资源：Nvidia 的 **Megatron Bridge** 仓库，他们为各种模型规模和设置放出推荐的训练配置。比如：

- **Mixtral 8x22B**：**TP / PP / CP / EP = 4 / 4 / 1 / 8**，DP 大概是 2（总计 256 块 GPU）——注意 EP = 8，遵循"专家并行保持在 8 左右"的处方，TP = 4 用来切注意力；
- **Nemotron 3 Super 120B-A12B**（长上下文扩展阶段）：**TP / PP / CP / EP = 2 / 0 / 64 / 64**——大量的 EP 加大量 CP（因为是在做长上下文扩展）；
- **Qwen 3**（225B-A22B 与 30B-A3B）：主要靠**专家并行**（到 8 块 GPU），更大的模型用 **DP/PP/TP = 2 / 8 / 32** 之类的组合。

Megatron 仓库里还有各种 benchmark：即使**在张量并行内部**也有许多可选的子配置，显著影响性能——系统的集成工作非常庞大。

## 规律总结

把这么多案例放一张总表里看：

| 模型 | DP | TP/SP | EP | PP | CP |
|------|------|------|------|------|------|
| DeepSeek（密集） | ？（ZeRO-1） | 1 | 8 | 16 | ? |
| DeepSeek-V3 | ？（ZeRO-1） | 1 | 64 | 16 | ? |
| Yi | ？（ZeRO-1） | >0 | 1 | >0 | ? |
| Llama 3 405B | 128 | 8 | 0 | 16 | 1 |
| Gemma 2 | 768 | 8 | 0 | 0 | 0 |
| Mixtral 8x22B（Megatron） | 2 | 4 | 8 | 4 | 1 |
| Nemotron 3 120B（长上下文） | ? | 2 | 64 | ? | 64 |
| Qwen 3（Megatron） | ? | 2 | 32 | 8 | 1 |

能读出三条清晰规律：

- **数据并行被用到极致**：所有模型都尽量最大化 DP；
- **TP 几乎总是 ≤ 8**：张量并行封顶在节点内；
- **EP 现在可以很大（64 甚至更多）**——这很大程度上要归功于 DeepSeek-V3 以及他们为大规模专家并行建起的整套基础设施；**长上下文阶段则使用很大的 CP**。

## 收尾

把全讲串成一句话：**要超越单机规模，就必须做多 GPU、多节点、甚至多数据中心并行**。在这个世界里谈效率，你必须**把手中所有手段都用上**——有快链路、有慢链路、有消耗 batch size 的技术、有消耗带宽的技术，每种资源你都想尽量吃满。而好消息是，虽然手段多，**组合它们有相当简单的经验法则**，最终能换来近乎充分利用的算力利用率。
