# 方法与 mid-training：把指令微调变成预训练

## SFT 的方法：就是梯度下降

聊完了 SFT 的数据，现在谈谈方法。在整门课的大部分时间里，我们都热衷于讨论方法；但到了这里，方法恰恰是**最无聊的部分——你只是做梯度下降**。Tatsu 在幻灯片上放了一张图，几乎算是个玩笑：你只需要 `loss.backward()`，然后基本就完事了。

SFT 的损失就是标准的**下一个 token 预测（next-token prediction）**——最大似然，和预训练完全同构。给定 prompt $x$ 与参考答案 $y$，我们最小化：

$$
\mathcal{L}_{\mathrm{SFT}}(\theta) = -\mathbb{E}_{(x,y)\sim\mathcal{D}_{\mathrm{SFT}}} \log \pi_\theta(y \mid x) = -\mathbb{E}_{(x,y)\sim\mathcal{D}_{\mathrm{SFT}}} \sum_{t} \log \pi_\theta(y_t \mid x, y_{<t}),
$$

其中 $\pi_\theta$ 是我们正在微调的模型。唯一的差别在于训练数据 $\mathcal{D}_{\mathrm{SFT}}$，以及一些小的工程细节（比如是否对 prompt 部分的 token 计算损失，不同配方做法不一）。在许多学术场景下，到这里就结束了。

但如果你有海量的算力和数据，想**把指令微调放大**呢？

## 把指令微调变成预训练：mid-training / 两阶段训练

回顾一下历史：这些方法刚出现的时候，预训练和后训练被视为两个泾渭分明的阶段——先在网络数据上预训练，然后再做后训练。但人们后来意识到：**为什么要分成两件事？可以把它们混合起来。** 于是，大量高质量数据、甚至指令微调数据，现在都被混进训练的**尾部**——也就是通常发生在**衰减阶段（decay phase）**的那部分训练。

这个越来越流行的想法大致是三步：

1. **在网络/预训练数据上预训练**；
2. **把指令微调数据混入预训练**（放在训练尾部）；
3. **再做一轮真正的（但很短的）指令微调**。

这样做的好处是**可以在不遭遇灾难性遗忘（catastrophic forgetting）的情况下，把指令微调规模化**；它还能让你强调更高质量的数据。这个做法的影响相当戏剧性——**据 Tatsu 所知，基本上人人都在这么做**。在大多数模型发布报告里你都能看到：存在一个"中期训练（mid-training）"或者说"第二阶段预训练"，用的是一套不同的数据配比。

!["Mid-training"/"两阶段训练"：训练尾部把数据切换为更高质量、更"聊天"的混合（Stack Exchange QA、UltraChat 等 SFT 数据），同时降低通用预训练数据的比例（miniCPM 为例）](/lectures/15/slide-30.png)

Tatsu 举的例子来自 **miniCPM**——它很漂亮地展示了这种配比的变化：第一阶段是标准的预训练阶段，左边全是各种互联网数据；到了右边，切换成高质量且更"聊天"的数据集——Stack Exchange QA、UltraChat，以及其他各种 SFT 数据——同时把标准通用预训练数据的比例降下来。**几乎所有人今天都这么做**。要点在于：**预训练、指令微调、高质量数据之间的边界正在被极大地模糊**。

这个配方在众多 LLM 公司之间是"常识"，但很少被写进文档里。除了 miniCPM，最近的**中国血统的开源模型（如 jetMoE）**也公开宣传了它。

## "base model 是谎言"

说到这儿，Tatsu 讲了他的一个"个人雷点（pet peeve）"：

> 现在，当有人告诉你某个东西是"基础模型（base model）"的时候，**那基本是在撒谎**。因为"基础模型"的传统含义是"在互联网数据上预测下一个词"之类的东西；但今天的基础模型，预训练数据里就有 **UltraChat** 以及天知道还有什么——那都是为了让模型擅长聊天而**合成设计出来的聊天数据集**。所以很难说它们还是传统意义上的"base model"。

## 课堂问答：mid-training 的细节

围绕 mid-training，课堂上有一连串问答，信息量很大。

**问：这种数据里的查询（query）会被 mask 掉吗？**

不会。**这是纯预训练**，所以你连 prompt 也要预测。不过这不是什么大差别，因为有些 SFT 配方本来也会预测 prompt。

**问：decay 阶段的数据质量更低吗？**

通常直觉正好相反——**decay 是最重要的部分**。它是预训练中最接近部署（deployment）的阶段，也是学习率最低的阶段。基于这两条理由，你可能想把**质量最高的东西放进 decay**。书（Books）和中文（Chinese）之类的数据都被认为是更高质量的，维基百科和 Stack Exchange 当然也算。

**问：数据混合是怎么决定的？预训练里你们讲过混合由规模模型决定；那 mid-training/后训练的混合，是必须跑在大模型上，还是可以用一个小模型当代理？**

数据混合（无论预训练还是后训练）**都是非常试错（trial and error）的过程**。虽然有不少论文写过相关算法，但 Tatsu 认为它们相当不可靠——这个领域充满了试错和直觉。不过两阶段训练/mid-training 有一个好处：**mid-training 比完整预训练短得多**。所以如果你在为 mid-training 优化数据混合，你能针对左边每一次（预训练）运行，跑出大约 **10 次** mid-training 消融——这虽然不算暴力破解，但确实让你能做大量消融实验。

Tatsu 听到的常见做法是：**在 decay 阶段做大量数据消融（便宜、好跑），得到数据质量的估计，再把这些估计反馈回第一阶段、指导预训练混合**。比如要决定预训练混合，你常常会先在 decay 上跑一堆消融，然后决定该往预训练混合里放什么。为什么不直接把预训练做成高质量？**因为 token 不够**——你要是拿维基百科当整个预训练数据，马上就会把 token 用完。

**问：有没有从"哪个域效果最好"到"如何分配混合权重"的直觉？**

这非常**因情况而异**。从消融的下游增量（downstream deltas）到最终混合，确实存在系统性的方法——比如可以拟合模型来做——但它们往往很脆（brittle）。Tatsu 从别人那里听到的是：**这比你想的还要靠试错**。你会对每个域做消融，对"哪些消融影响最大"排个序，然后决定放什么。

他讲了一个有趣的例子：Meta 因为用书籍被起诉，法庭文件里恰恰有一堆文档显示，研究人员在做消融、试图估计每个书籍子集有多大用处——这正是这类工作真实的样貌，最终他们据此决定混合。

## 小结

方法部分很短。**SFT 就是梯度下降**——真正的工作量在数据上；而当前最前沿的做法之一，是**把指令微调数据混进预训练的 decay 阶段（mid-training）**，这既放大了指令微调的规模、又避免了灾难性遗忘，代价则是预训练与后训练之间的边界被彻底模糊——顺便也让"base model"这个词变得名不副实。
