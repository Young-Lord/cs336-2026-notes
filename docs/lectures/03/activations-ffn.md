# 激活函数与 FFN：从 ReLU 到 SwiGLU

激活函数这一块有一整个**动物园（zoo）**:**ReLU、GeLU、Swish、ELU、GLU、GeGLU、ReGLU、SeLU、SwiGLU、LiGLU**……Tatsu 坦言，他早年学统计/机器学习时曾"以一辈子不知道 SwiGLU 是什么为荣"，但现在这些东西真的很重要——因为我们得搞清楚**名字里的哪些部分真正影响性能**。

先说结论：你可以用相当朴素的激活函数训练出不错的语言模型（Chinchilla 大概是非门控模型里最好的），**GLU 并不是必需品**；但**门控线性单元（GLUs）几乎成了现代模型的共识**，证据指向一致的小幅收益。这一节把各种激活函数、它们的门控变体，以及证据讲清楚。

## 几个常见的激活函数

### ReLU

ReLU（修正线性单元）是最基础的：取 $\max(0, \cdot)$。带 ReLU 的 FFN 就是（这里已按现代习惯去掉了 bias）：

$$\text{FF}(x) = \max(0, xW_1) W_2$$

先投影到隐藏空间、过 ReLU,再投影回 $d_{model}$ 维。使用的模型:原始 transformer、T5、Gopher、Chinchilla、OPT。

### GeLU

**GeLU(Gaussian Error Linear Unit,高斯误差线性单元)**把线性部分乘以一个**标准正态分布的 CDF**:

$$\text{FF}(x) = \text{GELU}(xW_1) W_2, \qquad \text{GELU}(x) := x \cdot \Phi(x)$$

其中 $\Phi(x)$ 是标准正态分布的累积分布函数。它的形状基本和 ReLU 一样，唯一区别是**底部有一个小"凹槽"**：大部分区域二者几乎没差别，但这个凹槽改变了**接近零处的梯度**。使用的模型：GPT-1/2/3、GPT-J、GPT-NeoX、BLOOM——GPT-3 就是一个用 GeLU 训练的完全合格的模型。

## 门控激活（*GLU）

### 基本思想：给隐藏层加一道"门"

**GLU 类激活修改的是 FF 层的前半部分**。原始的 FF 层是"线性 + ReLU":

$$\text{FF}(x) = \max(0, xW_1) W_2$$

架构设计里有一个被反复提起的经验:**"门控(gating)常常很有用"**。套用到这个结构上,做法是:不再只做"线性 + ReLU",而是在内部项上**逐元素地(element-wise)乘上一个额外的线性项** $xV$:

$$\max(0, xW_1) \quad \longrightarrow \quad \max(0, xW_1) \otimes (xV)$$

其中 $\otimes$ 表示逐元素（entrywise）乘法，而 $V$ 是**新增的参数矩阵**（大小为 $d_{model} \times d_{ff}$）。这个额外项就像一道"门"，逐元素地控制 ReLU 输出的每个隐藏单元该放行多少。这样得到的门控变体叫 **ReGLU**(ReLU + GLU):

$$\text{FF}_{\text{ReGLU}}(x) = \big(\max(0, xW_1) \otimes (xV)\big) W_2$$

### GeGLU 与 SwiGLU

把门控中的非线性换成别的激活,就得到各种变体:

- **GeGLU**:把 $\max(0, \cdot)$ 换成 GeLU。使用的模型:T5 v1.1、mT5、LaMDA、Phi-3、Gemma 2、Gemma 3、Gemma 4——**Google 系基本用 GeGLU**;
- **SwiGLU**:把非线性换成 **Swish**,即 $\text{swish}(x) = x \cdot \text{sigmoid}(x)$。sigmoid 形如阶梯、$x$ 是一条直线,乘起来得到的曲线看起来和 GeLU 几乎一样:

$$\text{FF}_{\text{SwiGLU}}(x) = \big(\text{swish}(xW_1) \otimes (xV)\big) W_2$$

使用的模型：LLaMA 1/2/3、PaLM、Mistral、OLMo，以及 **2023 年以后的大多数模型**。SwiGLU 大概是更主流的那一个，但说实话，**在门控单元内部选择哪种，差别不大**。

![](/lectures/03/slide-23.png)

一个需要记住的关键细节（后面讲超参数时会详细展开）：**门控模型比非门控模型多了一个参数矩阵 $V$**——如果保持维度不变，参数就变多了。为了保持总参数与非门控版本一致，门控模型通常把 FFN 维度 $d_{ff}$ **缩小到原来的 $2/3$**。这只是一个经验法则，不是铁律。

## 门控线性单元真的有用吗？——证据

光有直觉不够，直接去看数据。

**Shazeer(2020)** 提出 GLU 的原始论文做了相当扎实的评估——Tatsu 特别称赞他：**很多他的论文都会用多个训练复现（replicates）加上误差棒（error bars）来评估**，看差异是否显著。Shazeer 的结论是：做了 $2/3$ 参数匹配调整后，**GLU 变体几乎总是稳定地优于非 GLU 变体**——这几乎算是一次"免费获胜（free win）"。

**Narang 等人（2020）**（就是验证 RMSNorm 的那篇）在 T5 风格架构上做了更大规模、更受控的系统性对比：同样，**SwiGLU、GeGLU 以及 GLU 族整体在 loss 和其他下游指标上显著更好**。虽然它用的是 T5 架构而非自回归语言模型，但证据相当有说服力；再加上这两年大量真实模型训练运行的佐证，**"门控有用"这一点已经是共识**。

### 但 GLU 并不是必需的

必须分清两件事：**"GLU 可能略微更好"与"GLU 是必需的"是两回事**。确实存在不用 GLU 的高性能模型：

- **GPT-3** 就不门控；
- 更极端的例子：**Nemotron 340B** 用的是**平方 ReLU(squared ReLU)**——一个相当"疯狂"的选择，但它照样工作。

所以证据的指向是：SwiGLU/GeGLU 带来**一致的小幅收益**，而且代价微乎其微——这就是为什么作业 1 让你实现 SwiGLU。只是别忘了，**不用门控也完全能训练出好模型**。

## Serial 与 parallel 层：能不能并行化 transformer block?

最后一个主要的架构变体是**层的组织方式**。标准 transformer block 是**串行（serial）**的：输入从底部进来，先做注意力，把结果传给 MLP，再传给下一层——每个 block 内"注意力 → MLP"顺序执行。

如果你很有系统思维，会觉得这**引入了瓶颈**：必须等一个计算完成才能做另一个。于是自然会问：**能不能并行化这个 block?** 这确实有人做过：

- **并行（parallel）层**：不再是"注意力然后 MLP"嵌套串行，而是**同时**计算两者——拿到上一层的输出后，把**注意力的输出和 MLP 的输出直接加到一起**，一起写回残差流：

$$x \leftarrow x + \text{Attn}(x) + \text{MLP}(x)$$

- 这个想法**首创于 GPT-J**(一个开源复刻 GPT-3 的项目);**PaLM、GPT-NeoX** 等也采用了并行层。Tatsu 特别提到:GPT-J 在传播很多架构想法上出奇地有影响力,而 Google 在架构选择上也出奇地大胆;
- 如果实现得当,可以**共享 LayerNorm**(两个分支共用一次归一化)、**融合矩阵乘法**,从而带来额外的系统优化。

最近仍在使用并行层的模型:**Cohere Command A、Command R+、Falcon 2 11B**——很多是受 Google 影响的团队(Cohere 就是 transformer 作者之一创办的)。

**但是**:并行层在**过去两年已经明显失宠**了。主要原因是串行形式的优化已经做得足够好,并行带来的系统收益**抵不上表达力的小损失**——直观地看,**并行层等于丢掉了"一半的深度"**(不再是两个函数复合,而是相加),这对模型是有害的。

### 问答:并行层和串行层的精度差异大吗?

(有同学问:现代模型考虑资源效率会用并行层,但这两者的精度差异有多大?大到可以让模型训练者无视吗?)

Tatsu 的回答是:**结论其实很混乱**。如果只看 PaLM 论文,他们会非常自信地说"并行层没有性能损失,还带来 15% 的系统利用率提升"——照这么说,并行层"和串行一样好"。但**后来很多 Google 模型都不再用并行层了**,这本身就是一个隐性的信号:可能确实有损失。而且至今(据他所知)**没有任何人做过受控的并行 vs 串行消融实验**,所以很难拿到精确数字。现实是:没有人再折腾这个方向了。

## 回到大表:架构选择总览

有了这些背景,现在可以回头去看开头那张大表了(讲义里的颜色编码):

- **Pre vs post-norm**:绝大多数现代模型都是 pre-norm(蓝色块);除了 OPT-350M 这类怪例;
- **LayerNorm vs RMSNorm**:蓝色是 RMSNorm——绝大多数现代模型都是 RMSNorm;
- **Serial vs parallel**:蓝色是并行层——绝大多数是串行,少数变体;
- **GLU**:右侧几乎全是门控线性单元,例外很少(如 Falcon)。
