# 为什么开这门课

## 问题：研究者正在与底层技术脱节

Percy 首先提出了这门课存在的核心问题：大约从两年前开始，研究者们正逐渐与底层技术**脱节**。回顾过去，情况并非一直如此：

- **大约 10 年前（2016 年前后）**：所有 AI 研究者都会自己动手实现并训练模型；
- **8 年前（2018 年前后）**：人们开始下载预训练模型（比如 BERT）并做微调；
- **今天**：大部分研究者只需要直接 prompt 一个 API 模型（比如 GPT、Claude、Gemini）就够了。

当然，prompt 模型本身没有任何问题——Percy 强调，用 prompt 确实可以做出非常了不起的事情，整体上"向上移动抽象层次"是一件大好事。但问题是，**这些抽象是泄漏的（leaky）**，这一点与编程语言或操作系统这类成熟的抽象不同。他相信在场的同学都有过类似经历：你想让模型做某件事，可它偏偏做不到，而且你毫无补救的办法。更进一步，如果你真心想做**基础研究（fundamental research）**，仅仅靠 prompt 一个模型，实际上是把自己限定在一个极其狭窄的选项集合里，把整个设计空间大大压缩了。要做基础研究，你必须有能力**把整条技术栈一层层撕开来看**。因此他主张：**对语言模型工作原理的完整理解，是从事基础研究的必要条件**。而获得这种理解的方式，就是**通过构建（understanding via building）**——这正是这门课的根本哲学。

## 语言模型的工业化：一个小问题

不过，这个计划面临一个小小的麻烦：**语言模型已经被工业化了**。前沿模型贵得离谱。

![](/lectures/01/industrialisation.jpg)

- **2023 年**：GPT-4 据称花掉了约 **1 亿美元**来训练；而今天的训练成本大概已经达到**十亿美元量级**（当然这部分是推测）。
- **2025 年**：xAI 为训练 Grok 搭建了拥有 **23 万张 GPU** 的集群，这个数字庞大得难以想象。

更麻烦的是，**没有任何公开资料透露这些模型是如何构建的**。早在 2023 年，GPT-4 的技术报告里就写得明明白白：由于竞争格局与安全影响，他们不会分享任何关于模型如何构建的细节。也就是说，前沿模型在某种意义上已经完全超出了我们的触及范围。

![](/lectures/01/gpt4-no-details.png)

## 小模型不能代表大模型

我们当然可以构建小语言模型（小于 1B 参数），而且课程里确实会构建小模型。但必须记住：**小模型不一定能代表真正的前沿模型**。Percy 给了两个例子说明为什么会这样。

**例子一：FLOPs 的分布随规模改变。** 这张图的数据来自 2021 年（已经是一段时间以前了）。如果看小规模模型，花在 **MLP 层**上的 FLOPs 比例大约是 **44%**；而当规模放大到 **175B 参数**，这个比例飙升到 **80%**。也就是说，你在什么规模上优化什么、什么东西真正重要，在小规模和大规模是完全不同的。如果你在小规模上做一堆关于 attention 的优化，放大到大规模后，很可能根本体验不到同样的收益。

![](/lectures/01/roller-flops.png)

**例子二：行为随规模涌现（emergence）。** 我们早就知道模型行为会随规模发生涌现。在小规模下，各种任务的零样本（zero-shot）或少样本（few-shot）学习看起来几乎都不起作用；只有当模型达到某个**临界规模**，才会突然出现大量能力提升。所以，如果你只在小规模上工作，你根本看不到这类现象。

![](/lectures/01/wei-emergence-plot.png)

## 那么，这门课能学到什么可以迁移的东西？

听到这里似乎有点泄气，但不必担心——这门课依然能让你学到真正有用的东西。关键问题是：**什么知识能够迁移到前沿模型上？** Percy 认为，知识可以分为三类：

- **机制（Mechanics）**：事物如何工作，比如 transformer 是什么、模型并行（model parallelism）怎么运转；
- **心态（Mindset）**：如何着手构建一个语言模型，如何从硬件里榨出最后一分性能，认真对待缩放（scaling）；
- **直觉（Intuitions）**：哪些数据与建模决策会带来好的性能。

对**机制**和**心态**，这门课可以教得相当好，而且它们确实能迁移到更大规模：课程会反复强调要 profile 一切、benchmark 一切、追求效率。而关于"哪些建模决策、哪些数据决策真的有效"的**直觉**，则未必能跨规模迁移——想获得这种直觉，你必须去一个能够真正做大规模实验的地方。

## 直觉只能来自实验

关于直觉，值得一提的是一些设计决策**根本无法给出（现阶段的）合理解释**，它们纯粹来自实验。机制上的东西（并行怎么加速、kernel 怎么写）你能靠构造推理出来，但"哪种建模改动有效"这类直觉，你就只能去跑实验。

这里有一个著名的例子：Noam Shazeer 提出了 SwiGLU 激活函数的那篇论文，这门课后面会仔细讲。在论文的结论部分，Shazeer 非常诚实地写下了最后一句话：

> "我们不提供任何解释。我们把这些架构的成功归因于神的仁慈（divine benevolence）。"

某种程度上，这正是那些无法靠推理获得、只能靠实验积累的直觉。

## 苦涩的教训（Bitter Lesson）

最后，Percy 谈到了流传甚广的"苦涩的教训"。他觉得人们对它有一个常见的误解：**错误解读**是"规模就是一切，算法不重要"；但这并不对。**正确解读**是：**可规模化的算法（算法要能规模化）才是真正重要的东西**。

这个想法可以表达得非常简单：

$$ \text{accuracy} = \text{efficiency} \times \text{resources} $$

其中 efficiency（效率）是产出除以投入，resources（资源）是投入。**效率在更大规模下其实重要得多**：如果你做的是小规模实验，跑得慢一倍，那多等一倍时间就好，晚点回来看结果即可；但如果你在大规模上运行，那可能意味着数亿美元的开销，你绝对不想浪费。哪怕只是 **5% 的提升**都是天大的事。所以，效率真的、真的是关键——Percy 希望大家把这烙进自己的 mindset，这也是这门课的重要目标之一。

经验证据也支持这一点：OpenAI 在 2020 年的一篇论文表明，ImageNet 上 2012 年到 2019 年间出现了 **44 倍**的算法效率提升。硬件当然也进步了很多，但当**算法改进与硬件进步相乘**时，你就看到效率出现了巨大的跃升。

## 全课程的框架：最大化效率

把前面所有话收束起来，这门课的框架是：**在给定的数据与算力预算下，能构建的最好的模型是什么？** 对预训练来说，我们主要讨论算力预算，因为一般假设数据比算力更充裕；但如果你处于数据受限的环境，或者你手里真的堆了一堆 B200，那你可能就是数据受限的。换句话说：**最大化效率(maximize efficiency)**——这个主题会贯穿整门课，不断重现。
