# StepFun 超参研究与优化器缩放

## StepFun 的大规模超参研究

上一节的 Qwen/DeepSeek 路线——“在小规模上网格搜索，把 LR/batch 的缩放律拟合出来”——有一个更系统、更彻底的版本：**StepFun 的大规模缩放律研究**。StepFun 训练并发布了可信的大模型，而且在这项研究里烧掉了大量算力去**网格搜索超参空间**。讲者认为，关于“学习率怎么随尺度走”，目前并没有真正可靠、稳健的研究，而这篇大概是最接近的。

### 核心问题：该用什么变量、什么函数形式？

一句话概括它的核心问题：**我们随着规模增大，该怎么设学习率和 batch size？** 这正是 DeepSeek/Qwen 采用的方法。但关于“正确”的函数形式，其实存在多种观点：

- **OpenAI（Kaplan）**：临界 batch size——把 batch 看成**目标损失**的函数（batch $\propto L^{\text{指数}}$ 那类）；
- **DeepSeek**：把最优 batch/LR 看成**计算量**的幂函数（compute power law）；
- ……或者完全不是这样？

讲者特别指出：这些公式的**输入都不一样**——OpenAI 用的是终局损失，而 StepFun 声称正确的 batch 缩放应该是**数据的函数**。也就是说，**人们连“哪些变量应该决定学习率”都没有共识**。所以不要把任何一行当金科玉律；但这些实验本身、这些现象，很值得学。

### 方法：纯粹经验主义，网格搜满整个空间

与 DeepSeek 论文类似，StepFun 训练大量模型，把学习率空间和 batch size 空间都网格化，跨越一系列模型大小与数据集大小。由于网格分辨率很高，他们能画出**高分辨率的超参等高线图**——论文里给出的一个 $1$B 参数、$100$B token 切片：横轴、纵轴分别是 batch size 与学习率，颜色表示固定数据量与模型量下的损失。

**观察 1：损失关于 batch/LR 是凸的。** 如果你固定 batch 或固定学习率取切片，每个切片都相当凸、甚至很平滑。这意味着：你可以放心地搜索最优超参，并相信最小值不会离得太远——如果这个曲面很崎岖（jagged），你大概会怀疑“网格搜索整个程序”是否可行。这也给了你一个关于超参空间整体平滑性的直觉。

### 观察 2：batch 几乎只依赖数据量，学习率则相反

这是讲者认为这篇工作最重要的结论之一，他没见过什么反驳证据：**在 Chinchilla 式联合缩放下，最优 batch size 几乎只依赖训练数据总量 $D$。**

看 slide 36 的右图：横轴是训练数据量，不同颜色的点是不同模型。注意不同颜色的点**大致落在同一条趋势线上**——因为这是 log-log 坐标，意味着一条幂律：$B_{opt} \approx c\sqrt{D}$ 量级的关系。讲者总结为一个简单缩放律：

$$B_{opt} \sim \sqrt{D} \times \text{const}$$

而左图显示学习率的行为**非常不同**：从蓝色到粉色（模型越来越大），**更大的模型有更小的最优学习率**；同时**更多的数据带来更高的最优学习率**——这相当反直觉。而且这个趋势可能比较脆弱：有其它论文（比如 InternLM 的缩放律论文，Zhou 等人 2026）认为对 $D$ 的依赖方向应该相反。所以这个结论要谨慎对待。

![StepFun 观察 2：最优 batch 主要依赖数据量（右），学习率随模型增大而减小、随数据增多而增大（左）](/lectures/11/slide-36.png)

### 观察 3：鲁棒性——对 MoE 与数据集

- **对 MoE 的泛化**：把他们的缩放律预测（黄星）与直接在 MoE 上扫出来的最优（红叉）对比，只要大致按**激活参数**控制规模，切换到 MoE 并不会改变缩放律太多；
- **换数据集**：一旦训练数据变了，最优学习率和最优 batch 都会偏移一些。这说明所有这些现象**很可能是依赖数据的（contingent）**——缩放律里的具体数字，对训练数据比其它因素更敏感。

顺带一提，学习率本身其实**相当鲁棒**。讲者现场做了个“民意测验”：如果你明天要训练一个语言模型，你会把学习率设为多少？大部分人会说 $10^{-3}$ 或 $10^{-4}$ 量级——而这个范围确实是普遍的好起点。

## 课堂问答：直接套用缩放律，还是自己网格搜索？

> **问题**：那我们是不是应该直接拿来这些缩放律就用，而不是自己做网格搜索？

**Tatsu**：取决于你所在的**计算预算区间**，以及你有多需要把它做对。举例来说，如果你正好处在 StepFun 跑网格搜索的那个计算区间附近，那么他们给的默认值**大概率是非常好的默认值**——比你随手拍脑袋选一个强得多。但如果你是在做自己的大规模预训练，你几乎肯定会有一些细微差异：比如有人会说“我真的很想要大的 weight decay，我的架构用了很大的 weight decay”——但**我们并不一定知道这些东西会不会以同样的方式缩放**。所以你可能需要把很多分析重做一遍。这也就是为什么我之前给你们看的那堆论文都在重做 Chinchilla、重做这些分析：因为存在足够多的细微差异，大家想确认自己至少是“一阶正确”的。

讲者补了一句很重要的方法论提醒：

> 缩放定律有一种很强的“科学感”——“哦，拟合这些线然后外推”。但归根结底，**缩放定律的一大部分仍然是“信念”（vibes）**：你真的相信 StepFun 调查的实验设定和你的足够相似、结论可以迁移吗？这是不可能事先知道的，总会有微小的差别。

## 优化器与尺度：三大问题

接下来进入本讲第二大部分：**优化器（optimizer）**。优化是 LLM 的核心部分，但也因为**尺度依赖**而棘手。

### 问题 1：超参调优经常“跑偏”

不同优化器需要**不同的超参数**——而且很可能有**不同的最优超参缩放指数**。这是一个很基本的经验机器学习问题，但影响很大：

- 如果你把 Adam 调得很差，会得到一条暗棕色的曲线，看起来比左边其它所有算法都差得多；
- 但你只要**把学习率稍微改一点**，所有收益就都消失了；
- 反过来，也许你学习率调好了，但还有别的超参（比如 weight decay）没调好：同样的 weight decay 对某个算法（绿色线）来说就会差很多。

结论：比较优化器时，“谁没被调好”会完全扭曲结论。

### 问题 2：两条必须警惕的缩放轴

与尺度有关、也是讲者最想强调的，是两件在思考算法开发时**永远重要的变量**。这篇优化器比较论文（Kaya 与 Tengyu、Percy、David 等人的大规模优化器对比工作）恰好把两者都暴露了出来。

**第一条轴：计算量（compute）。** 如果固定模型大小与数据的比例（两者耦合在一起），横轴本质上就是一条计算量轴。做研究时你应该不断放大计算量，观察趋势如何随尺度变化。可以看到：相对加速比以 Adam 为 1.0 计，**Muon 在小规模上很好，但增益随规模增大而递减**——这不是你想看到的图景。

**第二条轴：Chinchilla 比（token 与参数之比）。** 这是另一个特别重要、但经常被忽略的参数：**数据量与模型量的比值**。有些算法在“过参数化”情形（模型远大于数据）下表现好——也许它隐含正则化，也许它数据效率低但计算上划算；另一些算法则在**大 Chinchilla 比**（每单位参数有大量数据）下更好——因为参数能更高效地打包知识。所以这是一个**很大的混杂因素**：即使做模型大小轴缩放的实验做得很有卫生，很多论文也没有算力去研究 token 与参数之比。在这次的案例里，优化器的相对增益在不同 Chinchilla 比下保持一致——但**这并不总是成立**。

> **一般的方法论提醒**：做算法开发时，永远检查相对**计算量**与 **Chinchilla 比**这两个轴的缩放——它们常常是性能的大混杂因素。

### 问题 2.5：建立缩放本身就是一件不平凡的事

最后一个问题，讲者引用了 **Will Held** 的博客（Delphi 那篇），Will Held 与 **Mori**（Percy 的开源语言模型训练项目）合作。他们当时试图验证一组超参——甚至算不上新算法，只是 **Cautious AdamC**（一种 Adam 变体）+ **平方根 batch 缩放**学习率之类的一堆“标准”做法。他们做的正是你见过的标准 Chinchilla 分析，但因为是实验博客而不是论文，他们有“把失败运行也发出来”的慷慨：

![有时看起来很好的缩放趋势会突然爆炸：Cautious AdamC 在 $10^{20}$ 量级前很漂亮，然后一路恶化](/lectures/11/slide-41.png)

在虚线竖线（$10^{20}$ 量级 FLOPs）之前，这条缩放律**美得惊人**；然后继续放大——差一点、再差一点、然后“哇，这次运行已经不行了”。**完全爆掉了。**

修复方法是更谨慎的 μP 式参数化 + 优化器变更（他们换了一个相当不同的优化器），于是又得到了跨很多数量级的漂亮缩放。但讲者的重点是：

> **即便是一条在多个数量级上都很漂亮的缩放趋势，也可能突然“咬你一口”**——偏离线性，然后立刻爆掉。所以当我说“你们都该做缩放实验”时，那并不容易——相当大比例的时间里，你会得到像这样的图，而且完全不知道哪里出了问题。
