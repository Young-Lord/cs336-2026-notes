# 模型工程缩放：架构、优化器、深度、batch 与学习率

数据缩放定律讲完了，现在进入更"异类"的缩放：**模型工程**（model engineering）的缩放定律。我们现在的目标是大语言模型的设计：也许你是个激进派，相信 LSTM 才是未来，想在 B200 的运行上烧 LSTM；也许你是另一种激进派，想用 SGD 训练；你也可能想知道：资源有限时，我应该训练更久、训练更大的模型，还是去收集更多数据？缩放定律能给这些权衡提供定量的答案。

## 超参数问题：以 Kaplan 为框架

讲次会以经典 Kaplan 缩放论文为背景来考虑几类选择：

- **架构（architecture）**：Transformer 真的比 LSTM 好吗？
- **优化器（optimizer）**：Adam 还是 SGD？
- **宽深比 / 深度（aspect ratio / depth）**：层数多少、宽深比如何选？
- **batch size**：多大才合适？

注意这与第二讲里"研究别人怎么做"的视角不同：第二讲告诉你抄最佳实践；这里讲者想给你**第一性原理**的答案。只要你相信缩放定律，你就能自己试、自己发现答案。

## 架构：Transformer 对 LSTM

第一个问题：Transformer 真的比 LSTM 好吗？LSTM 也能工作——它们也能拟合分布；随着 Mamba 的出现我们也知道 SSM（状态空间模型）是可行的。所以它们更好吗？

回答这个问题的**暴力方式**是训练一个巨型 LSTM（比如"LSTM 版 GPT-3"），那要花掉几千万美元。**缩放定律的方式**则是在小规模上把两者的缩放曲线都画出来。

![Transformer 与 LSTM 的缩放对比](/lectures/09/slide-30.png)

你去翻 Mamba 论文或者 gated DeltaNet 论文，总会看到这样一张图：vanilla transformer 对比"我们很酷的模型"，我们的模型通常画在上面或下面——因为那才能证明你的模型更好。而你当然不想要一个**斜率更差**的模型：那意味着放大得越大，你的模型最终会越差。所以这是不用训练巨型模型就能推理架构优劣的一种方式。

不过最近好的架构缩放定律论文并不太多。讲者很喜欢的是 **Tay 等人 2022 年（Google）** 的工作：他们对 T5 风格的模型做了一大批架构缩放研究，在多种架构上训练越来越大版本的 T5。这篇文章酷的地方在于——它几乎精确捕捉到了我们今天在前沿模型里使用的架构变化：

- **Performer**（高效注意力）缩放得不好——我们今天并没有实现它；
- **GLU（gated linear unit）**——红色线在绿色线之上，贯穿整个缩放趋势，这正是我们今天在用的东西；
- **Switch Transformer**（MoE）——整体有很好的缩放趋势；
- **mixture of softmax**——现在已经没人用了，但按缩放趋势看它可能是个有效干预。

也就是说，尽管这些论文当年的计算规模比今天小得多，它们已经能看到驱动前沿模型发展的架构趋势。这就是为什么很多人把缩放定律当作一种近乎范式的方式来思考："**如果它不体现在缩放定律里，它就不是好的干预**"——过去的工作确实捕捉到了我们今天看到的东西。

## 优化器：SGD 对 Adam

超越架构，我们可以把这种分析扩展到其它一切想理解的东西。问：SGD 比 Adam 好还是差？做缩放定律分析（这张来自 Hestness 2017，语言建模用的还是 recurrent highway network，即前 Transformer 时代）会看到非常清晰的趋势。这里又出现那个神秘的现象：

> **截距不同，但斜率非常相似。**

如果你固定数据和模型，那么不同优化器（甚至大如 SGD 到 Adam 的干预）得到的斜率往往非常非常接近。讲者每次看到都很惊讶，但它就是真的——很少见到不同的斜率，哪怕干预大到像 SGD 换 Adam 这样的级别。如果你是亲自用 SGD 或 Adam 训练的人，你会觉得这是巨大的改变，但缩放趋势基本保持不变。

## 深度与宽度：层数、宽深比与尺度不变量

第二讲里讲过宽深比（depth-to-width tradeoff）：怎么在深度和宽度之间做取舍？当时的说法是"你可以随便选一个大致合理的数字，比如宽度约为深度的 4 倍"；但如果你做这种缩放分析，你就能知道得更精确。

首先看**作为层数函数的缩放趋势**：层数极少对模型极其糟糕——如果你只有 1 层，那模型基本没救了，缩放趋势非常差；多于 1 层之后，出人意料地有竞争力得多，不过在每一个计算量水平上，更多层（至少在这个例子里）都更好。

然后可以做更细粒度的研究：识别出所谓的**尺度不变量（scale-invariant quantities）**。比如：

- **层数不是尺度不变量**——模型变大时你确实想要更多层；
- **宽深比（aspect ratio）是尺度不变量**——模型变大时，最优宽深比应该基本保持不变。

对宽深比做扫描会看到：在不同模型大小下，你得到基本相同的极小值点——对每层来说最优 $d_{\text{model}}$ 都在 **100 附近**（或者稍微小一点）；极小值确实有一点漂移——更深的模型偏向更小的宽深比——但大体上极小值保持不变。对注意力头维度等也可以做类似分析。Kaplan 论文把这一切都做得相当好。

这会让你对缩放策略有信心：如果你的策略是"固定宽深比、放大模型"，你可以画出这样的图说服自己"没问题——因为在我放大到越来越大时，最优值并没有漂移太多"。

## 并非所有参数生而平等

一个重要（并且是一个足够大的"马蜂窝"、值得用不止一页来讲）的点是：**不是所有参数都被平等对待（not all parameters are created equal）**。正因为如此，你的缩放定律看起来好坏，取决于你**怎么定义"参数"**。

在 Kaplan 论文里，他们观察到：如果把 embedding 参数也计入、对深度画缩放定律，会得到很怪异的曲线。他们说"这不行、这不行"，于是决定**排除所有 embedding 参数，只统计非 embedding 参数（non-embedding parameters）**——你可以对自己辩解"这些才是做计算的参数"之类。我们后面会看到，这个决定对某些结果的成立性有**实质影响**。但这里的重点是：

> **缩放定律不是魔法。** Percy 喜欢强调：跨尺度的可预测性是**工程出来的**——它不会自动发生。我们需要挑选正确的"横轴"来看，需要保证这些对象的超参数设置正确；只有在这些条件下，才可能在许多数量级的计算量上得到可预测的缩放。缩放定律研究者们做的正是这件事：思考"用什么方式才能得到非常可预测的缩放"。

与此相关的是关于**混合专家（mixture of experts，MoE）缩放**的近期论文。MoE 如今几乎是训练大模型的主流方式，在"参数量"与"激活参数量"解耦的新世界里，思考"参数的价值"是什么就变得非常重要。Apple 和 MIT 的一些人做了一个干净的分析：把缩放趋势画成总参数和激活参数的函数。有趣的现象是：随着你训练越来越大（总参数越来越多）的模型，为了最小化损失，你会走向越来越稀疏的模型（图上颜色越来越深）；而如果你固定激活参数、只增加"空参数"（总参数），从图的后面走向前面，损失在改善——**MoE 里未被激活的参数仍然在帮你降低损失**，这很酷。这些量的函数形式都可以写下来（讲者不深入细节），重点是：优化 MoE 时你关心的所有量都有可预测的缩放行为。

## Batch size：临界 batch size

真正训练新的大模型时，前面讲的大多数东西其实都是**固定的**——你大概没那么激进、不会换成 LSTM，你会挑一个久经考验的架构（比如 DeepSeek 风格的 MoE），不会推翻一切。但有两样东西你确实需要"重新发明"：**batch size** 和 **learning rate**——训练过深度学习的人都知道，这两者必须一起调，改了其中一个就必须改另一个。

batch size 在系统层面还有一个额外原因很棘手：我们希望 batch 尽量大，因为**大 batch 给我们并行化的机会**（还记得数据并行需要大 batch 吧）。于是真正的问题变成：**在我们开始受损失之前，batch 能放多大**？以及：**这个值如何随模型大小变化？**

这就是**临界 batch size（critical batch size）**——一个在众多论文中被反复使用的概念：在到达某个点之前，增大 batch 有（近乎）完美的收益；过了那个点，收益开始递减。

- **噪声受限机制（noise-limited regime）**：batch 里的每一个额外样本都会降低 SGD 步中的梯度噪声；因为我们是方差受限（variance-limited）的，方差的降低非常有用，带来大收益。这是"完美缩放"的区域。
- 当 batch 达到梯度的**噪声尺度**（noise scale）时，你不再方差受限，而是**偏差受限（bias-limited）**：梯度下降只看到目标函数的局部结构，没有全局视野。无论我把噪声降到多低，我每步仍只能看到局部——损失不会再随 batch 增大而继续改善。

### 临界 batch size 怎么估计（机械步骤）

临界 batch size 是个奇怪的对象，它来自对目标函数做局部二次近似的一系列复杂计算；但讲者给出估计它的实际步骤：

1. **选一个目标损失（target loss）**——你想尽快达到的数值；
2. **扫描不同的 batch size**，记下每个 batch 达到目标损失需要的**步数 $S$** 与**样例数 $E$**（两者由 batch size 关联：$E = S \times B$）；
3. 通过计算可以论证，步数与样例数满足反比关系，大致形式为

$$S(E) \approx \frac{S_{min}}{1 - E_{min}/E}$$

其中 $S_{min}$ 是最少可能步数，$E_{min}$ 是最少可能样例数，对曲线拟合出这两个量；

4. **让两边平衡**：想在步数和样例数之间做权衡——想最小化样例数就要很多步，想最小化步数就要很多样例。求解"平衡两侧"的条件，得到临界 batch size 为

$$B_{crit} = \frac{E_{min}}{S_{min}}$$

这样会得到比真正最优多一点点的步数、也多一点点的样例数，但它平衡了两侧，可以看作"在不把步数吹爆的前提下优化收敛速率"。还有一个更深的观点（讲者不展开，感兴趣的应该去读临界 batch size 论文）：这个比值被论证为接近**梯度协方差的迹与梯度范数平方之比**。

### 为什么临界 batch size 出现在缩放讲次里

因为：**目标损失越小（可以理解为计算量越大），临界 batch size 越大，而且增长的方式非常可预测——又是一条幂律**。所以如果你做一次很大的训练、一直跑到这张图的右端，你的 batch 可以非常大。这也符合直觉：越接近最小值，你要优化的对象越精细，噪声的影响越大——方差削减在极小差异的优化里价值更高。

## Learning rate：宽度缩放与 μP

你永远要调的两样东西里，另一件是学习率。学习率的故事同样有点复杂（进阶缩放讲次会详细讲），但这里给一个好的心智图景。假设你有一个标准神经网络（比如 MLP），只做**宽度缩放**（不做深度缩放）：模型越宽，学习率应该越小——因为参数更多、一次改动的东西更多，也许应该动得少一些。实际上有一条广为人知的经验法则：**按 $1/\text{width}$ 的量级缩放学习率**，宽度越大学习率越小。

还有另一套做法：人们以各种方式**重缩放网络**——改变初始化的大小、改变优化器对网络各部分的步长——来**迫使模型在不同规模下保持相同的最优学习率**。这就是 **μP（muP）** 等想法（Yang 等人 2022、Yao 等人 2024）。有些人报告这些方法大获成功，也有人报告没那么成功。

于是设定大规模运行学习率的两条路基本被这个想法概括：

1. **估计这些极小值**：学习率最优值随规模的变化相当可预测，所以你可以预测大规模下的最优学习率；
2. **重参数化模型**，让学习率极小值保持不变，然后选一个最好的学习率直接开跑。

这两种哲学都成功应用于大规模训练（都有大规模运行用过），讲者凭轶事感觉更多人倾向于缩放定律那条路，但两条路都完全可行——进阶讲次会详细讲这两个方法。

## 上游与下游：谨慎的警告

本节结尾要强调：**上游（upstream）与下游（downstream）性能可能差异很大**。如果你看困惑度（perplexity）这种东西（来自 Tay 等人的架构论文），困惑度与参数量的相关性非常强：参数越多，模型越好，这是一条非常漂亮的线性趋势。于是你心想"太好了，我要发布我们的最好模型 NL-12"。结果 **NL-12 并不是你的最好模型**——实际上是 NL-32 XL，一个困惑度差得多的模型。上游到下游的相关性可能是讲者见过的最糟糕的相关之一。

> **缩放定律一般是你想在困惑度那一侧应用的对象**：它们非常干净、非常规律、非常可预测；但从困惑度到下游的迁移，远没有乍看起来那么确定。这里要非常谨慎。

作为轶事：讲者的前学生去各家公司做后训练（post-training），他们总是抱怨"那些预训练的人把模型丢给你，说'困惑度很好，剩下的都是你们的问题了'"——但其实问题往往在预训练这一侧就开始了。你不想成为那种人，要真正思考迁移（transfer），而不只是盯着困惑度。

## 基于缩放定律的设计流程

也许出乎意料、也许不出：重点是，在开始大训练之前，你应该**对自己会看到什么有个大致的预期**——不只是"能不能训起来"。如果做缩放定律，你应该能相当精确地预测这次运行的效果数值：如果我选这个优化器而不是那个，收益是多少？你应该能预测出来。

于是缩放定律的设计流程就是：

1. **训练一批较小的模型**；
2. **建立缩放定律**——在 log-log 图上拟合这些线（比如"Adam 对 SGD 的缩放定律"）；
3. 如果拟合足够好，你就**有信心这条差距会持续**，基于缩放定律的预测选择最优超参数；
4. 把它**部署到大规模训练运行**上。

这是缩放定律流程的朴素版本，但对"实践中该怎么想"已经相当准确了——不然你还能怎么办？凭空直接部署一次运行？大概不会。

> **课堂问答一：缩放定律图上的每个点怎么考虑方差？跑几次？取平均还是取最小/最大？**
>
> **Tatsu**：据我所知，大多数情况下（如果不是全部）这些点都是**单次运行（singleton）**。原因是：当你关心困惑度时，困惑度非常干净——如果你重跑一遍，方差大概在第二位小数。因为训练数据非常同质、你有很多数据、评估集又很大，这些量把方差压得非常低。但如果你做学习率或临界 batch size 的缩放定律，你会看到一些真正惨不忍睹的方差。人们确实会做一些方差削减，但说实话并不常见——没有达到应有的普遍程度。

> **课堂问答二：有人直接在下游指标上做缩放定律吗？**
>
> **Tatsu**：有人直接对下游指标做缩放定律，但那会有和这个一样的问题。所以看待缩放定律的正确方式是**至少可靠地建立一件事**：比如我看到这条 transformer 的线，我知道（或者说强烈相信）它会继续——这是一条非常规律的趋势，可能会有一点点弯曲，但应该存在某种规律性；而不是把它当作某个注定精确的预言。缩放定律是**下界（lower bound）**，你总是可能做得更好——但如果我只是继续同样的配方放大，它就是我将会得到的。

> **课堂问答三：拟合的是训练损失还是验证损失？**
>
> **Tatsu**：按好的科学实践（比如 Kaplan 2021）拟合测试损失；但现实中，除了极少数模型（比如无限计算那个、还有数据重复那些），所有的模型都只做**单遍 SGD（one-pass SGD）**，所以泛化差距非常非常小，训练和验证损失非常接近。我见过一些预训练代码库甚至没有验证损失——因为如果你只过一遍数据，train 和 val 大概率非常接近。所以很多图把这两者混用，因为它们都处在单遍机制里。
