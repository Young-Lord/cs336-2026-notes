# 数据缩放定律：为什么是幂律

先讲**数据缩放定律（data scaling laws）**——这是一类非常简单的单变量关系。在这个世界里，我们固定整个训练流程（training procedure），并且在一般情况下，**模型要比数据集大**；然后我们规则地增大数据集大小 $n$，观察误差如何下降。

## 我们期望看到什么

如果超参数调得比较好，我们期望这条关系是**单调（monotone）**的：数据更多，模型在任务上应该做得更好，误差应当下降。而如果你做的是分类，或者甚至是下一个 token 预测，那么性能应该从"随机猜测"一直提升到某个类似"熵"的对象——也就是你无法再做得更好、由任务本身决定的**不可约误差（irreducible error）**，即噪声下限（noise floor）。所以整体上你会得到一个类似 **sigmoid** 的曲线：一开始快速下降，靠近噪声地板时趋平。这就是我们对系统的一般预期。

## 经验观察：log-log 图上的直线

接下来是一个经验观察——你自己完全可以、也应该去复现它（在作业三的某些部分你会做出和这差不多的图）：取一个比数据集大很多的模型，逐步增大数据集大小，横轴取对数、纵轴取对数测试损失，画出来的点会形成一条**非常清晰的线性趋势**。

![语言模型的数据缩放定律：log-log 图上的直线](/lectures/09/slide-15.png)

这张图来自 Kaplan 等人 2020 年的论文——OpenAI 的神经缩放定律论文（Neural Scaling Laws），讲次里会反复引用它，因为里面有大量漂亮的消融实验和漂亮的数据。log-log 图上的一条直线，意味着这是**无标度（scale-free）或者说幂律（power law）**的关系。这是什么意思？如果某个东西在 log-log 图上是线性的，说明：

$$\log \text{Error} = -\alpha \log n + \log k \quad\Longleftrightarrow\quad \text{Error} = k \cdot n^{-\alpha}$$

也就是说，误差在**多项式地衰减（polynomially decaying）**。同时这通常也意味着你**离渐近线还非常远**——一旦接近渐近线，曲线就会开始变平、不再保持直线，而不是继续一条直线。

## 玩具例子：为什么幂律会自然出现

暂时忘掉语言建模，这堂课接下来几页是一堂统计学课。考虑最简单的估计问题：**估计均值**。输入 $x_1, \dots, x_n \sim \mathcal{N}(\mu, \sigma^2)$，任务是用经验均值

$$\hat{\mu} = \frac{1}{n}\sum_{i=1}^{n} x_i$$

估计 $\mu$。误差是多少？由标准论证（$\hat{\mu}$ 是高斯变量、方差为 $\sigma^2/n$）：

$$\mathbb{E}\left[(\hat{\mu} - \mu)^2\right] = \frac{\sigma^2}{n}$$

对两边取对数：

$$\log \mathbb{E}\left[(\hat{\mu} - \mu)^2\right] = -\log n + 2\log\sigma$$

这就是一个"缩放定律"：对数误差是对数样本量的线性函数。更一般地，**任何形如 $1/n^{\alpha}$ 的多项式衰减（再加上一个常数）**，在对数坐标下（去掉常数项之后）都会给你一条缩放定律。

在参数化估计（parametric estimation，比如均值估计或回归）里，你当然预期多项式速率——你不会预期别的。而且如果你上过统计估计课程，你会知道：**几乎所有经典模型都预期是 $1/n$ 的缩放**（回归之类可能是 $d/n$ 之类）。如果这就是缩放定律的起源，那么我们画出来的线应该大致是斜率 $-1$ 的直线，即 $y = -x + C$。

## 指数之谜：神经网络的缩放慢得多

然而，当我们拟合神经缩放定律时，得到的指数完全不同。下面这些指数，左边两个来自 Hestness，右边一个来自 Kaplan：

| 任务 | 缩放指数（斜率） |
|------|------|
| 机器翻译（machine translation） | 约 $-0.1$ |
| 语音（speech） | 约 $-0.3$ |
| 语言建模（language modeling） | 约 $-0.1$ |

也就是说，这比估计均值或拟合线性回归**慢得多**——仍然是多项式速率，但指数只有 $-0.1$ 量级。这很有意思：我们得到漂亮的幂律速率，但指数并不好看。什么样的估计问题会给出这种速率？答案是：**当模型更"非参数（nonparametric）"的时候**。

## 插曲：非参数学习的缩放定律

承诺这是本讲最后一页统计学。这次不是估计均值，而是估计一个**任意光滑函数** $f$。假设输入 $x_1, \dots, x_n$ 均匀分布在二维单位盒子里，$y_i = f(x_i) + \mathcal{N}(0, 1)$，任务是估计 $f(x)$。

![非参数回归的维度灾难](/lectures/09/slide-19.png)

一个平凡的做法：把二维空间切成边长 $n^{-1/4}$ 的小盒子。这样沿着每个维度有 $n^{1/4}$ 个盒子，总共有

$$(n^{1/4})^2 = n^{1/2} = \sqrt{n}$$

个盒子，每个盒子拿到 $n / \sqrt{n} = \sqrt{n}$ 个样本。用盒子内样本估计局部均值，误差大约为

$$\text{Error} \approx \frac{1}{\sqrt{n}} = n^{-1/2}$$

（加上其它光滑性项）。推广到 $d$ 维，误差大约为

$$\text{Error} = n^{-1/d} \quad\Longrightarrow\quad y = -\frac{1}{d}\,x + C$$

即**缩放斜率由维度决定**。所以：灵活的"非参数"学习具有依赖维度的缩放定律——维度越高，速率越慢（维度灾难）。一个有用的心智模型是：前面那些神经网络的缩放速率，大致等价于一个**在约 10 维空间中工作的非参数回归器**（比如最近邻或其它估计器）从数据中学习的速率。仅仅看一眼缩放定律的斜率就能知道这件事，挺酷的。

有人把这个论证推得更远：**Bahri 等人（2021）** 等做缩放定律理论的人论证说，缩放定律源于 $1/n^{\alpha}$ 的多项式学习速率，而且斜率 $\alpha$ 与**数据的（内在）维度（intrinsic dimensionality）**密切相关——即神经网络确实表现得像一个非参数平滑器。这是一套很有意思的论证，你可以按自己愿意的程度去相信它；我本人并不完全确信，证据有些粗略（它依赖内在维度的估计器，而内在维度估计本身是 sketchy 的）。但无论如何，"这些指数在告诉你神经网络学得有多快"是件值得思考的事。

## 数据构成：斜率不变、截距会变

数据缩放定律本身并没有你想象的那么有用：它只告诉你"我的模型学得有多快"，这对预测（forecasting）有用，但对工程而言不够。做工程时你更关心别的数据问题：

- 我该用怎样的**数据混合（data mixture）**？怎么为我的模型挑选训练数据？
- 我该**重复数据**吗？还是把计算省下来做别的？或者只重复高质量的部分、不重复低质量的部分？

缩放定律能帮我们做其中一部分决策。一个关键观察是：如果数据缩放定律的本质是泛化界的经验版本，那么**数据集的构成通常影响缩放定律的截距（offset/intercept），而不是斜率**——斜率基本由模型类决定，而不是由分布决定。这意味着：**截距会变，而斜率保持不变**，并且截距可能非常有讲究。

讲一个玩具例子：对线性回归，有两种可以采样的数据源。如果你只拿其中一种数据，无论怎么训练误差都居高不下；你实际上想要**两者的混合**。把"截距作为混合比例的曲线"画出来，你会开始得到一些关于"更多样的数据非常有帮助"的深刻见解。

这在实际中意味着什么？你可以**在小规模上拟合数据混合的缩放定律**来做预训练数据优化：假设你有两个数据源（比如新闻 news 和维基百科 Wikipedia），想知道各用多少。做法是：在很小的模型、很小的数据上训练，拟合"不同混合比例如何影响性能"的函数；随着模型一点点放大，观察这些趋势如何变化，然后用与数据缩放定律完全相同的方式把它外推到完整训练规模，问"继续放大下去哪个混合是最优的"。这就是"数据混合定律"（data mixing laws）的朴素想法：在很小的计算量下拟合函数形式、找到最小值、再把它放大。

遗憾的是，如果你去问做过很多数据混合工作的人，现实会比这个理想世界**噪得多**。据我所知，在很多情况下实际发生的是：训练一堆小模型，从小模型上挑出最好的数据混合，然后直接放大——根本不需要缩放定律。DataComp 是这个方向上很好的大规模实证研究，他们发现：不拟合缩放定律、只在小规模上选最好的混合，效果就很好。这其实和"截距不同、斜率不变"的论证一致——**如果斜率不变，那么小规模下的最优混合也是大规模下的最优混合**。

## 数据重复：有限数据下会怎样

与数据相关的另一个重要问题（讲者也会在数据语境下提）是**重复（repetition）**。计算在增长，而数据总量不增长，所以很多人关心"重复数据越来越多遍"会发生什么。几年前有一项很好的研究（Scaling Data-Constrained Language Models）大致显示：**用标准训练配方，重复到约 4 个 epoch 以内，你完全不会受伤害**；但超过这个点之后，实际实现的缩放定律（图里那条实线）就比"如果有新鲜数据"投影出来的缩放定律（虚线）差很多。你也可以为此写下一个修改过的函数形式，一般都能预测这种行为。

![数据重复下的缩放定律](/lectures/09/slide-24.png)

我们还可以把这个想法推到极端：这是与我们联合指导的一位学生（Perseus）最近的工作——如果我们允许**无限多的计算**，即允许把数据一遍又一遍地重复任意多次，这个系统能榨出什么？结果是不能只是不断重复数据、不断把模型做大——这些都有递减收益。于是你会转向其它手段，比如**集成（ensembling）多个模型**，试图从数据里榨出更多。但讲者真正想指出的是：标准的数据缩放定律是那条红色的线——非常漂亮、可预测的性能提升；而当你做各种干预（正则化、加集成）时，性能确实提升，但**斜率看起来惊人地相似**。这是一个在你开始拟合自己的缩放定律后会反复遇到的教训：

> **你的干预常常只改变缩放定律的截距，而几乎不改变斜率。**

## 数据过滤是尺度依赖的

最后一点，讲者喜欢用它来说明"数据的很多现象其实是尺度依赖（scale-dependent）的"，一个例子是**数据过滤（data filtering）**。如果你或我明天要为训练的模型过滤数据，我们大概会**非常激进地过滤**——只保留最高质量的部分，因为我们没有很多计算量，反正也训不完整个互联网，不如过滤到最高质量。但如果你有海量计算量，你就会想训练越来越多、越来越杂的内容——因为你不想在高质量数据上重复。于是随着计算量增长，你的过滤器会越来越宽松，可能开始训练越来越低质量的内容。很多我们通常静态思考的东西（数据过滤、数据质量）实际上是**动态的**：随着规模增大，你必须思考"剩下的数据从哪来"，过滤器不能固定不变，最优过滤器也确实不是规模的固定函数。

## 两个课堂问答

> **课堂问答一：为什么无限计算的图看起来是线性的？**
>
> （同学：无限计算预训练那张图，横轴纵轴看起来都是线性尺度的，而前面我们用的是 log-log 尺度，为什么？）
>
> **Tatsu**：这是个不太好的坐标轴（讲者和同事刚刚还讨论过这种"坏坐标轴"）。这张图其实还是在对数尺度上画的，只是看起来像线性。而且这里的 Y 轴范围非常小，线性尺度和对数尺度看起来基本一样。如果你看拟合的函数形式，它们仍然是多项式——我们拟合的就是同样的函数形式。这引出一个更一般的点：**如果你只看计算量的一个很窄的区间，很难区分某个东西是多项式缩放还是指数缩放**——因为泰勒近似存在，任何东西放大看局部都是线性的。所以对"这到底是多项式还是别的函数形式"，你要始终保持一点怀疑。

> **课堂问答二：数据缩放定律为什么总是强调"模型比数据大"？**
>
> （同学：你反复说模型要比数据集大，这具体是什么意思？）
>
> **Tatsu**：当你做数据缩放定律时，你会同时把模型放大。如果数据量太大而模型太小，损失会被模型容量卡住，落在渐近线上——那时候不管加多少数据都无济于事。所以当我们思考缩放定律时，通常想讨论的是**幂律机制（power law regime）**，也就是较简单的那个情形；要么你就在幂律机制下做，要么就显式地把渐近线拟合出来再修正它。当我说"模型比数据大"时，只要大得足以落在幂律机制里就行，通常大约是数据的 10 倍就足够了。

## 小结

到这里，数据缩放定律讲完了——这是整个讲次里最容易理解的部分。即使作为统计学/机器学习出身的人，这部分也都非常简单直白：你增加数据，性能就以一种可预测的方式变好。它无争议。真正值得感叹的只是：对如此大的模型，数据带来的收益竟然仍是多项式形式的——这有点酷，但也并不疯狂。数据缩放定律的要点：

- **log 数据量与 log 误差之间有着惊人的线性关系**，跨领域、跨模型都成立；
- **理论理解**类似于泛化界：均值估计的例子展示了为什么多项式是自然的；
- **应用**：数据收集与整理（curation）。
