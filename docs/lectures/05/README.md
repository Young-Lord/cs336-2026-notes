# Lecture 5: GPUs, TPUs

**讲师**: Tatsu Hashimoto · **主题**:GPU 与 TPU(GPUs, TPUs)

## 本讲内容

这一讲是课程**系统部分**（systems）的开篇，目标是把 GPU 这层"魔法"拆开。前半讲是 GPU 的硬件模型与编程模型：从 **Dennard scaling 的枯竭**与**并行扩展**讲起，对比 **CPU（延迟）与 GPU**（吞吐）的哲学差异，然后深入解剖 GPU——**SM/SP 计算单元、内存层级（寄存器、L1/shared、L2、HBM）、执行模型（线程/块/warp）、内存模型**，再以 **TPU** 作为"GPU 的另一个进化分支"做对照（趋同演化、MXU 与 tensor core、脉动阵列），最后讲**矩阵乘法硬件史**（从 shader 黑客到 Tensor Core）与**算力 vs 内存扩展（内存墙）**。第二部分讲**六个加速技巧**:roofline 模型、控制发散、低精度计算（FP16/BF16、FP8、MXFP8、MXFP4）、算子融合、重计算、合并访存、tiling，并用它们**解密矩阵乘法的"神秘性能曲线"**（整除性/对齐、波次量化 wave quantization）。第三部分把一切串起来，推导**在线 softmax 的望远镜求和**并完整拆解 **FlashAttention 的前向与反向**。

## 本讲要点

- **系统部分是"讲得通"的部分**：每一步都有合乎逻辑的步骤通向结果，但第一次接触 GPU 时会觉得像魔法——本讲的目标就是拆掉这层魔法，到结尾时你能理解那张"矩阵乘法的神秘曲线"为什么长那样；
- **旧路已尽，Dennard scaling 枯竭**：晶体管变小不必然变快（时钟频率有物理上限），所以只能走**并行扩展**——水平扩展执行单元；GPU 的浮点算力在 P100/V100 之后呈超指数增长，**没有 GPU 扩展就没有 LLM 扩展**;
- **CPU 优化延迟，GPU 优化吞吐**:CPU 用大控制单元 + 少量 ALU 追求"指令到结果"的低延迟；GPU 用海量轻量核心追求聚合吞吐——单个任务很慢，但总量极高；
- **GPU 的基本单元是 SM（流式多处理器)**:A100 有 128 个 SM，每个 SM 内部有 SP 并行执行线程；内存层级的关键数字——**L1/shared 约 20~30 周期，全局内存比 L1 慢约 10 倍**;SRAM 贵（上百倍）且必须常通电，所以要用层级而不是一整块 SRAM;
- **执行模型三要素**：线程（所有线程执行同一条指令、输入不同，即 **SIMT**）、块（保证运行在同一个 SM 上、共享 shared memory）、warp(**32 个连续编号的线程**为一组执行，是调度单元);
- **TPU 是 GPU 的趋同演化**：轻量控制 + 大矩阵乘单元 + 快/慢内存层级；GPU 的 tensor core 对应 TPU 的 MXU（都是**脉动阵列**)，但命名陷阱：**TPU 管处理器叫 tensor core,GPU 管矩阵乘单元叫 tensor core**;GPU 528 个小型 matmul 单元 vs TPU 8 个大型单元，TPU 拒绝小于 64 维的输入；
- **matmul 是机器学习里的"特权操作"**:V100 引入 Tensor Core 后，矩阵乘比 GPU 上任何其他浮点运算**快 10 倍以上**——这是任何可扩展架构里都有 matmul 的原因；
- **算力扩展得比内存快（内存墙）**:FLOPs 增长最快，内存带宽与互联很慢，差距越拉越大——所以本讲的优化几乎全是**内存优化**;
- **roofline 模型**：对角线是内存受限区，平坦区是计算受限区；要高效就要**提高运算强度**，站到平坦区去；
- **六个加速技巧**：控制发散（避免 warp 内分支开销）、**低精度计算**（比特少→搬运少；FP8 有 E4M3/E5M2,MXFP8 用"每 32 个元素一个 E8M0 缩放因子",**转置需要重新量化、实际保存两份副本**）、**算子融合**（把 5 个 kernel 合成 1 个，只付两次带宽）、**重计算**（丢弃激活反向重算，3 个 sigmoid 例子从 8 次内存访问降到 5/8）、**合并访存**（DRAM 突发模式，行主序沿行移动的线程无法合并）、**tiling**（把 tile 载入 shared memory，全局内存访问减少 $T$ 倍);
- **矩阵乘法的神秘曲线由两个现象构成**:①**整除性/对齐**——维度能被 16/32 整除才有好的合并读取；②**波次量化**——1792² 只要 98 个 tile（正好放进 A100 的 108 个 SM),1793² 变成 120 个 tile，多出的 12 个 tile 让大部分 SM 空等一整轮；
- **FlashAttention 只做两件事：tiling + 重计算**。难点在全局 softmax，解法是**在线 softmax（望远镜求和)**：维护 running max $m$ 与 running sum $l$，遇到更大的数就换掉并缩放纠正，从而可以逐 tile 推进，注意力矩阵从不物化到 HBM；反向传播则逐 tile 重算——六个技巧一次用齐。
