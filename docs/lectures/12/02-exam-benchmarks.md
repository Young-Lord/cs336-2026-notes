# 考试类基准：MMLU 到 Humanity's Last Exam

## 为什么考试适合测模型

考试（exam）是检验语言模型的一种很有用的方式——对人也是如此。它的好处在于：你可以**控制题目涉及的科目和难度**；题目被设计成有**无歧义的标准答案**；而且**很容易判分**。这几个特性让它成为评估语言模型最经典的形态。

从 MMLU 到 HLE，这些考试类基准的演进本身就是一个很好的故事：**模型变强、基准饱和，于是人们造出更难的基准**。下面按时间顺序过一遍。

## MMLU：名为"理解"实为"知识"

**Massive Multitask Language Understanding**（MMLU）是 2021 年提出的大规模多任务语言理解基准：

- **57 个科目**（数学、美国历史、法律、道德……），全部是多选题；
- 题目"由研究生和本科生从网上自由可得的资料中收集"；
- 在 GPT-3 上用 few-shot（少样本）提示方式评估。

![MMLU 的示例题](/lectures/12/mmlu.png)

尽管名字叫"语言理解"，讲者特别强调：**MMLU 实际上测的是知识，而不是语言理解**。它对模型的知识储备非常敏感，却不怎么考察"理解"层面的能力。

## MMLU-Pro：去噪、加选项、用上思维链

模型在 MMLU 上很快饱和了，于是有了 **MMLU-Pro**：

- **去掉了 MMLU 里有噪声的、琐碎的题目**；
- 把选项从 4 个**扩到 10 个**；
- 用**链式思考**（chain of thought）来评估——给模型更多发挥的机会；
- 结果是模型的准确率**下降了 16% 到 33%**——说明 MMLU-Pro 不再像 MMLU 那样饱和。

![MMLU-Pro 的示例题](/lectures/12/mmlu-pro.png)

讲者的观察是：**在饱和的基准上大家分数都很高，区分度已经没有了**；MMLU-Pro 通过增加难度重新拉开了差距。

## GPQA：博士级、"Google 也查不到"的问答

**Graduate-Level Google-Proof Q&A**（GPQA）在"难"字上更进一步。它的题目由 **61 位来自 Upwork 的博士级承包者**编写——这些人本身就是各领域的专家。

![GPQA 的示例题](/lectures/12/gpqa.png)

它还有一套严格的**审查流程**：其中有一个子集叫 **diamond set（钻石集）**，只有满足"两位专家答案一致、且最多一位非专家能答对"的题目才入选。也就是说，这些题是非专家即使用 Google 也几乎查不到答案的。

各组数据非常说明问题：

- **博士级专家**只能拿到 **65%**（这大都是四选一的多选题，高于随机但绝不是好成绩）；
- **非专家**即使给 30 分钟、允许用 Google，也只有 **34%**——略高于随机；
- 当时的 **GPT-4 只有 39%**。

而到了 2026 年，GPQA 上的分数已经涨到 **94%** 左右。讲者借此感慨：**这些基准的"保质期"都不太长**。不过他也补充说：即使某些基准在大模型上饱和了，它们对开发较小模型、或者拟合缩放定律仍然有用。

> **课堂问答：怎么知道这些题不在训练集里？**
>
> 有学生问：你怎么知道这些基准题没有被训练过？讲者的回答很坦率：**我们不知道**——因为我们不知道训练集里到底有什么（这个话题后面讲"污染"时还会专门展开）。他建议大家**对这些数字始终抱一点怀疑**。他还补充了一个更微妙的点：训练污染往往是**间接的**——模型不太可能直接训练过这个基准本身，但这些题目可能派生自其他来源，而那些来源可能出现在训练数据里。所以污染通常比"不小心训练到基准本身"要微妙得多。另一位学生追问了同样的问题，讲者笑着说："这个问题很重要，保持怀疑总是好的。"

## Humanity's Last Exam：给模型出"毕业考"

最后的考试类基准有一个不祥的名字——**Humanity's Last Exam（人类最后的考试）**，来自 2025 年。它的思路是："好吧，这些模型太厉害了，那我们就倾尽全力造一个真正难的东西。"

它的规模与设计：

- **2500 道题**，**多模态**、横跨许多科目，形式是**多选题 + 少量简答题**；
- **众包**生产题目，并设置了 **50 万美元奖金池 + 联合作者署名**作为激励（喜欢钱的拿钱，喜欢名的署名）；
- 题目经过**多轮评审、并由前沿模型过滤**——有一套完整的流程。

![HLE 的示例题](/lectures/12/hle-examples.png)

![HLE 的题目构建与过滤流程](/lectures/12/hle-pipeline.png)

针对训练污染问题，HLE 还做了另一件事：**持有（held out）了一个不公开的私有测试集**，确保它不会进入训练数据；至于发送给模型 API 的提示词会不会被厂商拿去训练，那就只能"希望"了。

![HLE 的结果：所有模型分数都很低](/lectures/12/hle-results.png)

讲者调侃说，**每一篇数据集论文看起来都是这个套路**："你看以前的基准，模型做得太好了；再看我的数据集，所有模型都做得特别差。"HLE 也不例外，而且低得离谱——刚发布时模型的分数甚至是个位数，2026 年再看，即便最强的模型（Mythos 之类）也还只有很低的分数，确实还有很大空间。

> **课堂问答：准确率是怎么算的？**
>
> 学生问：算准确率时，模型的输出是怎么跟标准答案比较的？讲者解释：对多选题，就是看模型生成的字母（A/B/C/D）是不是正确答案——`response = "C"`，然后检查它和答案是否相同。学生接着追问：那模型是怎么生成这个字母的？讲者说这其实就引出另一个问题：模型可以真的采样生成一个字母，更常见的做法是先产生链式思考、再给出答案和解释，然后从输出中**提取**答案。这个"答案提取"的方式确实会影响评估结果——**语言模型评估对答案提取方式可能非常敏感**——但这一讲不打算展开这一点。

## 基准分数的统计误差：为什么要报告置信区间

讲者在这里插了一段重要的方法论提醒：**基准分数本质上是一个统计估计，必须配套报告误差**。一次评估就像一次调查：你在 $N$ 道独立题目上测出准确率 $\hat{p}$。如果把每题看成独立同分布的伯努利变量，那么答对的题数服从二项分布 $\text{Binomial}(N, p)$，准确率估计值的**标准误**（standard error）为

$$\text{SE}(\hat{p}) = \sqrt{\frac{\hat{p}(1 - \hat{p})}{N}}$$

于是约 95% 的置信区间是 $\hat{p} \pm 1.96 \cdot \text{SE}(\hat{p})$。用代码算两个具体例子：

```python
import math

def standard_error(accuracy: float, n: int) -> float:
    """二项比例估计的标准误。"""
    return math.sqrt(accuracy * (1 - accuracy) / n)

# HLE：2500 题，准确率 10%
print(standard_error(0.10, 2500))    # ≈ 0.006，即约 ±0.6%

# MMLU-Pro：约 12000 题，准确率 70%
print(standard_error(0.70, 12000))   # ≈ 0.004

# 一个小型聊天基准：805 条指令，胜率 50%
print(standard_error(0.50, 805))     # ≈ 0.018，即约 ±1.8%
```

这个公式有几个直观的推论。**题目越多，误差越小**（$1/\sqrt{N}$ 衰减）；**越接近 0.5，误差越大**（方差最大处）；而两个模型之间的差距要显著，至少要差出约两倍标准误。这正是一节后面会提到的"报告规范（reporting norms）"的动机——就像科学界报告任何估计都要附带置信区间一样，**模型厂商报 GPQA 分数时，应该同时说明这个分数有多可靠**。

## 小结

考试类基准给我们展示了一条清晰的脉络：**随着模型变强、现有基准被迅速饱和，基准的难度一路走高**（MMLU → MMLU-Pro → GPQA → HLE）。有个值得注意的现象是**多选题形式至今仍被保留**——因为多选题的难度可以任意高，所以"多选题太简单"并不是真正的批评；真正的问题是它**限制了可问问题的类型**。

考试类基准的根本问题在于：**它不捕捉真实的使用场景**。没有人会向语言模型问 HLE 里的题——除了在评估 HLE 的时候。大多数时候，人们问的是开放式的、未必有标准答案、甚至不一定良构的问题。下一节就来处理这类"开放回答"的评估难题。
